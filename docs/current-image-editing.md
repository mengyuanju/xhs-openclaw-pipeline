# 当前图片修改工作台

基线：`auto-clow-poker` 的 `4c8d63b`。实现已合并到集成分支 `codex/integrate-workflow-upgrades`。
只使用中央 PostgreSQL；没有调用旧 SQLite image-edit store/worker，没有启用发布或生产定时任务。

## 页面与操作

管理员打开任务图片审核/归档对话框，选中当前页，点击“修改图片”。仅允许已批准文案、无未完成强制文案质检、且处于 MANUAL_ARCHIVE/REVIEWED 的任务。

- 添加文字：只处理“人工生成标识”。作业员可把默认文字改成 1～12 个文字、数字、下划线或短横线，并选择只应用到当前页，或批量应用到当前整套图片。原有“图片模型融合”仍为默认方式：每页只调用一次图片编辑模型，只把完整原图作为唯一输入，不使用蒙版，也不进行局部像素贴回。新增的“程序叠加”复用自动交付链路的描边胶囊 SVG 规范，以 Sharp 确定性合成并逐像素校验标识区域外没有变化，不调用图片编辑或视觉模型。模型方式共享现代无衬线白字、约 32px 视觉字号、深炭色不透明圆角底框和内边距的统一样式指令；文字错误、重复或不可读时直接失败，不再自动进行第二次修改。
- 实体替换：一次可建立 1～4 个“产品替换项”，每项绑定自己的真实参考图和使用方式，并可勾选一张或多张源图。作业员必须切换到每一张已选图片，分别填写可辨识的目标说明并框住一个完整目标。同一张图里的多个产品会合并为一个原子编辑请求，一次生成、一张联合蒙版和一次逐项结果验收，避免后一个结果覆盖前一个结果；跨图片则按页建立同一批次，每页仍在一个请求中完成该页全部替换，预览全部就绪后可整批采用。“完整产品”模式要求参考图只有一个清楚、完整、遮挡很少的产品；“外观参考”模式允许手部、手腕、裁切或次要产品，但主产品必须清楚且唯一可识别。外观参考只迁移可确认的颜色、材质、表壳、屏幕、按钮、标志和关键细节，忽略手部、背景和次要产品，未展示部分沿用原目标结构、姿态和透视补全。每个目标会在调用图片生成模型前独立检查唯一性、完整性、保护范围和对应参考图；任一项失败则整张图不调用图片生成模型。定位通过后，系统把原图、按替换项绑定的参考图和联合目标蒙版交给图片编辑模型，仅允许改动框选区域；最终再用原图像素覆盖蒙版外区域。生成后逐项核对参考身份、目标位置、数量、部件拓扑及无关内容。
- 局部修改：作业员在说明中写清“改哪里”和“改什么”。通过原有源图验收后，直接把完整原图、作业员说明和冻结的管理员图片编辑规则交给图片编辑模型，单次请求只生成一次。不再调用局部视觉规划器，不检查唯一候选或规划选区尺寸，不自动生成建议、角色引导图或蒙版，也不做局部像素贴回。生成后以原图和结果图核对任务完成、目标数量、落点/原位置修补、文字及未点名内容，再执行文字/视觉验收和 PNG 尺寸完整性检查。历史机器规划和建议坐标不再参与执行；只有旧客户端明确提供的人工遮罩仍按原遮罩逻辑执行。
- 处理记录展示状态、失败原因、审计、校验结果、重试、拒绝、取消和采用。支持修改前后滑动对比、缩放及选择某一结果比较。
- 同一页可保留多个已就绪的预览版本；采用其中一个后，仍可明确选择并采用另一个已有预览，系统会把它作为新的当前版本并记录被替换的资产。新建或重试修改仍必须以最新当前图为源，避免在过期图片上继续生成。
- 恢复历史图集也先排队校验、生成恢复预览，仍需明确采用；只能恢复当前批准文案对应的历史版本。

参考图自身不能进入交付图集。历史 `COMPOSITE` 和 `AI_FULL` 记录仍可查看、重试或恢复，但新界面不再创建这两类请求。

模型生成标识、真实产品替换和局部修改都使用管理员“提示词 → 图片编辑（IMAGE_EDIT_SYSTEM）”中当前已发布的规则。创建请求时会冻结提示词版本、内容和哈希；人工重试继续使用原版本，模型生成标识不再自动修复。作业员填写的文字、局部说明和上传图片作为不可信任务数据附加，不能覆盖管理员规则。未发布图片编辑提示词时不允许创建这些模型改图请求。程序生成标识不读取或冻结图片编辑提示词。

## 状态与运行

`DRAFT → QUEUED → RUNNING → PREVIEW_READY → ACCEPTED / REJECTED`

可取消草稿、排队、执行、预览和失败请求；普通失败可明确重试，最多三次执行。历史局部修改建议仍可在 FAILED 记录中显示为“待确认建议”；采用时只保留选中说明，清除机器规划及蒙版，重新排队进入直接编辑，不重新定位或校验规划区域。每次领取带独立租约 token；领取使用 `FOR UPDATE SKIP LOCKED`，执行期间续租。过期任务进入 FAILED，不自动重复收费。取消/过期后，旧执行无法回传生效；AI 调用在下一次续租检查时收到中止信号。

中心服务不再运行图片编辑模型，也不再提供中心机单次改图入口。手动改图与普通生图统一进入图片执行机的 `IMAGE` 容量池；只有启用图片能力的执行机才会领取。中心在同一领取事务中按任务优先级、等待补偿和负责人轮转统一选择普通生图或改图，`PAUSE` 任务不会被领取。改图占用现有 `EXECUTOR_IMAGE_CONCURRENCY`、共享 Codex 总许可和图片许可，不会额外开启一套并发。

执行机通过租约绑定的远程 HTTP 协议读取冻结上下文、源图和参考图，回传校验记录及最终 PNG；中心复核执行身份、源版本、PNG 尺寸/格式和校验哈希后落库。领取回执、校验提交和结果提交均支持不重放模型的网络重试。中心和图片执行机通过 `imageEditExecutorVersion=10` 协商最新编辑能力：带 `replacements` 的批量或多产品替换要求版本 10，局部修改要求版本 9，程序标识要求版本 8，历史单产品模型修改仍兼容版本 7。自动验收未通过的生成结果会作为隔离的失败预览上传并保留。局部编辑验收会返回固定失败码和定向修复说明，不再要求修复区域坐标；当文字及无关内容仍完好且修复次数未耗尽时，作业员重新确认费用后可选择以失败预览为编辑目标、以原图为只读外观参照继续补救。失败预览不会自动进入正式图集，作业员仍可查看、对比、从原图重试，也可在明确确认并填写原因后人工采用；系统保留完整审计记录。确定性合成与历史恢复仍兼容版本 3 执行机。

运行机只需要现有 Node/Sharp/Codex 环境，不安装或下载本地 OCR。程序生成标识复用 `aiDisclosureBadgeSvg` 和 `createAiDisclosureStyle`，记录渲染器、样式版本、位置、颜色及像素完整性校验；模型生成标识则在完整原图上单次绘制，不传蒙版、不做程序化像素拼接，并复用 `createImageAlignmentValidator` 核对必需文字和唯一出现次数。模型方式出现文字缺失、错字、重复、额外文字、OCR 置信度不足或尺寸错误时直接失败，不再触发自动二次修改。真实产品替换、局部修改和恢复继续按各自视觉验收规则执行。

仅当前页实际继承的人工生成标识作为必需文字重新校验；新增文字也加入后续编辑的文字白名单。输出目标页为 1086×1448 PNG，其余页面复用原资产及原格式。源图不可覆盖。每次编辑新建完整 image run，目标页新资产，其他页通过成员关系引用原资产。结果包括父资产、源运行、文案版本、编辑操作、参考哈希、遮罩和校验记录。

打开编辑、保存草稿、排队执行和生成预览均保留当前图集、任务状态、图片审核信息和旧 READY 交付；失败、取消或拒绝预览也不改变这些信息。只有明确采用新图（包括单张、整套标识、集中处理或历史恢复）时，才在同一事务中校验源版本和输出文件哈希、撤回旧 READY 交付并进入预览撤销队列、切换当前图集、清空图片审核及质检放行信息，任务回到 MANUAL_ARCHIVE（待图片初审）。采用后必须由负责人重新初审，再按图片抽检策略进入质检等待或交付池；尚有当前源图的待处理编辑时仍禁止重新提交初审或新建交付记录。全部作业列表在采用后立即刷新状态。此规则适用于后续操作，不自动恢复历史上已撤回的交付记录。

## 直接局部修改的完整链路（2026-09-20）

1. 选择页面、填写目标和修改说明、确认模型费用；可先保存草稿。
2. 中心校验账号权限、任务/文案状态、源图版本和哈希，冻结提示词版本并排队。
3. 支持版本 9 的图片执行机从共用 IMAGE 容量池领取，读取原图并维持租约。
4. 检查原图尺寸，并沿用源图文字/视觉验收（最多两次检查；失败不调用图片编辑）。
5. 原图＋说明直接调用一次图片编辑模型。没有局部视觉规划、自动选区或蒙版贴回。
6. 输出转为 1086×1448 PNG；原图与结果对比做修改语义验收，再核对已批准文字、格式和尺寸。
7. 成功生成 PREVIEW_READY；生成后验收失败则保存隔离的失败预览、原因和校验记录，不自动再生成。
8. 用户对比后采用、拒绝或重试。文字与未点名内容完好时，可明确确认费用后基于失败图和原图参照按修复说明再次编辑，无需规划坐标。
9. 只有明确采用后才替换目标页并生成新图集版本，保留其他页，撤回旧交付并回到人工图片初审，再走原抽检/交付流程。

中心、网页和图片执行机需一起更新并重启才能启用本次变更；无需数据库迁移。历史主编辑规则仍保留冻结版本；新直接编辑合同使用 INTERNAL_EDIT_DIRECT_TEXT 与 INTERNAL_EDIT_DIRECT_REVIEW，避免历史规划补充规则重新生效。实体替换的参考图/目标检查、程序标识和历史人工蒙版不属于本次移除范围。

## 数据迁移

基础数据迁移为 `server/migrations/0052_image_editing.sql`；执行机接管迁移为 `server/migrations/0056_executor_image_edits.sql`：

- `image_edit_requests`：版本快照、操作配置、状态、次数、租约、操作者、失败/校验信息，`requeue_reason=IMAGE_MANUAL_EDIT`。
- `image_edit_reference_assets`：请求与参考资产绑定、排序、用途、sha256。
- `image_edit_results`：目标资产、完整运行、遮罩、校验、采用状态。
- `image_edit_events`：创建、上传、执行、采用、拒绝、恢复、重试、取消及过期审计；动作 requestId 在任务内唯一。
- `assets` 新增 `parent_asset_id`、`asset_role`、`edit_metadata`；保留原有图片生产链字段。
- `image_run_asset_members` 与 `image_run_asset_view`：支持跨运行复用资产。任务详情、图片问题资产校验、交付归档检查和格式重处理读取此视图。
- `image_runs.execution_id` 允许 NULL：人工编辑不伪造普通模型任务执行。
- `image_edit_requests.execution_id` 绑定真实执行机的合成 `IMAGE` 执行；用于共享容量、模型调用审计、心跳和节点追踪。编辑生成的 `image_runs.execution_id` 也指向该执行。

迁移只在隔离测试数据库应用过，未操作生产数据库。使用现有数据库升级流程应用迁移。

## HTTP 接口

### 初审前集中处理

图片初审入口遇到待处理修改时打开“集中处理图片修改”弹窗，保持初审按钮可点击。弹窗汇总整个任务的待处理修改，不受历史记录最近 100 条的限制。任务详情中的提示条也提供直接入口。

- 按页展示修改说明、原图与结果，可放大对比；支持一键采用全部可用结果、一键拒绝全部结果，以及逐项选择后统一应用。拒绝只结束修改请求，保留当前正式图片。
- 同一页存在多个结果时，需明确选择一个采用；同页其他结果自动标记为拒绝，应用前可查看选择。源图或文案已经变化、自动校验不通过或模拟结果均不能批量采用。
- 草稿、排队和执行中的修改单独显示，可逐项或勾选统一取消。默认不取消，也不会重新调用模型。失败结果仍在原图片编辑历史中处理，不混入批量采用。
- 从初审按钮进入时，全部处理完成后刷新图集并继续初审确认；还有未完成修改则留在弹窗。从提示条进入仅处理修改。刷新列表同时更新任务版本，方便处理并发冲突。
- `POST /v1/tasks/:taskId/image-edits/resolve-pending` 接收 `requestId`、`imageRunId` 与 `decisions: [{ id, version, action }]`，每次最多 500 项，action 为 `accept`、`reject` 或 `cancel`。沿用负责人/管理员权限与资产完整性校验，在一个数据库事务中合并不同页的结果；任一冲突全部回滚。相同请求可安全重试，逐项原因和批量选择均记录审计。
- `GET /v1/tasks/:taskId/image-edits?pending=true` 返回全部待处理修改；原历史接口保留 100 条限制。中心通过 `pendingImageEditResolutionVersion=1` 声明批量处理能力，无新增数据库迁移。

自动化验证覆盖批量合并、混合采用/拒绝/取消、同页冲突、过期版本、权限、文件损坏后整批回滚、幂等重试、取消后的迟到结果，以及桌面/手机弹窗和初审衔接。使用隔离数据库和假模型，不消耗模型额度。

全部沿用 Koa 的响应封装和现有账户身份验证，允许任务负责人 USER 和 ADMIN 使用；写入事务再次验证账号权限、任务归属、状态和凭据版本。

执行机另使用 `/v1/executions/claim-image[-batch]` 统一领取，并通过 `/v1/executions/:executionId/image-edit/*` 完成上下文读取、租约心跳、受限资产下载、校验暂存、PNG 回传和失败上报。这些机器接口不接受普通用户会话代替执行机调用。

创建/恢复必须提供 `requestId, sourceImageRunId, sourceAssetId, copyRevisionId, sha256, targetPage`。创建还提供 operation 及对应 overlay/references/instruction；整套文字请求额外共享一个 `batchId`，便于恢复批次进度和批量采用；新建局部修改不提交 mask，历史客户端仍可提交合法 mask。直接排队的添加文字会调用图片编辑模型和视觉文字校验，必须提供 `confirmation=LIVE_IMAGE_COST_ACCEPTED`；批量模式按图片张数分别产生模型调用。仅保存草稿不会调用模型，可以稍后在“提交草稿”时确认费用。新界面的文字 overlay 固定为 `AI_DISCLOSURE / AI_GENERATED / bottom-right`，服务端覆盖客户端传入的字号、颜色、底色、透明度和边距，只接受合规标识文字。真实产品替换只绑定一张参考图，并必须提交 `target.description` 与 1086×1448 源图坐标系内、至少 24×24 的 `target.region`；`referenceMode` 可为默认的 `STRICT` 或显式选择的 `APPEARANCE`。动作接口必须提供 `requestId, version, reason`；草稿首次提交或未保留旧确认的失败任务重试还需费用确认。源版本变化返回冲突，无法覆盖新图集。重复 requestId 不重复采用或审计，复用到不同输入会拒绝。

上传限制：PNG/JPEG/WebP 文件签名与解码格式一致，拒绝 SVG、动画、截断及伪造 MIME；每个文件原始大小 ≤5 MiB、像素 ≤16M、规范化后 ≤10 MiB。每请求 ≤4 图、合计 ≤20 MiB/32M 像素；每任务累计 ≤20 参考资产/50 MiB。去除 EXIF 后统一保存 PNG，同时保存原始与规范化 sha256、原始类型、尺寸、上传人、用途、来源。路径仅由服务器生成，不使用客户端文件名。
