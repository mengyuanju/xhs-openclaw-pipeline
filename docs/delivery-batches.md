# 交付批次使用说明

共享交付上线后的日常操作请参阅 [共享交付与汇总保存](shared-delivery.md)。新的主页面默认显示全部状态，支持逐条确认、日期筛选和管理员汇总保存；下文保留原始批次工具的使用说明。

交付池现在把“内容已经 READY”和“内容已经装入交付包”分开记录，解决同一词包分多次打包时无法判断此前交付数量的问题。

## 页面上的数量

- **READY 总数**：当前所有可交付内容。
- **待交付**：当前版本尚未进入任何交付批次，默认列表只显示这些内容。
- **已打包**：当前版本已经进入一个交付批次，不会再次进入新的批次。
- **版本更新待重交**：任务曾交付过，但文案或图片已形成新的审核通过版本；新版本需要重新打包。

例如一个词包有 100 条内容，上午创建了一批 20 条后，页面会显示待交付 80、已打包 20。再次点击“新建交付批次”时，默认只打包剩余的 80 条。

## 推荐操作

1. 在“待交付”视图中确认范围；可以按词包筛选，也可以勾选若干任务。
2. 点击“新建交付批次”。系统生成类似 `JF-12AB34CD` 的批次号，并冻结该批次所含的任务、文案版本和图片版本。
3. 下载完成后，可在“交付历史”中查看每批数量、创建人、创建时间和下载次数。
4. 需要再次发送同一批内容时，使用历史中的“重新下载”，不要创建重复批次。
5. 如果内容返工并产生新版本，它会进入“版本更新待重交”；重新打包只会收录这个新版本，旧批次仍保留冻结快照、原图引用和明细。

批次明细一经创建不会修改。Excel 导出仍是统计与核对工具，不会改变交付状态，也不会占用某个版本的交付批次名额。

## 文件保存

系统只长期保存 `.delivery-snapshots/<批次UUID>.json` 中的冻结文本、文件顺序、图片路径及校验值，图片使用现有本地原图。ZIP 按需生成到独立临时目录，使用后、断连或取消时清理；历史“重新下载”会按同一快照再次生成。文件内容保持冻结版本，不保证重新生成的 ZIP 容器字节与旧包完全相同。快照或原图缺失、图片大小或哈希不匹配时拒绝下载，不替换为当前版本。被快照引用的原图受清理和永久删除保护。

## 上线注意事项

首次启用批次需要 `0054_delivery_batches.sql`，快照存储需要 `0120_delivery_snapshot_assets.sql`。上线前同时备份 PostgreSQL 与 `CONTROL_PLANE_STORAGE_ROOT`。旧批次必须先通过 `scripts/migrate-delivery-snapshots.mjs` 校验旧 ZIP、匹配本地原图并建立快照，具体步骤见[共享交付升级说明](shared-delivery.md#升级与验证)。默认检查；`--apply` 写入快照，额外指定 `--remove-archives` 才删除已校验的旧包。未迁移成功前保留旧包和备份。

数据库备份仍不包含图片及快照 JSON。日常备份与恢复必须同时包含数据库、`.delivery-snapshots` 和全部被引用原图；临时 ZIP 可以重新生成，无需长期备份。中心和 Web 同步升级，健康检查中的 `finalDeliveryVersion` 必须为 `3`。
