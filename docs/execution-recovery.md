# 执行卡住后的回收

此前执行机节点心跳只能证明进程在线，不能证明某个任务仍在运行。Codex 超时后若迟迟没有进程 `close` 事件，任务会一直占用执行槽；中心也没有回收这类执行的机制。

## 行为

- 中心启动时检查一次，此后每 15 秒检查过期执行，每批最多 100 条。任务超过 30 分钟没有业务阶段进度，或者已建立的任务心跳超过 2 分钟未更新，将转为 `COPY_FAILED` / `IMAGE_FAILED` 并释放中心并发槽。
- 执行机在首次模型调用前确认任务心跳，之后随运行时心跳续期。任务心跳不会刷新阶段进度。中心撤销执行或本机超过 2 分钟未确认心跳时，执行机会取消底层请求，阻止后续模型调用和结果写入。
- Codex 文案与图片进程的终止等待有 5 秒清理上限；Windows `taskkill` 自身也有 5 秒上限。若仍无法确认子进程退出，返回“结果未确认”，本机模型并发许可继续保留到该 PID 退出，避免继续叠加调用。
- 任务、冻结输入、视觉方案检查点、已提交图片和历史返回仍被保留。未完成的模型链路标记为失败且结果未知，不伪造模型输出或耗时。上传、完成和回收使用数据库锁，防止回收后写入晚到结果。
- 超时、取消和失效执行不会自动重放模型调用。检查执行机和已保存结果后，通过已有重试或续跑入口恢复任务。

## 升级顺序

1. 更新中心服务，执行 `npm --prefix server run db:upgrade -- --apply`，并重启中心服务。启动也会自动应用 `0013_execution_heartbeats.sql`。该迁移新增可空心跳字段和恢复索引，不删除业务数据。
2. 更新并重启各执行机。无需新增环境变量。中心 `/health` 的 `capabilities.executionHeartbeats` 为 `true` 表示支持任务心跳。
3. 检查原有卡住任务：满足期限的执行会转为失败并注明原因。根据详情中的模型返回和保存产物，决定重试或续跑。

为了滚动升级兼容，旧执行机以及首次任务心跳尚未成功的执行，使用 30 分钟无进度兜底；只有成功发送过任务心跳的执行才启用 2 分钟失联回收。新执行机连接旧中心时保持原协议，因此应先更新中心。

## 验证

`npm test` 和 `npm --prefix server test` 覆盖模拟模型、任务心跳、取消传播、有界进程清理和回收调度。以下真实 PostgreSQL 集成测试创建独立临时数据库，不读取项目 `.env` / `DATABASE_URL`，不连接生产数据库，也不消耗模型额度：

```powershell
$env:TEST_POSTGRES_BIN = 'C:\Program Files\PostgreSQL\18\bin'
node --test server/integration/execution-recovery.mjs
```

该测试覆盖旧任务、失联、进度停滞、正常任务保留、并发回收、事务回滚、已保存产物保留、晚到写入拒绝，以及图片上传与回收同时发生时的锁定行为。
