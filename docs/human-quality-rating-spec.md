# Spec: 人工文案与图片就绪度评分

## Objective

在分布式作业工作台的文案审核和图片审核中增加人工评分。评分用于版本质量记录、返修分析和三分率统计；它不复用自动 QC 分，也不由模型填写。

## Rating scale

人工评分只允许 `1 | 2 | 2.5 | 3`：

- `1`：当前版本不可用；文案机器原稿应废弃，图片可重试或废弃。
- `2`：需要明显修改或重做，不能直接放行。
- `2.5`：接近达标；文案机器原稿仍须实际修改，图片可以通过。
- `3`：达到无需修改文案或图片即可确认通过的标准。

文案和图片使用不同的通过规则。文案机器原稿只有 `3` 分可在不修改标题、正文或标签时确认通过；`2` 分或 `2.5` 分必须发生真实文案修改，人工确认达标后由系统将最终稿记录为 `3` 分。图片的通过阈值仍为 `score > 2`，因此 `2.5` 分和 `3` 分可以通过，`1` 分和 `2` 分只能重试或废弃。评分本身不会自动放行或废弃，人工仍需明确提交相应审核动作。

## Review presentation

生产配置中的人工评分设置允许管理员控制：

- 文案审核是否展示评分档位的名称和说明；
- 文案审核和图文终审是否分别展示扣分原因选项。

三个开关默认开启，且只改变对应审核界面的展示，不改变固定分值或各阶段的通过规则。只有管理员可以修改这些设置；普通用户和审核员只能按当前生产配置进行审核。文案机器原稿低于 `3` 分时仍需填写扣分原因或评分说明，隐藏文案扣分原因后评分说明必填；图文终审只强制选择分数，扣分原因、问题页和评分说明始终选填。

## Source of truth

- 评分写入 PostgreSQL 控制面，并由 `/workbench` 读取。
- 每条评分绑定不可变的 `copy_revision_id` 或 `image_run_id`。
- 审核人取自服务端认证上下文，不接受客户端指定。
- 记录只追加不覆盖；历史数据保持“未评分”，不从旧审核状态推断分数。
- 自动 QC 的 `0–3` 整数分与人工评分分开存储、分开展示和统计。

## Copy review

1. 机器原稿在 `COPY_REVIEW_PENDING` 中接受初评。
2. 在账号有权处理当前任务且任务处于可编辑状态的前提下，只有分数决定标题、正文和标签能否修改：`2` 和 `2.5` 解锁编辑，`1` 和 `3` 保持只读。扣分原因或评分说明是否已经填写，不影响编辑解锁，只约束评分或审核动作能否提交。
3. `1` 分可在保留评分和反馈后废弃；`2` 分和 `2.5` 分都必须实际修改标题、正文或标签，机器原稿不能直接放行；只有 `3` 分机器原稿可不改文案直接确认通过。
4. 保存标题、正文或标签的人工修改时创建新的未批准文案修订版，任务仍停留在 `COPY_REVIEW_PENDING`。
5. 标题、正文或标签发生真实修改后，不再要求“修改后自评”。审核人确认修改稿达标时，系统把当前最终稿记录为 `3` 分，同时保留机器原稿的初评分、扣分原因和说明。
6. 评分后再次修改标题、正文或标签时，旧评分仍保留在原版本上，但不能作为新版本的当前评分；新版本需要重新确认达标。
7. 普通生产批次的首次初审通过只表示当前文案已达标。批次闭合后，系统按冻结的抽检配置直接放行或先进入普通抽检；只有无需抽检或抽检完成后，任务才进入 `IMAGE_QUEUED`。
8. 文案抽检或图文终审打回的返工稿在人工确认达标后必须进入 `MANDATORY_RECHECK`。提交返工稿不会立即进入生图；只有强制复检通过后，任务才进入 `IMAGE_QUEUED`。
9. 图片文案规划在账号有权处理当前任务且任务处于可编辑状态时始终可修改，不受文案分数档位或扣分反馈完整度影响。仅修改规划不算真实文案修改，不能让 `2` 分或 `2.5` 分机器原稿通过，也不会触发系统将最终稿记录为 `3` 分。

## Image review

1. 只有完整图片运行进入 `MANUAL_ARCHIVE` 后才计入人工图片评分。
2. 第一版按整套 `image_run` 评分，低分时可选填问题页、原因和说明；这些反馈不影响提交。
3. `2.5` 或 `3` 可通过并进入 `REVIEWED`。
4. `1` 或 `2` 可重试或废弃，但不能通过。
5. 重试和废弃必须保留评分人、分数和时间；已填写的原因、问题页和说明一并保留。
6. 管理员在重试时可修正当前图片规划的逐页文字与画面指令；中心必须在同一事务中保存本轮图片评分、新的人工批准修订版和任务指针，旧修订与旧图集保持不可变。页数和页面类型不能在图片审核阶段改变。

## Statistics

- 文案首评三分率：每个任务首个机器原稿初评为 `3` 的任务数 / 已完成文案初评的非免审任务数。
- 文案首评高于两分占比：文案初评为 `2.5` 或 `3` 的任务数 / 已完成文案初评的非免审任务数；该指标不代表 `2.5` 分机器原稿可以直接放行。
- 图片首轮三分率：每个任务首套完整、非模拟图集初评为 `3` 的任务数 / 已完成首轮图片评分的任务数。
- 图片达标率：图片首评为 `2.5` 或 `3` 的任务数 / 已完成图片首评的任务数。
- 当前页面展示三分率、高于两分占比和有效样本数；后续可基于同一明细扩展评分覆盖率、`2/2.5 → 最终确认 3` 转化率、返修次数和低分原因。

重复评分不能扩大分母；免审、模拟和历史未评分项目应单列。

## Acceptance criteria

1. 前后端均拒绝 `1、2、2.5、3` 以外的评分。
2. 文案机器原稿只有 `3` 分能在未修改标题、正文和标签时确认通过；`2` 分和 `2.5` 分都必须发生真实文案修改，`1` 分只能废弃。
3. 人工确认修改稿达标后，系统将最终稿记录为 `3` 分，不接受客户端对修改稿提交 `2.5` 分自评，也不覆盖机器原稿的初评事实。
4. 图片只有 `2.5` 分和 `3` 分能与通过动作组合；`1` 分和 `2` 分只能重试或废弃，服务端拒绝矛盾组合。
5. 文案评分绑定当前文案修订版，图片评分绑定当前图片运行；旧版本提交返回冲突。
6. 人工评分不修改或覆盖自动 QC。
7. 文案修改稿可以保存而不立即进入生图队列。
8. 普通批次按冻结配置直接放行或先抽检；返工稿提交后必须强制复检，且只有复检通过后才进入待生图队列。
9. 文案评分废弃，以及图片重试、废弃和通过，都留下追加式评分记录。
10. 重复网络请求不会创建重复的审核提交。
11. 自动测试使用 Fake，不调用模型或消耗模型额度。
12. 评分档位说明以及文案、图文终审扣分原因的展示开关只有管理员可修改；开关只影响对应审核界面，不改变评分值或通过规则。
13. 标题、正文和标签只在文案机器原稿评分为 `2` 或 `2.5` 时可编辑；低分反馈是否填写只影响提交，不影响字段解锁。
14. 有权限且处于可编辑状态的审核人可以在任意文案分数下修改图片文案规划；仅修改规划不算真实文案修改，也不能让 `2` 分或 `2.5` 分机器原稿通过。
