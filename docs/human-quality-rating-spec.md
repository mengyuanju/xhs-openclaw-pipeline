# Spec: 人工文案与图片就绪度评分

## Objective

在分布式作业工作台的文案审核和图片审核中增加人工评分。评分用于版本质量记录、返修分析和三分率统计；它不复用自动 QC 分，也不由模型填写。

## Rating scale

人工评分只允许 `1 | 2 | 2.5 | 3`：

- `1`：当前版本不可用，建议废弃当前版本或重新生成。
- `2`：需要明显修改或重做，不能直接放行。
- `2.5`：达到最低放行标准，可进入下一阶段，也可选择小修。
- `3`：无需修改即可直接进入下一阶段。

文案和图片的放行阈值均为 `score > 2`。因此 `2.5` 和 `3` 可以通过；`1` 和 `2` 不能与通过动作组合。评分不会自动放行或废弃，人工需再明确选择保存、通过、重试或废弃动作。

## Source of truth

- 评分写入 PostgreSQL 控制面，并由 `/workbench` 读取。
- 每条评分绑定不可变的 `copy_revision_id` 或 `image_run_id`。
- 审核人取自服务端认证上下文，不接受客户端指定。
- 记录只追加不覆盖；历史数据保持“未评分”，不从旧审核状态推断分数。
- 自动 QC 的 `0–3` 整数分与人工评分分开存储、分开展示和统计。

## Copy review

1. 机器原稿在 `COPY_REVIEW_PENDING` 中接受初评。
2. `1` 分可在保留评分和原因后废弃；`2` 分进入修改；`2.5` 分可修改或直接通过；`3` 分可直接通过。
3. 保存人工修改时创建新的未批准文案修订版，任务仍停留在 `COPY_REVIEW_PENDING`。
4. 修改稿接受“修改后自评”。当前修改稿为 `2.5` 或 `3` 时可进入 `IMAGE_QUEUED`。
5. 评分后再次修改内容时，旧评分仍保留在原版本上，但不能作为新版本的当前评分。

## Image review

1. 只有完整图片运行进入 `MANUAL_ARCHIVE` 后才计入人工图片评分。
2. 第一版按整套 `image_run` 评分，低分时可记录问题页、原因和说明。
3. `2.5` 或 `3` 可通过并进入 `REVIEWED`。
4. `1` 或 `2` 可重试或废弃，但不能通过。
5. 重试和废弃也必须保留评分人、分数、原因和时间。
6. 管理员在重试时可修正当前图片规划的逐页文字与画面指令；中心必须在同一事务中保存本轮图片评分、新的人工批准修订版和任务指针，旧修订与旧图集保持不可变。页数和页面类型不能在图片审核阶段改变。

## Statistics

- 文案首评三分率：每个任务首个机器原稿初评为 `3` 的任务数 / 已完成文案初评的非免审任务数。
- 文案达标率：文案初评为 `2.5` 或 `3` 的任务数 / 已完成文案初评的非免审任务数。
- 图片首轮三分率：每个任务首套完整、非模拟图集初评为 `3` 的任务数 / 已完成首轮图片评分的任务数。
- 图片达标率：图片首评为 `2.5` 或 `3` 的任务数 / 已完成图片首评的任务数。
- 当前页面展示三分率、高于两分的达标率和有效样本数；后续可基于同一明细扩展评分覆盖率、`2 -> 2.5/3` 转化率、返修次数和低分原因。

重复评分不能扩大分母；免审、模拟和历史未评分项目应单列。

## Acceptance criteria

1. 前后端均拒绝 `1、2、2.5、3` 以外的评分。
2. 只有 `2.5` 和 `3` 能与通过动作组合；服务端拒绝矛盾组合。
3. 文案评分绑定当前文案修订版，图片评分绑定当前图片运行；旧版本提交返回冲突。
4. 人工评分不修改或覆盖自动 QC。
5. 文案修改稿可以保存而不立即进入生图队列。
6. 文案评分废弃，以及图片重试、废弃和通过，都留下追加式评分记录。
7. 重复网络请求不会创建重复的审核提交。
8. 自动测试使用 Fake，不调用模型或消耗模型额度。
