# 图片生成与图片编辑真实端到端测试方案

日期：2026-09-15<br>
范围：文案生成、多页图片生成、人工生成标识、真实产品融合、自然语言局部修改、预览采用、跨页版本合并、失败恢复和审计。<br>
运行原则：真实模型用例必须显式开启付费开关；不使用 mock 冒充模型结果；测试任务标记为 `IMAGE_EDIT_FULL_E2E_20260915`，不得发布。

## 1. 验收目标

1. 文案执行机生成 5 页经过结构校验的文案和图片计划，页面类型覆盖封面、步骤、对比、清单和总结。
2. 5 张图片逐张由真实图片模型生成并通过 OCR、语义、版式、尺寸和整组质量校验。
3. 不同版式不应造成整套视觉语言漂移。重点检查相同层级字体、文字框形状和文字框颜色的一致性。
4. 人工生成标识只影响目标页，不得从已采用页面串到其他页面的源图校验或结果文字白名单。
5. 真实产品参考图通过上传、规范化、哈希绑定、模型融合和实体一致性校验，参考图不得进入交付图集。
6. 无蒙版自然语言编辑能定位指定对象或区域，保持未点名区域及全部已有文字。
7. 每次采用都创建新图片运行；未编辑页面继续引用正确资产；旧源图不覆盖；审计、模型调用和执行租约可追溯。

## 2. 测试数据

- 生产链路测试任务：固定 5 页，查询明确要求不同版式，但统一现代无衬线字体、奶油白圆角文字框和橙棕色强调色。
- 真实产品参考：Wikimedia Commons 的 CC0 红色陶瓷马克杯实拍图，保留来源、许可、原始 SHA-256 和规范化 SHA-256。
- 编辑顺序：第 1 页文字标识 → 第 2 页真实产品融合 → 第 3 页自然语言局部修改 → 在旧基线页上再创建编辑以验证跨页重基。
- 所有结果保存在 `output/live-e2e/production-task-<taskId>/`，报告不得包含凭据或数据库连接串。

## 3. 端到端主流程

| 编号 | 场景 | 操作 | 必须验证 |
| --- | --- | --- | --- |
| E2E-01 | 启动与能力 | 启动生产控制端，等待两个执行机心跳 | 迁移校验通过；执行机声明 `imageEditExecutorVersion=1`；容量和真实 RUNNING 执行一致 |
| E2E-02 | 真实文案生成 | 创建固定 5 页测试任务 | COPY 被领取；研究、生成、审核阶段有心跳；文案和 5 页 `imagePlan` 落库；模型不是 fake/mock |
| E2E-03 | 真实多页图片生成 | 文案通过后自动生图 | 5 页均为 1086×1448 PNG；每页 OCR 与本页白名单一致；无串页文字；模型调用与执行记录完整 |
| E2E-04 | 套图字体一致性 | 对 5 页原图做多图视觉比较 | headline、subtitle、正文分别归类；相同层级字体类别/字重一致；全页字体不超过 3 种；不存在某一页突然变为手写、衬线或另一套展示字体 |
| E2E-05 | 文字框配色一致性 | 提取标题框、正文框的近似 HEX 与形状 | 同类文字框圆角/描边/阴影语言一致；主文字框颜色属于同一色簇；不得出现无业务原因的黑框、纯白框或完全不同高饱和色；文字对比清晰 |
| E2E-06 | 添加人工生成标识 | 第 1 页添加“该人物形象由AI生成”并采用 | 目标文字逐字、清晰、只出现一次、右下角；已有文字不变；仅第 1 页资产变化；标识元数据写在第 1 页 |
| E2E-07 | 跨页标识隔离 | 第 3 页在第 1 页已采用标识后创建编辑 | 第 3 页源图校验不要求第 1 页标识；不得出现“源图必需文字缺失”的假失败；第 1 页标识继续保留 |
| E2E-08 | 真实产品融合 | 上传红色陶瓷马克杯实拍图并替换第 2 页对应马克杯 | 上传格式/大小/像素/哈希正确；参考实体颜色、圆柱杯身、白色内壁、C 形杯把保留；无矩形贴片；全部文字保持；参考资产不进入交付图集 |
| E2E-09 | 自然语言局部修改 | 第 3 页按位置描述修改托盘或背景颜色 | `localization.mode=PROMPT`；指定区域明显变化；未点名物品、构图和文字保持；不新增文字/图标/物体 |
| E2E-10 | 多页重基与采用 | 不同页面连续创建并采用编辑 | 新运行合并最新非目标页，不回退先前已采用编辑；目标页 parent/source/hash 正确；旧运行仍可追溯 |
| E2E-11 | 预览与审计 | 查看前后对比、拒绝一个草稿、采用有效预览 | DRAFT/QUEUED/RUNNING/PREVIEW_READY/ACCEPTED 状态正确；CREATE/EXECUTE/VALIDATION/ACCEPT 事件完整；重复请求幂等 |
| E2E-12 | 恢复与失败路径 | 取消草稿、提交非法参考、模拟租约过期与服务前置失败 | 非法输入不调用模型；过期只失败一次且不自动重试收费；失败文本可读；并发槽释放；重试不超过 3 次 |

## 4. 文字和文字框专项判定

- 精确文字：按 NFKC、去空白和标点后的程序比较为辅助，最终仍要求视觉模型确认字形可读；数字、单位、中文标点单独检查。
- 字体类型：视觉模型只能判断字体类别和视觉特征，不能从像素可靠识别具体字体文件。因此记录 `SANS_SQUARE`、`SANS_ROUNDED`、`SERIF`、`HANDWRITTEN`、`DISPLAY_OTHER`，按 headline/subtitle/body 分层比较。
- 文字框颜色：记录每页标题框和正文框的估计 HEX；同类框以 RGB 欧氏距离不超过 40 作为自动预警阈值，视觉检查确认渐变、透明度和场景光照造成的合理偏差。
- 一致性和多样性分开判定：页面布局骨架应不同；字体家族、字重体系、圆角、阴影、描边和核心配色必须一致。
- 任何 OCR 错字、串页文字、黑色悬浮字幕、低对比、遮挡主体或页边裁切均为失败。

## 5. 数据与调用核验

- `task_executions`：COPY/IMAGE/IMAGE_EDIT 的节点、阶段、心跳、开始结束时间和错误。
- `model_call_traces`：操作类型、模型、状态、尝试次数；测试报告只记录计数和安全字段。
- `image_runs` / `image_run_asset_members`：每次采用后的完整页集合与跨页资产继承。
- `assets`：PNG 尺寸、sha256、parent_asset_id、origin_image_run_id、asset_role 和 edit_metadata。
- `image_edit_requests/results/events`：版本、租约、校验、实体一致性、定位方式和审计动作。
- 验证结束后保留测试任务和本地报告供人工复核，不执行发布。

## 6. 通过标准

- 主流程 E2E-01～E2E-10 全部通过；E2E-11～E2E-12 的无模型负向用例全部通过。
- 真实模型结果允许因生成随机性触发业务校验失败，但系统必须正确阻断采用、保存证据并释放执行容量；重新生成只在显式付费重试后发生。
- 套图字体或文字框配色不一致属于产品质量缺陷，即使 OCR/语义校验通过也在报告中单独判失败，不能写成“整体通过”。
