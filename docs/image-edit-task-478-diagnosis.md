## 页面被撑开

历史记录中的预检说明、失败详情、质量记录和审计 JSON 缺少完整换行约束。自动网格轨道会被无断点长文字扩宽；多次失败又默认展开全部预检提醒，使记录区很长。

当前图片与独立图片编辑器共用的历史样式现在使用 `minmax(0, 1fr)`、`min-width: 0` 和长文字换行。标题、按钮允许换行，失败详情高度最多 260px，超长内容内部滚动。执行前提醒默认折叠并显示条数，完整提醒仍可展开。

假数据浏览器回归包含 9 条历史、长错误、预检和审计 JSON；1010×878 桌面和 390×844 手机均无横向溢出。原两套图片编辑器浏览器测试也通过。

最有力的根因候选是 Codex Windows 沙箱读取大文件时的输出丢块。官方仓库已有高度匹配的 [问题 #46815](https://github.com/openai/codex/issues/46815)。其对应版本源码使用 [8 KiB 读取块](https://github.com/openai/codex/blob/rust-v0.155.0-alpha.9.2/codex-rs/windows-sandbox-rs/src/process.rs#L324)、[容量 256 的广播队列及不等待的发送](https://github.com/openai/codex/blob/rust-v0.155.0-alpha.9.2/codex-rs/windows-sandbox-rs/src/unified_exec/backends/legacy.rs#L164)，并在消费者落后时 [跳过丢失块](https://github.com/openai/codex/blob/rust-v0.155.0-alpha.9.2/codex-rs/utils/pty/src/process.rs#L402)。图片经文件读取器转为 Base64 后会放大约三分之一；6034 对应 19,465,800 字节，远大于约 2 MiB 的瞬时积压容量，6341 对应 1,742,188 字节，在该范围内。

这不是官方模型图片大小限制，也不是超过某个大小就必然失败；调度时机影响是否丢块。历史记录没有保存 `haimo1` 的实际 CLI 版本及完整原生工具参数，且已解析响应覆盖了原始协议输出。因此以上是有源码、文件完整性与大小对照支持的高置信判断，尚未逐层重现历史请求。

## 输入传输防护

上传文件和已有资产保持原样。原生工具只接收本次制作的临时副本，每张最多 1 MiB，以给 Windows 文件读取器的 Base64/JSON 留出余量：

- 小图保留全分辨率、无损 PNG。
- 超限的不透明图先转质量 95、4:4:4 的 JPEG，保留文字与画面尺寸；仍超限才等比缩小。
- 透明图保留 PNG 和透明度，超限时等比缩小。
- 全画面和方向保留，不裁剪、不拉伸；只使用明确的有序 `referenced_image_paths`，最多 5 张输入，不从历史附件猜选、不手工拼 Base64。

## 已生成但验收未通过

历史人工采用的失败预览属于另一种情况：已有原生生成图片，但建筑上的企业标志、额外文字与本页批准文字白名单不符，因而自动验收失败。输入传输防护不能保证这些质量问题消失；验收规则继续生效。

13:52:46 最新失败也属于这类质量问题，而非 Base64 或图片生成失败。正式记录证明：

- 图片原生生成 1 次成功；`generationAttempts=1`、`billedImageGeneration=true`。
- `entityConsistency.passed=true`：参考建筑匹配、目标位置正确、单个替换正确、其他内容保持。
- `dimensions.passed=true`：结果 PNG 为 1086×1448。
- 标题、副标题和四条分类文字均识别成功；条目核对全部通过，没有正文缺失或顺序错误。
- `text.passed=false`、`failureClass=EXTRA_FACT`：画面仍包含 Optolink、COHERENT、LUMENTUM、1750、HGTECH、Accelink 等额外可读标志/招牌。错误摘要中的 `missing:["otherText"]`、`extra:["otherText"]` 是结构化字段差异，不能解释为“正文缺失”；具体原因在 `validation.text.extraClaims`。

当前编辑说明要求“保持全部文字不变”，而本页规则要求“企业标志”和“任何额外可读文字、数字或标签”不得出现。源图本就含违规楼体招牌，参考图也带 Optolink，完整保留文字会保留这些违规内容。预检仅提醒、不阻止生成，不能自动豁免最终验收。因此传输更新后，同样的说明仍可能因规则冲突失败。

若继续遵守现有页面规则，编辑说明应明确只保留六条批准正文，允许去除所有建筑上的标志、招牌和额外数字；若确实需要保留楼体品牌，则须先由用户决定修改本页内容规则。此次排查没有放宽验收、改写请求或再次调用图片模型。

更新 Web 后布局改动生效；生成防护需在 `haimo1`、`haimo2` 等实际图片执行机更新并重启后生效。不需要数据库迁移。本次没有进行收费真实生成验证。
