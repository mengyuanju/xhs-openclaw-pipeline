## 1. 文档目的

本方案用于解决大批量小红书图文生产中的四类核心问题：

1. 图片必须根据最终生成文本制作，并能追溯到对应正文，而不只是“提示词里带了正文”。
2. 图片风格需要贴合内容垂类、语气、受众和信息密度，同时保持同一篇笔记内部统一。
3. 大批量任务之间需要有足够的风格差异，避免同质化、通用模板感和连续重复。
4. 图片中的简体中文需要尽量减少繁简混用、错字、乱码、漏字和不可辨认字符。

本文明确区分当前已经实现的能力与后续建议，避免把提示词约束误认为已经完成质量闭环。

## 2. 目标与非目标

### 2.1 目标

- 最终图片内容只来自已确定的文本版本和可追溯的页面计划。
- 同一篇笔记的 3–5 张图片风格统一，但页面构图根据职责变化。
- 不同笔记从匹配内容的风格候选中受控轮换，而不是永远选择最高分配方。
- 生成后自动检查图文语义、可见文字、版式和风格一致性。
- 文本修改后旧图片自动失效，未重新验收前不得批准。
- 批量生产可恢复、可限流、可统计、可复现。

### 2.2 非目标

- 本方案不增加自动发布到小红书的能力。
- 本方案不允许未授权参考图进入图生图。
- 本方案不承诺仅靠图片模型即可实现 100% 中文准确率。
- 本方案不要求每一张图片使用完全不同的风格；多样性以“不同笔记之间不同、同一笔记内部统一”为原则。

## 3. 当前实现

### 3.1 当前生成链路

```text
Excel 导入并固定任务配置
        ↓
文本模型一次生成 title、body、imagePlan
        ↓
每页组合图片系统提示词、视觉配方、完整正文和当前页计划
        ↓
首图：无参考图则文生图，有参考图则图生图
        ↓
后续图：外部参考图 + 已规范化首图作为风格参考
        ↓
Sharp 统一为 1086×1448 PNG
        ↓
机械 QC、保存资产、进入人工审核
```

主要实现位置：

- [src/post-contract.mjs](../src/post-contract.mjs)：校验文本模型返回的 `imagePlan`。
- [src/pipeline.mjs](../src/pipeline.mjs)：组合每页提示词和执行任务管线。
- [src/images.mjs](../src/images.mjs)：逐页调用图片模型并规范化输出。
- [src/openclaw.mjs](../src/openclaw.mjs)：封装文本、视觉、文生图和图生图命令。
- [src/qc.mjs](../src/qc.mjs)：执行当前机械质检。

### 3.2 已经解决的部分

- 每张图片的最终提示词包含完整标题、完整正文和当前页计划。
- `imagePlan` 数量固定为 3–5，第一张必须是 `hero`。
- 每页有独立的标题、副标题、要点和视觉方向。
- 后续页面使用首图延续色调、光影、装饰和视觉符号。
- Live 模式下每张交付图都调用一次图片模型。
- 输出统一为 1086×1448 PNG，并检查完全重复文件。

### 3.3 尚未解决的部分

#### 3.3.1 图片文字并非从最终正文做二次提取

当前 `title`、`body` 和 `imagePlan` 由文本模型在同一次调用中同步生成。系统要求它们一致，但没有在正文确定后执行独立的提取步骤，也没有记录每个图片要点来自正文哪一段。

因此当前状态是“逻辑上要求一致”，不是“可验证、可追溯地提取”。

#### 3.3.2 没有生成后图文匹配验收

当前 QC 检查图片数量、尺寸、格式、来源、完全重复以及正文风险字段，但不会让视觉模型重新读取最终图片，所以无法自动发现：

- 图片主体或场景与正文不符；
- 图片展示了另一页的内容；
- 缺少关键步骤或数字；
- 图片新增正文没有的事实；
- 图片中的中文错字、乱码、漏字；
- 图片风格或排版不适合当前内容。

#### 3.3.3 风格检索容易集中到同一个高分配方

当前视觉配方评分主要使用质量分、类别精确匹配、受众文本和标签子串。相似选题会重复命中相同的最高分配方，缺少批次配额、近期去重和 Top-K 抽样。

#### 3.3.4 风格与布局没有分层

当前一个任务只锁定一条视觉配方，并应用到整套图片。配方虽然保存 `layoutRules`，但运行时没有将其加入提示词。封面、步骤、清单、对比和总结页主要依赖图片模型自行理解 `kind`。

#### 3.3.5 文本修改后图片不会自动过期

图片资产只关联任务，没有关联生成时使用的文本版本和图片计划。管理员修改正文后，旧图片仍然可以参与审核，可能形成新的图文不一致。

#### 3.3.6 简体中文要求不足以保证文字正确

提示词要求中文清晰、无错字，但没有明确 `zh-CN` 白名单、OCR 对比和自动修复。即使补充“使用简体中文”，也只能减少繁简混用，不能可靠消除伪文字、错字、漏字和字形错误。

## 4. 总体决策

### 4.1 决策一：采用两阶段文本与视觉规划

先生成并确定最终正文，再由独立视觉规划步骤只读取最终文本，生成可追溯的 `visualBrief`。

```text
选题数据
   ↓
生成并校验最终正文
   ↓
从最终正文提取 visualBrief
   ↓
校验来源、数字和允许显示文字
   ↓
进入图片生成
```

这样可以避免正文和图片计划在同一次模型输出中相互漂移。

### 4.2 决策二：风格与布局分层

- `collectionStyle`：笔记级风格，一篇笔记只选择一个，控制媒介、色彩、字体、质感、装饰和留白。
- `pageLayout`：页面级布局，根据 `hero`、`steps`、`checklist`、`comparison`、`detail`、`summary` 独立选择。

风格统一不等于排版相同。页面可改变信息结构，但不能改变整套图的核心视觉语言。

### 4.3 决策三：使用受控风格调度，不使用纯随机风格

不同任务应先按内容匹配过滤，再从 Top-K 候选中进行稳定带权抽样。批次层控制风格使用配额和近期重复。

### 4.4 决策四：增加生成后视觉验收与有限重试

最终 PNG 必须经过：

- OCR 或等价文字识别；
- 视觉模型语义验收；
- 风格和布局验收；
- 跨页与跨任务近似重复检查。

严重语义错误重新生成当前页，轻微排版或文字问题使用图生图修复。每页最多自动修复两次，仍失败则阻断并进入人工审核。

### 4.5 决策五：简体中文采用白名单与确定性渲染优先

当前采用“模型生成无字视觉素材、程序渲染中文”的混合模式，并保留简体中文白名单和 OCR/VLM 验收。

每张交付页的视觉底图仍必须来自图片模型；程序只负责受控文字、合规标识和最终 PNG 合成，不得以本地占位图替代模型视觉素材。

## 5. 目标管线

```text
任务入队并固定提示词版本
        ↓
文本生成与人工修改
        ↓
锁定 currentTextRevision
        ↓
视觉规划：内容提取、来源映射、整套风格、逐页布局
        ↓
确定性校验：页数、段落来源、数字、可见文字白名单
        ↓
批次风格调度：内容匹配、Top-K 抽样、配额和近期去重
        ↓
逐页提示词编译
        ↓
逐页图片生成
        ↓
OCR + 视觉语义 + 风格布局 + 近似重复验收
        ↓
通过 ───────────────→ 保存并进入人工审核
        ↓ 未通过
轻微问题：图生图修复；严重问题：重新生成当前页
        ↓
最多两次仍未通过 → 阻断并展示证据
```

## 6. 视觉规划数据契约

建议增加独立的 `visualBrief`，不再只依赖自由文本 `imagePlan.prompt`。

```json
{
  "schemaVersion": 1,
  "sourceTextRevisionId": 128,
  "sourceTextSha256": "...",
  "collectionStyle": {
    "familyId": "warm-life-photo",
    "variantId": "warm-life-photo-v2-green",
    "contentTone": ["实用", "温和", "生活化"],
    "visualMedium": "真实生活摄影结合轻量信息卡",
    "palette": ["米白", "浅木色", "低饱和绿色"],
    "typography": "简体中文无衬线，标题粗体，正文常规体",
    "decoration": "圆角标签、细线图标",
    "informationDensity": "medium"
  },
  "pages": [
    {
      "index": 1,
      "kind": "hero",
      "sourceParagraphIds": [1, 2],
      "sourceEvidence": ["桌面反复变乱，问题通常不在收纳盒不够"],
      "visualSubject": "真实租房桌面整理后的生活场景",
      "layoutId": "hero-subject-center-title-left-v1",
      "allowedVisibleText": {
        "headline": "桌面整理先做减法",
        "subtitle": "别急着买收纳盒",
        "bullets": []
      },
      "mustShow": ["真实桌面", "完成整理后的清爽状态"],
      "mustAvoid": ["购物推荐", "无关品牌", "正文没有的数据"]
    }
  ]
}
```

### 6.1 来源规则

- 每页必须记录一个或多个 `sourceParagraphIds`。
- 事实、步骤、数字和专有名词必须有 `sourceEvidence`。
- 关键数字必须与正文逐字一致，不允许模型换算或推测。
- `allowedVisibleText` 是图片中唯一允许出现的主要可见文案。
- 标题可以是正文原句或受控缩写；受控缩写必须保留来源证据，不得产生新事实。
- 正文没有的建议、数据、价格、时间和结论不得进入图片。

### 6.2 修改失效规则

任何标题、正文或页面计划修改后：

1. 重新计算 `sourceTextSha256` 和 `visualBrief` 哈希。
2. 与旧哈希不一致的图片标记为 `STALE`。
3. `STALE` 图片不得作为最终审核通过依据。
4. 重新生成或重新验收后才能恢复为 `PASSED`。

## 7. 内容驱动的风格设计

### 7.1 内容视觉画像

视觉规划阶段应从完整正文提取：

- 垂类：家居、旅行、美食、科普、情绪、穿搭等；
- 内容形态：教程、清单、对比、故事、测评、路线、知识解释；
- 情绪：温和、轻松、克制、专业、活泼、紧迫；
- 受众：年龄、使用场景、阅读目的；
- 信息密度：低、中、高；
- 视觉媒介：真实照片、纪实场景、插画、信息图或混合；
- 重点主体：人物、物品、动作、空间、数字或流程。

### 7.2 风格包

每个风格包至少包含：

- 稳定 `familyId` 和 `variantId`；
- 适用类别、内容形态、情绪和受众；
- 视觉媒介与真实感要求；
- 主色、辅助色、明暗、饱和度；
- 字体和文字层级；
- 边框、圆角、图标和装饰；
- 各页面类型允许的布局；
- 负面约束；
- 可选的授权参考图；
- 历史质量分、使用次数和近期使用时间。

建议先维护 12–20 个基础风格，每个风格提供 3–5 个配色或装饰变体。

### 7.3 页面布局映射

| 页面类型 | 信息职责 | 推荐布局 | 文字密度 |
|---|---|---|---|
| `hero` | 回答核心问题、建立主题 | 强主体场景＋大标题 | 低 |
| `steps` | 按顺序展示动作 | 编号纵向流程、分镜或路径 | 中 |
| `checklist` | 提供检查与执行清单 | 勾选卡片、分组清单 | 中 |
| `comparison` | 展示差异和选择依据 | 左右双栏、前后对比 | 中至高 |
| `detail` | 展示局部、结构或操作细节 | 局部特写＋标注 | 低至中 |
| `summary` | 收束结论和下一步行动 | 核心结论＋行动卡片 | 低至中 |

同一篇笔记共用 `collectionStyle`，但每页根据 `kind` 选择独立 `layoutId`。

## 8. 大批量风格调度

### 8.1 原则

- 不同笔记之间追求多样性，同一笔记内部追求一致性。
- 先保证内容匹配，再保证新鲜度。
- 不允许完全自由随机；随机只能发生在已通过内容匹配过滤的候选中。
- 选择结果必须可复现，任务重试默认保持原风格。

### 8.2 候选过滤

先过滤掉：

- 状态不是 `PUBLISHED` 的风格；
- 生成目标不是 `MODEL_IMAGE` 的风格；
- 类别、内容形态或视觉媒介明显不匹配的风格；
- 不支持当前关键页面类型的风格；
- 达到批次配额或处于近期冷却期的风格；
- 参考图授权状态不允许图生图的风格。

### 8.3 评分与抽样

建议将评分归一化为 0–1：

```text
finalScore =
  contentRelevance × 0.45
  + historicalQuality × 0.20
  + batchNovelty × 0.20
  + recentNonUsage × 0.10
  + quotaAvailability × 0.05
```

对分数最高的前 5 个候选做带权抽样，使用 `taskId + styleCatalogVersion` 作为稳定随机种子。

### 8.4 批次约束

- 相邻 3 个任务不得使用同一个基础风格族。
- 单个风格族占同一批次的比例默认不超过 15%。
- 同一类别连续任务不得使用相同 `variantId`。
- 同一风格失败重试时保持原风格；只有明确判定为风格不匹配时才重新调度。
- 批次规模不足以满足所有约束时，内容匹配优先于多样性。

### 8.5 推荐规模

```text
15 个基础风格
× 4 个配色或装饰变体
× 每种页面类型 3 个布局变体
= 足以支持大批量生产的受控组合空间
```

组合数量不能代替质量控制。所有变体仍需经过发布、校准和使用配额管理。

## 9. 简体中文与排版质量

### 9.1 图片模型提示词要求

每张图片应包含以下固定约束：

```text
所有可见文字必须使用中国大陆规范简体中文（zh-CN）。
只能逐字使用 allowedVisibleText 中提供的文字，不得改写、增删、翻译或自行补充。
禁止繁体字、异体字、拼音、英文占位符、乱码、伪文字和不可辨认字符。
如果无法准确显示某段文字，宁可不显示，也不得生成错误文字。
```

### 9.2 文字量约束

- 封面标题建议不超过 14 个可见字符。
- 单页副标题建议不超过 20 个可见字符。
- 单页主要要点控制在 2–4 条，每条建议不超过 12 个可见字符。
- 避免在模型图片中生成长段落、密集表格和大量连续数字。
- 重要数字、步骤顺序和主体名称必须使用白名单。

### 9.3 OCR 验收

对最终 PNG 识别可见文字，并与 `allowedVisibleText` 规范化后比较：

- 繁体、异体和不可辨认字符：硬失败；
- 标题、数字、步骤名称不一致：硬失败；
- 次要要点缺失：进入修复；
- 多出白名单外的明显文案：硬失败；
- OCR 置信度不足：进入人工审核，不能自动判定通过。

### 9.4 混合排版模式

当前生产链路采用：

```text
图片模型生成无文字或少文字的背景、主体和插画
        ↓
HTML、SVG 或 Sharp 使用固定简体中文字体精确排版
        ↓
OCR 再次核验最终文件
```

该模式具有更高的文字准确率、版式稳定性和修改效率，尤其适合步骤、清单、对比和数据页。代价是需要维护设计令牌、布局组件和字体资产，并修改当前全模型交付边界。

## 10. 生成后图文匹配验收

### 10.1 每页验收契约

```json
{
  "pageIndex": 2,
  "sourceTextRevisionId": 128,
  "visualBriefSha256": "...",
  "subjectMatched": true,
  "sceneMatched": true,
  "headlineMatched": true,
  "bulletCoverage": 0.75,
  "styleMatched": true,
  "layoutMatched": true,
  "contradictions": [],
  "extraClaims": [],
  "textErrors": ["第三个步骤文字无法辨认"],
  "passed": false,
  "failureClass": "MINOR_TEXT",
  "repairInstruction": "保留当前主体和风格，补充第三步文字并提高文字对比度"
}
```

### 10.2 硬失败条件

- 主体、场景或动作与当前页职责明显不符；
- 图片展示了另一页内容；
- 缺少核心步骤、关键结论或关键数字；
- 出现正文没有的新事实、价格、时间、结论或建议；
- 图片文字与正文矛盾；
- 标题、数字、专有名词或步骤顺序错误；
- 使用错误风格族或布局类型；
- 与同套图或批次历史图片高度近似；
- 繁体、乱码、不可辨认文字达到主要信息区域。

### 10.3 修复策略

| 问题类型 | 处理方式 |
|---|---|
| 文字对比度、轻微遮挡、小范围漏字 | 使用当前图片执行图生图修复 |
| 主体错误、场景错误、页面职责错误 | 基于首图风格参考重新生成当前页 |
| 风格偏移但内容正确 | 使用首图和风格配方执行图生图修复 |
| 中文大面积错误 | 直接重新执行程序排版；若模型底图含额外伪文字则重新生成无字底图 |
| 新增事实、数字错误、内容矛盾 | 重新生成，不在错误图片上继续叠加编辑 |

每页自动生成或修复总次数应受限，默认首次生成加两次修复。达到上限后记录证据并阻断，避免无限消耗模型额度。

### 10.4 整套图验收

除逐页检查外，还应检查：

- 页面顺序是否符合正文逻辑；
- 3–5 页是否覆盖主要内容且互补；
- 是否重复表达同一信息；
- 色调、字体、装饰和视觉媒介是否一致；
- 是否存在“同一底图只换文字”；
- 首图是否正确建立整套视觉风格；
- 是否与同批次近期图片高度相似。

当前 SHA-256 只能发现完全相同文件。批量场景还需要感知哈希或视觉向量检查近似构图和近似视觉内容。

## 11. 数据与状态建议

建议为图片资产和验收结果增加以下可追溯字段或等价结构：

- `source_text_revision_id`
- `source_text_sha256`
- `visual_brief_sha256`
- `page_index`
- `page_kind`
- `style_family_id`
- `style_variant_id`
- `layout_id`
- `generation_attempt`
- `alignment_status`: `PENDING | PASSED | FAILED | STALE | MANUAL_REQUIRED`
- `alignment_result_json`
- `ocr_result_json`

建议新增或扩展：

- `visual_plans`：保存正文到页面计划的来源映射。
- `style_assignments`：保存风格调度分数、候选和稳定种子。
- `image_generation_attempts`：保存每次生成或修复的模型、输入、失败类型和输出资产。
- `image_alignment_results`：保存 OCR 与视觉验收证据。

审核批准必须满足：

- 当前文本版本存在；
- 当前文本版本对应的全部页面图片存在；
- 图片没有 `STALE`；
- 全部页面为 `PASSED` 或有明确的人工覆盖记录；
- 最新生成运行不是 `mock_only` 或 `blocked`。

## 12. 批量执行与成本控制

### 12.1 队列拆分

建议将大批量流程拆为可恢复阶段：

1. `TEXT_GENERATION`
2. `VISUAL_PLANNING`
3. `STYLE_ASSIGNMENT`
4. `IMAGE_GENERATION`
5. `IMAGE_ALIGNMENT`
6. `IMAGE_REPAIR`
7. `MANUAL_REVIEW`

每个阶段保存状态和幂等键，进程中断后从未完成阶段继续，不重复消费已通过的模型调用。

### 12.2 模型调用预算

单条任务的基础成本预计为：

```text
1 次文本生成
+ 1 次视觉规划
+ 3–5 次图片生成
+ 3–5 次视觉验收
+ 0–2 次每页可选修复
```

应提供批次级任务上限、图片调用上限、视觉验收调用上限、修复上限和预计费用确认。视觉验收可根据模型能力将 1–3 张图片分批，但验收结果仍必须逐页输出。

### 12.3 并发与限流

- 文本、图片和视觉验收使用独立并发限制。
- 同一任务的图片默认按顺序生成，后续页只能引用已通过或至少完成规范化的首图。
- 不同任务可以并行，但风格分配必须先以事务方式占用批次配额。
- 429、网络中断和模型超时应采用有上限的退避重试，不得改变已固定的任务配置。

## 13. 可观测性指标

至少记录：

- 首次图文匹配通过率；
- 每页平均生成次数和修复次数；
- OCR 标题完全一致率；
- 关键数字完全一致率；
- 风格族和变体使用分布；
- 单一风格在批次中的最高占比；
- 近似重复率；
- `STALE` 图片数量；
- 人工覆盖和人工驳回原因；
- 每条任务的文本、图片、视觉验收调用数量和耗时。

这些指标用于校准风格配额、重试阈值和提示词，不用于宣称图片已经满足所有版权或平台要求。

## 14. 分阶段实施

### Phase 1：文本溯源与版本绑定

- 在最终正文确定后独立生成 `visualBrief`。
- 增加来源段落、证据、允许显示文字和哈希。
- 图片绑定文本版本、页面序号和视觉计划哈希。
- 文本修改后将旧图片标记为 `STALE` 并阻止直接批准。

### Phase 2：风格与布局分层

- 将视觉知识库拆分为笔记级风格与页面级布局能力。
- 在运行提示词中真正使用 `layoutRules`。
- 根据完整正文生成内容视觉画像。
- 对每个页面类型建立至少两个经过校准的布局变体。

### Phase 3：批量风格调度

- 实现内容过滤、Top-K 稳定带权抽样。
- 增加批次配额、近期去重、风格使用账本。
- 在管理端显示风格分布和任务最终选择结果。

### Phase 4：OCR、视觉验收与修复闭环

- 复用现有 `runVision` 能力增加逐页语义验收。
- 接入 OCR 或等价文字识别能力。
- 将修复分为图生图修复和重新生成。
- 增加最多两次的自动修复上限和失败证据。

### Phase 5：混合中文排版（已完成）

- 图片模型生成无文字视觉素材，并保留程序文字安全区。
- Sharp/SVG 使用固定简体中文字体完成版式并添加“AI生成”标识。
- 后续页使用去文字风格参考，避免把首图文字复制进模型底图。
- 对最终合成文件继续执行 OCR 和视觉验收。

## 15. 验收标准

### 15.1 图文匹配

- 每张图片都绑定当前文本版本和唯一页面计划。
- 每个事实、步骤、数字和专有名词都可以追溯到正文证据。
- 图片新增正文外事实、数字或建议时必须自动失败。
- 人工修改正文后旧图片立即变为 `STALE`。

### 15.2 风格与排版

- 同一篇笔记共享一个风格族和视觉媒介。
- 每页布局与 `kind` 和信息职责匹配。
- `layoutRules` 实际进入生成提示词或程序排版参数。
- 同一批次单个风格族占比默认不超过 15%，除非候选不足并留下原因。
- 相邻三个任务不使用相同风格族。

### 15.3 简体中文

- 所有主要可见文字来自 `allowedVisibleText`。
- 标题、关键数字、步骤名称必须逐字一致。
- 自动验收不得把低置信度 OCR 当作通过。
- 繁体、乱码或不可辨认文字命中主要信息区时阻断。

### 15.4 批量可靠性

- 各阶段可恢复且不会重复消费已通过的模型调用。
- 每页自动修复次数有明确上限。
- 风格选择使用稳定种子，可解释、可复现。
- 任务能够展示生成、验收和修复的完整证据链。

## 16. 备选方案与取舍

### 16.1 只继续强化图片提示词

- 优点：改动小、上线快。
- 缺点：没有生成后证据，无法保证模型真正遵守图文匹配和中文要求。
- 结论：只能作为辅助措施，不能作为完整方案。

### 16.2 每个任务直接选择最高分风格

- 优点：简单、结果容易复现。
- 缺点：批量同质化严重，高分风格会被反复使用。
- 结论：由 Top-K 稳定抽样和批次配额替代。

### 16.3 每张图片随机一个风格

- 优点：表面多样性高。
- 缺点：同一篇笔记视觉割裂，品牌感和阅读体验差。
- 结论：拒绝。多样性应发生在笔记之间，而不是同套页面之间。

### 16.4 全模型整图生成

- 优点：视觉自由度高，真实场景和插画能力强。
- 缺点：中文和精确排版不稳定，修正文案通常需要重新生图。
- 结论：作为当前兼容路径保留，但必须增加白名单、OCR、视觉验收和修复上限。

### 16.5 模型素材＋程序排版

- 优点：中文准确、布局稳定、修改成本低，适合大批量。
- 缺点：需要维护字体、设计令牌和布局组件，也会改变当前全模型交付边界。
- 结论：作为中文准确率不达标时的推荐升级路径。

## 17. 建议的最终原则

1. 先确定文本，再规划图片；图片不能与正文同步猜测。
2. 图文匹配必须可追溯、可验收，不能只依赖提示词承诺。
3. 同一篇笔记风格统一，不同笔记受控多样。
4. 风格由内容决定，布局由页面职责决定。
5. 简体中文要求是必要条件，但白名单、OCR 和确定性排版才是可靠保障。
6. 自动修复必须有上限，失败必须保留证据并进入人工。
7. 大批量系统首先要可恢复、可复现、可限流，其次才是增加更多随机变体。
