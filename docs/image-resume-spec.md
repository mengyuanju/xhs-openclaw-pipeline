# 生图断点恢复

## 目标与操作

失败后保留已完成工作，从未完成的步骤继续。分布式工作台和任务详情提供“从失败步骤继续”；任务详情中的未提交文案修改不会影响此次恢复。重新提交审核或选择“使用最新配置重新生成”仍创建全新生成流程。

| 失败位置 | 恢复行为 |
| --- | --- |
| 视觉规划未完成 | 继续视觉规划 |
| 某页生图失败 | 仅生成未完成页；跳过已完成页面 |
| 模型图片已返回，本地处理失败 | 用保存的原始 PNG 重试尺寸处理与保存 |
| 图片已保存，对齐/OCR 请求失败 | 重试该页验收，保留已生成图片 |
| 对齐已返回不通过 | 继续该页剩余修复次数，不重新请求同一次验收 |
| 整套质量评估失败 | 仅重试整套评估，保留逐页结果 |
| 本地 QC 或结果保存失败 | 复用模型评估，重新执行无模型成本的本地检查 |
| 上传失败 | 复用成功上传回执，按文件哈希补传剩余图片 |
| 完成状态回报失败 | 复用已生成、验收和上传结果，再提交完成状态 |

已完成是指结果已保存到检查点。模型侧已完成但响应未收到、或文件尚未成功落盘的工作无法从本地恢复。文件被改动或损坏时，仅受影响页面失效，随后重新进行整套评估。这里的“继续”是失败后的显式操作，不是无限自动重试。

## 中心与执行器契约

`POST /v1/tasks/:id/retry` 保持 `{ "useLatestConfig": false }` 请求结构。图片任务使用原快照重试时，中心在新的执行快照中增加：

```json
{
  "imageRecovery": {
    "nodeId": "original-image-worker",
    "runIds": ["newest-previous-execution-uuid", "older-execution-uuid"]
  }
}
```

每次重试仍创建新执行 ID，旧执行 ID 的迟到更新仍返回 `STALE_EXECUTION`。原节点持有本地图片，因此领取 SQL 限定恢复任务只能由该节点领取。节点离线时任务等待；不得由其他节点静默重新生成。`useLatestConfig: true` 清除恢复关系，按原有逻辑读取最新配置。

`GET /health` 新增 `capabilities.imageResume: true`。Web 请求恢复前检查该能力，旧中心只显示升级提示，不提交重试。中心和执行器必须同步升级：旧执行器不理解新快照，不能与新版中心混用。新增数据均写入已有 JSON 字段，不需要改表。

## 检查点与完整性

执行机保存目录为 `data/executor-work/<整数任务ID>/standalone-image-generations/<执行UUID>/`。

- `source.json`、`visual-plan.json`、`image-prompts.json`：已审核内容、完成的规划和实际逐页提示词。
- `.raw-XX-attempt-N.png` 及对应 `.checkpoint.json`：模型原始返回与来源；只有处理完成且最终检查点落盘后才清理原始图。
- `XX-kind.png` 及对应 `.checkpoint.json`：文件 SHA-256、真实 provider/model、生成次数、验收结果、页面是否完成。
- `quality-assessment.json`：整套模型评分及参与评估的页面哈希；页面发生变化即失效。
- `uploads.json`：文件哈希和中心素材回执；可跨多次失败恢复复用。
- `progress.json`、`qc.json`、`result.json`：进度、机械检查和运行结果。

恢复前校验源文案、规划结构、文件名、UUID、PNG 格式/尺寸和内容哈希。旧版没有图片检查点的 PNG 仍可被识别，但需要再次验收，来源标为 `recovered-existing-image`。没有旧规划时才重新规划。

新执行在 PREPARING 阶段先复制所有已完成图片和继承的规划、提示词、质量评估，复制完整后才开始后续工作。准备阶段中断时，执行器回溯到有完整记录的祖先；后续多次失败不会丢掉早期成功页面。上传记录按执行历史合并，以匹配当前内容哈希的回执为准。

中心接受完整交付后才清理任务工作目录；清理失败不把已完成任务改为失败。失败目录必须保留。没有可用源运行时恢复报错，不自动生成一套新图。

## 验证

`tests/standalone-image-generation.test.mjs` 覆盖规划复用、生成失败、逐页跳过、验收失败、整套质检失败、多次恢复、文件篡改、本地保存失败和旧执行终止；`tests/executor-image-resume.test.mjs` 覆盖上传恢复、完成回报重试、缺失检查点、旧执行终止、准备阶段中断回溯；`server/tests/image-resume.test.mjs` 覆盖快照继承、全新生成与领取节点归属。

测试使用假模型与临时文件，不消耗真实模型额度。正式生效前需更新远端中心及本机进程；实际带登录状态的页面和真实模型流程需在对应部署环境验证。
