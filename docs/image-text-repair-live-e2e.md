# 标准字体文字修正：真实端到端验证

本文记录开发环境中“标准字体排字 + 清理旧字背景”的真实系统验证。它与使用假模型的自动化测试分开：这里的错字定位、局部检查和整图检查确实调用模型，消耗额度。参考图和最终文字由程序使用标准字体绘制，不能因 `generationAttempts=0` 或 `billedImageGeneration=false` 就认为整个请求免费。

## 范围与运行前提

手工脚本为 [`scripts/image-text-repair-live-e2e.mjs`](../scripts/image-text-repair-live-e2e.mjs)，不包含在 `npm test` 中，也不自动启动服务、迁移数据库或调度后续测试。只有获得真实模型调用授权后，才使用显式参数 `--real-models` 运行。

脚本限定开发数据库 `xhs_control`、开发中心 `http://127.0.0.1:4311` 和开发网页 `http://127.0.0.1:3002`，并检查开发与生产存储分离、中心支持 `imageEditExecutorVersion >= 15`。生产数据库、生产页面与原始失败记录不参与写操作。

运行前及每次领取前，脚本检查没有其他图片请求排队或执行、没有其他 `IMAGE_QUEUED` / `IMAGE_RUNNING` 任务、没有其他活跃图片执行，也没有竞争中的版本 15 图片执行机。测试执行机使用独立节点和并发池，只通过真实 `claimImage` HTTP 接口领取工作；收到结果后再次核对私有工作区、请求和执行归属。版本 14 执行机不能领取新的标准字体文字修正。

`claimImage` 没有按编辑请求 ID 过滤的参数，因此领取前检查与 HTTP 领取之间仍有竞争窗口。运行期间须保持其他图片队列不新增；发现不归属本脚本的领取结果会停止，不执行该任务。这不是并发隔离压力测试。

## 手工运行

先按项目既有开发启动流程启动中心和网页，再执行首例：

```powershell
node scripts/image-text-repair-live-e2e.mjs --real-models --source-tasks=1760
```

全套默认依次读取源任务 1760、1768、1764：

```powershell
node scripts/image-text-repair-live-e2e.mjs --real-models
```

单独检查底部“匍匐”选区，并明确给私有副本的句段框增加 8 像素留白：

```powershell
node scripts/image-text-repair-live-e2e.mjs --real-models --source-tasks=1764 --paragraph-padding=8
```

`--source-tasks` 只接受上述三个明确范围内的任务，不接受任意任务 ID。模型执行默认每例最多 18 分钟，可通过 `--timeout-ms` 在 1～30 分钟范围内指定；浏览器和 HTTP 等待也有超时。任一例失败后停止，不自动付费重试，不把失败状态改成通过，也不走“仍采用此结果”绕过自动验收。

`--paragraph-padding` 默认 0，只接受 0～16 的安全整数。它将本次私有副本中的句段框向四边扩展，并截断到 1086×1448 图片边界，不修改原请求的框或源文件。报告同时保留 `sourceRepairs` 原配置、`requestedRepairs` 扩展后的目标配置、`repairs` 实际界面提交配置，以及留白像素数和说明。使用 8 时，1764 的句段由 `{x:108,y:1232,width:701,height:68}` 扩为 `{x:100,y:1224,width:717,height:84}`；实际替换仍限于定位出的字形区域。

## 真实链路与证据

1. 从原失败请求读取实际源资产、SHA-256 和 `config.textRepairs`，核对 PNG、尺寸、哈希及修正范围。源请求和源文件保持只读，运行后再次核对源记录指纹和源文件哈希。
2. 新建随机私有测试账号；通过真实浏览器登录、上传实际 PNG，在新工作区填写正确文字和词句，通过鼠标框选原句段，勾选模型费用确认并提交。
3. 注册独立版本 15 执行机，经真实 HTTP 领取并调用 `executeImageEditClaim`。`withModelCallTracing` 将真实模型调用记录写回中心；上下文、资产、参考和位置检查点以及结果上传均经过 HTTP。
4. 核对自动状态到达 `PREVIEW_READY`，参考与局部结果均为 `STANDARD_FONT`，字体哈希匹配，同字多处共用同一参考；没有参考生图或参考视觉模型调用。
5. 通过真实界面的正常“采用此版本”流程到达 `ACCEPTED`，检查当前工作区确实采用结果资产，再通过浏览器下载并核对文件哈希、尺寸和实际修改区域之外的解码像素变化数为 0。

模型追踪中的 `VISION` 与 `IMAGE_EDIT` 按实际操作分别记录。只有复杂背景清理可以调用 `IMAGE_EDIT`，且请求模式必须是 `ERASE_BACKGROUND`；最终合成后不调用图片模型重画文字。固定字体为 Noto Sans SC，当前已通过报告中的字体 SHA-256 为 `a3041811a78c361b1de50f953c805e0244951c21c5bd412f7232ef0d899af0da`。

报告位于本地 `reports/text-repair-live-e2e/`。每个新整数任务目录保存 `before.png`、`after.png`、`download.png`、`screenshot.png` 和 `result.json`；执行中断时可能只有已经完成的阶段产物。失败先保留原界面截图及可见错误，再按需另存重新打开工作区后的 `reopened-screenshot.png`。根报告保存各例状态、队列守卫、归属、真实调用摘要和清理结果；不保存明文密码、令牌或数据库连接串。报告和图片是本机验证产物，不能假设新检出的仓库已经包含它们。

## 发现的问题与已实施修复

- **开发库升级回执与已有结构不一致。** 启动检查发现 `0119_image_text_repair.sql` 的表结构已存在，但迁移回执未登记。核对其 JSONB 列、默认值及有效约束与原迁移一致后，仅补登记规范回执，没有重新执行结构变更。开发中心随后正常启动；记录见本地 [迁移回执修复](../reports/text-repair-live-e2e/migration-receipt-repair.json)。
- **底部选区被裁剪。** 1764 的句段位于原图 `y=1232`。仅按完整预览图的边界计算鼠标坐标，会把拖拽落到滚动窗之外或操作栏区域。脚本现仅滚动预览最近的可滚动祖先，将目标中心置于可见窗，重读图像边界，检查起终点位于裁剪区域和视口内且没有遮挡；拖后再读取界面实际选框坐标。没有通过修改 React 状态或绕过界面建立选区。无模型、无数据库的假浏览器检查已覆盖底部、顶部、仅预览滚动及遮挡停止。
- **失败截图丢失原现场。** 原脚本先重新打开工作区，导致提交失败时的界面状态被覆盖。现在先保存原失败界面和错误提示，重新打开后的截图单独命名。
- **定位提示混入整图设计规则，完整错词未明确纳入。** 当前定位协议已与整图设计规则隔离，并明确处理由完整汉字组成的错误词组，不能只寻找缺笔或不可识别字符。任务 1899 已到达前景完整性检查，但被后续保护拦截，不能因此认为整个修正通过。
- **置信度不足继续保守拦截。** 当前定位门槛为 0.85，局部与最终视觉校验门槛为 0.9；后续提示词修复没有继续降低这些门槛。1888 的 0.83 被拒绝是安全失败证据，不是修正成功证据。
- **原句段框遗漏旧字边缘。** 1764 的原框从 `y=1232` 开始，诊断发现旧字在 `y=1231` 已有明显抗锯齿边缘。区域外像素保护禁止越过框补涂，1899 因“前景像素无法分成可靠的完整文字”停止。当前诊断可读取选区外的邻近像素检查笔画完整性，但写入不能越过本次选区；发现切笔画时明确返回“框选区域切到原字笔画，请扩大句段选区”。脚本通过显式给私有副本增加留白解决本例，同时保存原框和实际框；原数据库配置、源哈希和置信度门槛保持。1901 在扩大后的选区内完成真实修正。

首次根目录全量检查使用默认并发时出现过一次 Windows 原生进程异常终止。后续 416 个压力作业未复现，限制并发后的完整根测试通过。当前未完成根因归属，不能据单次事件认定是文字修正逻辑或模型造成，也不能据后续通过宣称已经修复该原生异常；故障日志与复现结论独立保留。

1900 是另一次运行器意外退出：报告确认模型调用为 0，约 2 分钟执行心跳失效后私有请求安全进入 `FAILED`。该次日志没有新增 Windows 故障事件，不能确认与此前原生异常属于同一原因。恢复操作仅禁用本次临时账号 87、退役其独立执行机并保留私有任务，记录在中断报告的 `cleanup.recoveredAfterProcessExit` 中。1901 的监督重跑退出码 0，不构成进程异常已经根治的证据。

## 覆盖边界

当前真实通过项覆盖 `/image-editor` 独立图片工作区、真实来源图片、标准字体排字、平整背景清理、1 例有限区域的模型擦背景、多处同字参考复用、真实模型视觉检查、HTTP 执行链路及正常采用和下载。它不是生产环境验证，也不能代替业务任务批准文案和授权流程的真实验证。

1901 是 `MODEL_ERASE` 的 1 例真实通过样本：程序因纹理或阴影判定不宜直接清理，模型仅擦除旧字背景，程序随后合成“匍匐”，成品通过视觉和像素保护检查。这个有限样本不能概括复杂纹理、相邻文字或图案边缘的普遍质量；假模型测试也不能代替这些场景的真实验收。字体观感、罕见字覆盖、其他操作系统和并发队列竞争未在这组真实案例中穷尽，最终采用仍须检查成品。
