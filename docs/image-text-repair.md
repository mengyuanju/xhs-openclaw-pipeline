# 图片错字修正

任务图片编辑和独立图片编辑都提供“修正错字”入口。用户先输入正确的字或短词，并框选包含错误位置的一句话或小段文字。建议保留邻字，便于匹配字体、字号、颜色和基线；框选区域只提供定位上下文。

## 使用流程

1. 输入正确文字，例如“滩”。可补充目标词句，例如“看当天的天气和海滩开放信息”，帮助区分同段重复文字。
2. 在当前原图上框选包含错字的句段。同一张图有多个错误时添加多个修正项；同字的不同位置也分别添加。
3. 提交后，系统按正确文字生成字形参考图，自动检查参考图，再定位并替换。参考生成与参考校验只使用独立字形协议，不混入整张海报的配色、禁白底或 3:4 规则；定位、替换和最终检查仍沿用本次冻结的图片编辑规则。参考图生成后立即展示，不要求用户在中间额外确认。
4. 查看每种文字的参考图、每处原图与结果对比，以及完整结果。校验通过后沿用现有“采用”流程；校验失败但已生成结果时，也显示失败图片和原因，用户可以选择重试或“仍采用此结果”。手动采用需要明确确认并填写原因。
5. 参考字形有问题时，明确点击重新生成参考并重做关联位置；系统保留上一张参考图和具体校验原因，重试时将它们传给图片编辑模型，针对缺笔、粘连或错误部件修正。已通过但用户要求重新生成的参考也会附上重新核对，不会伪造上次检查失败。某处失败可重试，已成功的参考和局部结果复用。界面优先显示具体校验原因，运行中显示当前进度。

每张图最多 16 个修正项，每项正确文字为 1～8 个字符。多个位置使用相同正确文字时共用一张参考。不同文字分别显示参考卡片。任务图片的修正文字和补充词句须与当页已批准文案一致；独立上传图片以用户指定的修正为准。

## 执行与保护

新增操作类型 `AI_TEXT_REPAIR`，使用现有图片模型队列、费用确认、租约、审计、失败状态、预览和采用机制。它与“局部修改”独立，因为局部修改协议要求保留现有文字。

执行期间固定源图片、修正项和提示词版本。生成参考、定位实际字形、替换候选和视觉核对的输出均视为不可信数据。定位必须唯一、坐标为合法整数、实际字形矩形完全位于用户框选区域内；含混定位或相互冲突的字形区域无法通过。

图片模型接收段落上下文和已生成的参考字图。程序从生成候选中提取实际字形小区域，并将其回贴同一张原图。字形区域之外的解码像素逐像素检查不变，执行机和中心都执行检查。整图不能被模型候选直接覆盖。视觉校验失败的已生成片段也保留在失败预览中；宽高比例不符的候选会标记为未通过，只供用户检查和手动决定。失败片段不能作为重试时的已通过结果复用。

手动采用失败预览保留自动校验失败状态和原因，审计记录注明人工决定。没有生成修正图片时仍可查看参考图和失败原因，但不会把原图伪装成修正结果。预览文件格式、尺寸、哈希、资产归属与源图版本仍须有效，采用不会触发新的模型调用。

参考图和成功局部补丁作为本次修改的受限资产保存，执行进度随修改状态返回。失败不会丢弃成功项，也不会自动反复生成消耗模型额度。每次明确执行仍只生成或修正一次每种参考；失败参考作为修正输入前须核对源图、正确文字、PNG 格式和文件哈希。明确重试复用已通过的参考与成功补丁；重新生成某种参考时只使其关联位置失效。迟到的执行结果、失效租约、越界补丁和旧源图版本不能覆盖当前正式图片。

仍被修改记录绑定的参考图和补丁会保留，便于查看历史和重试。明确重新生成参考时，旧参考保持绑定直到新参考检查点存储完成，以免修正输入被提前清理；新参考替换或失败补丁替换后，失去绑定的旧素材进入持久清理队列；明确删除独立图片记录时也清理其生成素材。清理前再次核对素材类型、删除标记、任务、路径和文件哈希，源图与交付图不参与此类清理。

## 部署与验证

中心数据库需按现有升级流程应用本次新增迁移，中心及图片执行机需更新。新操作只会分配给声明 `imageEditExecutorVersion >= 14` 的执行机，旧执行机继续处理其支持的操作。

自动化测试使用假图片模型、假视觉模型和隔离数据库，不消耗模型额度。覆盖重复字参考复用、多处错误、错误参考、含混定位、越界及重叠位置、失败后重试、受限资产和区域外像素保护。真实模型生成的字形仍需在界面检查，视觉模型也可能误判。

本次人工采用改动验证：根目录全量测试 1803 项通过、62 项默认跳过，新增缓存重试场景后错字渲染与服务用例合计 32 项通过；两个编辑入口的四项实际浏览器测试通过，类型检查通过。自动模型全部使用假实现，未消耗模型额度。

服务端全量测试 965 项通过、79 项默认跳过、2 项失败：下载续租时序用例单独重跑通过，文案重试用例的测试数据缺少图片规划，单独重跑仍失败。这两个用例及其实现未被本次改动修改。相关图片编辑回归 76 项通过、1 项数据库用例默认跳过。

数据库生命周期用例已加入 `server/tests/image-editing-postgres.test.mjs`。本机 Windows 应用控制阻止启动临时 PostgreSQL 18 的 `initdb.exe`，因此完整隔离数据库生命周期尚未实际验证。2026-10-09 已按用户要求对开发库应用 `0119_image_text_repair.sql`，复查无待迁移项；依用户要求未备份，生产数据库未修改。部署时仍需更新中心、网页和图片执行机；其他数据库需按现有流程应用迁移。
