# 图片错字修正

任务图片编辑和独立图片编辑都提供“修正错字”入口。用户先输入正确的字或短词，并框选包含错误位置的一句话或小段文字。建议保留邻字，便于匹配字体、字号、颜色和基线；框选区域只提供定位上下文。

## 使用流程

1. 输入正确文字，例如“滩”。可补充目标词句，例如“看当天的天气和海滩开放信息”，帮助区分同段重复文字。
2. 在当前原图上框选包含错字的句段。同一张图有多个错误时添加多个修正项；同字的不同位置也分别添加。
3. 提交后，系统用标准字体直接绘制字形参考图，并检查字体是否包含全部目标字。参考图不调用图片生成或视觉模型；图片模型不负责画字。参考准备后立即展示，随后由视觉模型在框选句段中定位实际错字，不要求用户在中间额外确认。
4. 查看每种文字的参考图、每处原图与结果对比，以及完整结果。校验通过后沿用现有“采用”流程；校验失败但已生成结果时，也显示失败图片和原因，用户可以选择重试或“仍采用此结果”。手动采用需要明确确认并填写原因。
5. 需要重做参考时，明确点击“重新排字并重做关联位置”；系统重新用标准字体排字，使对应的修正位置重新处理。某处失败可明确重试，本次已通过的标准字体参考和局部结果可复用。界面优先显示具体校验原因，运行中显示当前进度；不会自动付费重试。

每张图最多 16 个修正项，每项正确文字为 1～8 个字符。多个位置使用相同正确文字时共用一张参考。不同文字分别显示参考卡片。任务图片的修正文字和补充词句须与当页已批准文案一致；独立上传图片以用户指定的修正为准。

字体排字本身不消耗模型额度。错字定位和成品视觉校验仍调用模型；复杂背景还会调用独立的擦字模型，因此提交和重试保留费用确认。平整背景由程序清理，最终文字始终由程序使用标准字体合成。生成参考和最终排字不会要求图片模型重画汉字。

新参考的 `validation.method` 为 `STANDARD_FONT`，字体信息保存在 `validation.textRendering`，包括渲染版本、字体文件哈希、字体名称、文字和字重。界面仅据明确来源标记展示“标准字体排字”；没有该标记的历史参考保留历史说明，不会把旧模型图标成标准字体结果。

## 执行与保护

新增操作类型 `AI_TEXT_REPAIR`，使用现有图片模型队列、费用确认、租约、审计、失败状态、预览和采用机制。它与“局部修改”独立，因为局部修改协议要求保留现有文字。

执行期间固定源图片、修正项和提示词版本，并记录标准字体来源。外部输入、定位结果、背景清理结果和视觉核对输出均视为不可信数据。定位必须唯一、坐标为合法整数、实际字形矩形完全位于用户框选区域内；含混定位或相互冲突的字形区域无法通过。

笔画完整性诊断可以读取选区外的邻近像素，确认原框是否切到旧字；读取范围不扩大写入权限。发现边界切笔画时明确提示“框选区域切到原字笔画，请扩大句段选区”，由用户重新框选后再处理。实际写入仍须完全位于本次选区内，不会自动越界补涂。

视觉模型结合段落上下文和标准字体参考定位实际目标，并确定与邻字协调的样式。程序清理平整背景；复杂背景使用独立擦字模型，只清除旧字并恢复背景。程序再把标准字体排好的正确文字合成到已清理的区域，最终合成后不调用图片模型重绘。背景处理方式记录为 `PROGRAMMATIC_FLAT` 或 `MODEL_ERASE`。

程序仅回贴实际字形矩形。字形区域之外的解码像素逐像素检查不变，执行机和中心都执行检查；模型返回的完整画面不能直接覆盖原图。成品视觉检查针对真实回贴结果，核对字形、样式、邻字、背景和整图一致性。未通过检查的片段会保留在失败预览中供人工查看；失败片段不能作为重试时的已通过结果复用。

手动采用失败预览保留自动校验失败状态和原因，审计记录注明人工决定。没有生成修正图片时仍可查看参考图和失败原因，但不会把原图伪装成修正结果。预览文件格式、尺寸、哈希、资产归属与源图版本仍须有效，采用不会触发新的模型调用。

参考图和成功局部补丁作为本次修改的受限资产保存，执行进度随修改状态返回。失败不会丢弃成功项，也不会自动反复调用模型消耗额度。标准字体参考复用前须核对来源标记、源图、正确文字、PNG 格式和文件哈希；局部补丁必须匹配同一版参考与源图。明确重试复用已通过的标准字体参考与成功补丁；重新排字时只使其关联位置失效。迟到的执行结果、失效租约、越界补丁和旧源图版本不能覆盖当前正式图片。

仍被修改记录绑定的参考图和补丁会保留，便于查看历史和重试。明确重新排字时，旧参考保持绑定直到新参考检查点存储完成；新参考替换或失败补丁替换后，失去绑定的旧素材进入持久清理队列；明确删除独立图片记录时也清理其生成素材。清理前再次核对素材类型、删除标记、任务、路径和文件哈希，源图与交付图不参与此类清理。

## 部署与验证

中心数据库需按现有升级流程应用文字修正迁移，中心及图片执行机需更新。标准字体文字修正只会分配给声明 `imageEditExecutorVersion >= 15` 的执行机，防止旧版模型画字执行机混入；旧执行机继续处理其支持的其他操作。

自动化测试使用假背景模型、假视觉模型和隔离数据库，不消耗模型额度。标准字体参考应检查字库覆盖与来源记录，浏览器检查来源标签、费用保护和失败原因展示。定位、背景清理及视觉检查仍可能出错，采用前仍需在界面检查成品。

当前标准字体流程的真实输入、手工命令、逐例结论、失败修复和覆盖边界见 [真实端到端验证](image-text-repair-live-e2e.md)。两处“鳖”、“鼬”和私有副本选区增加 8 像素留白后的“匍匐”均已分别完成真实自动验收、正常采用与下载校验；“匍匐”还覆盖 1 例有限区域的模型擦背景。历史失败和进程中断保持原记录，不能改称通过。真实验证会消耗定位、视觉及必要的背景模型额度；参考与文字排字不调用生图模型，不代表整个请求免费。最终自动化统计和真实案例以该文档及对应报告为准。

服务端全量测试 965 项通过、79 项默认跳过、2 项失败：下载续租时序用例单独重跑通过，文案重试用例的测试数据缺少图片规划，单独重跑仍失败。这两个用例及其实现未被本次改动修改。相关图片编辑回归 76 项通过、1 项数据库用例默认跳过。
