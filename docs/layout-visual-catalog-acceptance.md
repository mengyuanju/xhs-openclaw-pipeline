# 布局模板库实施与验收

日期：2026-09-07。

已按两张参考图实现 10 类、27 个布局模板，入口为管理员「生产配置 → 布局模板库」。本地 SQLite 与远端中心工作台共用目录契约。

## 已实现

- 表格展示分类、中文类型、编码、排版含义、适合内容；支持搜索、分类筛选、启停和编辑新版本。
- JSON 文件或文本整批导入；可直接粘贴模型 templates 数组。省略启用状态时默认未启用。重复导入保留现有启停状态与来源，设计冲突需增加版本，历史版本不可删除。
- 「用模型生成模板候选」每次接收 1～10 个候选，校验后自动入库为未启用。优先使用已发布 LAYOUT_CATALOG_SYSTEM；没有发布版本时明确使用内置规则并标注来源。
- 默认在原有一次视觉规划调用内按页面用途和实际条目数量选择模板，补充选择原因、主体与文字区域、统一配色及风格；保留人工指定。随机模式和关闭规划模式均可跳过规划模型。
- 生图提示词使用该次模板定义及风格。正文、逐页 headline/subtitle/bullets 继续锁定；规划不得新增标签、移动内容或改写文字。
- 完整规划在生图前保存；本地保存到任务状态和运行记录，中心保存到 image_runs.result.visualPlan。任务详情展示所选模板版本、原因、区域和整套风格。
- 中心续跑携带冻结规划及目录；本地检查点缺失、损坏或与中心不一致时复用中心规划。新执行提交不同规划会被拒绝。中心完成图片任务前必须已有校验规划；纯本地图片重处理沿用源运行规划，无需重新规划。
- 新模板按版本 2 解释左右语义；旧模板和旧快照保留原行为。新目录任务的首次领取和领取回执重放均校验执行机版本。

## 存储与接口

- 目录：本地 production_settings.settings_json.layoutCatalog；中心 global_settings 的 production.value.layoutCatalog。
- 本地新增 tasks.visual_plan_state_json，可在图片尚未完成时读取规划，并冻结任务目录。中心无需新增表或列。
- 管理员：GET/POST `/api/layout-catalog`，POST `/api/layout-catalog/generate`；远端对应 `/v1/layout-catalog` 和 `/v1/layout-catalog/generate`。
- 执行机：PUT `/v1/executions/:executionId/visual-plan`。校验当前执行归属、文案契约、冻结目录和规划一致性。写入幂等，JSONB 字段顺序不同不会造成误冲突。
- 目录保存使用 revision 并发检查和数据库事务；过期编辑返回 409，其他生产配置保持最新值。

## 验证

- 主工程在最新远程分支基础上的隔离提交目录中全量 967/967 通过（`node --test --test-concurrency=2 tests/*.test.mjs`），包含中心权威规划比较与本地规划偏离用例。
- 中心服务全量 159/159 通过；涉及 PostgreSQL 的新增验证使用 fake repository，未连接生产数据库。
- TypeScript 检查、Next 生产构建、`npm run smoke` 通过。Smoke 为本地模拟产物。
- Edge 实际浏览器验证：27 个初始模板、启停保存后刷新仍保留、编辑增加新版本并停用旧版、无效 JSON 不写入、有效 JSON 导入成功。1440、1024、768、320 像素宽度均验证通过，布局区不溢出。
- 浏览器测试使用临时数据库和隔离服务；应用原有 favicon 缺失由测试夹具返回 204，业务页面与目录请求无控制台错误。
- 复核修正了恢复规划丢失、完成门禁缺失、目录替换删除历史、候选数量与字段契约未重验，以及恢复规划未与中心比较的问题。
- 测试未调用真实文本或图片模型，不消耗模型额度；真实出图美观度、OCR 和布局遵循度尚未作为本轮验收结论。

## 生效方式

更新并重启应用、中心服务和执行机后使用。首次初始化会在缺少目录字段的数据库记录中导入 27 个参考模板；已存在的目录、历史规划和旧提示词发布版本不会被覆盖。模型候选生成按钮会调用配置的模型，但模板初始化、普通 JSON 导入和确定性规划不需要模型调用。

本轮完成工作区修改与隔离验证，没有部署远端服务、发布生产提示词或增加生产调度。
