# 本机生成链路优化（2026-09-05）

## 范围与结果

只修改本机模型适配器、规划/检索流程、进度预估；不改变中心服务、分布式调度、通信或并发许可上限，不启动生产任务。

此前样本中三张图共 947 秒，视觉规划三次合计约 271 秒；文案检索约 68 秒。它们是旧 OpenClaw 链路的单次观测，不代表当前 Codex 链路，也不是本次优化后的速度承诺。此次验收使用 fake 模型响应与本机隔离网页，无真实模型成本测试。

## 图片输出接收

- OpenClaw 每次调用写入隔离目录，依据真实 `outputs[].path` 接收文件，不强制模型遵守最终业务文件名；没有结构化元数据时只接受隔离目录中的精确目标。
- 校验真实路径、调用时间、文件类型、大小和完整 PNG 解码，拒绝越界、陈旧、符号链接或损坏文件。业务文件使用独占写入，不覆盖已有产物。
- Codex 相同原生事件 ID 与路径去重；不同候选仍视为歧义，不擅自选图。接收、落盘或多候选歧义失败不会在适配器内重调生图；候选保留在错误的 `recoveryDirectory` 中，供人工判断。原有“无产物”的有限传输重试保留。
- 编辑参考图只保留原件；成功、失败以及部分附件转换失败均清理临时副本。恢复目录不能用于公开静态托管。

## 视觉规划

`generateVisualPlan` 被队列流程与单独生图流程共用。首次规划、局部修复及动态分页规划显式传递生产配置中的 `copyGenerationThinking`。

Codex `runText({ outputSchema })` 将业务 Schema 交给 CLI 的 `--output-schema`，不再只约束包裹内层 JSON 的 `rawText`。返回接口依旧是 `{ rawText, ... }`，不传 Schema 的文案/审核调用保持兼容。OpenClaw 沿用提示词与本地校验，不宣称它支持未核实的 CLI 结构化参数。依据：[Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)、[Structured Outputs 支持的 Schema](https://developers.openai.com/api/docs/guides/structured-outputs)。

`mustShow` 新生成内容区分 `画面：…` 与 `文字：…`；文字必须逐字存在于 `allowedVisibleText`。旧规划继续接受原字符串格式并保留原校验，事实证据、数字和文字白名单没有放宽。

校验逐页进行：有效页固定，缺页、重复页号和无效页单独请求修复。修复响应只能替换请求中的失败页，不能覆盖已通过页面或根元数据。仍最多调用三次；耗尽后只对未通过部分使用明确标记的确定性规划。鉴权等非瞬态服务错误直接失败，不伪装成成功。

每次失败的原始响应在运行私有目录中保存为 `visual-plan-attempt-N.json`（脱敏、最多 50,000 字符），附思考等级和逐页错误。保留数据用于当前运行的局部修复及后续诊断；这不是跨进程自动恢复未完成规划的缓存。日志落盘失败不能触发额外模型调用。

## 检索

DeepSeek 在已有摘要、至少两个不同规范化主机名的公开来源，且每个计入来源都有标题和非空片段时提前结束。缺摘要、标题、片段、只有一个站点或不安全 URL 时仍补搜。这里“不同站点”按主机名计算，不意味着两个独立机构已互相证实。

显式 `requireAuthoritative: true` 要求命中现有权威域名评分规则，普通站点不能早停或通过最终 fallback。修正 `gov.example.org` 等伪权威域名误判；域名评分仍只是来源排序/门槛启发式，不是事实真伪认证。默认 Codex 及其他检索适配器行为保持兼容。

复用已有任务检查点，不新增跨任务长期搜索缓存。已有回归覆盖相同配置恢复不重搜、配置变化后重新检索。调用次数可查看 `research.attempts`，检索墙钟耗时沿用文案 `timing.researchMs`。

## 排队与进度

OpenClaw 文本串行锁、Codex 总并发/单图片许可均未放宽；调用结果新增 `execution.queueWaitMs`，Codex 调用跟踪同时记录该值。它用于区分本机排队和模型服务等待，不代表已经提升吞吐量。

进度按准备、规划、出图与逐页验收、整套质检、保存五阶段记录。首图先建立风格，后续预算按实际图片并发数计算；不再把阶段百分比当作耗时百分比。阶段结束后重算剩余预算，阶段超预算时（包括没有新心跳的网页轮询期间）显示无法准确估算，不显示假倒计时。

历史保存在输出根目录的 `image-stage-timing.sqlite`，按提供方、模型、思考等级、页数和并发数隔离，读取同配置最近最多 30 条；至少三条有效样本才使用各阶段中位数。库全局最多保留 300 条，仅记录完成且非恢复的全程运行，过滤不足 30 秒或超过 24 小时的样本。SQLite 失败仅使历史不可用，不使交付失败或重新调用模型。

默认不同输出根目录不共享历史；调用方可通过 `runtime.timingHistoryPath` 指向已有父目录内的同一本机数据库。此次没有为分布式执行入口修改存储配置。冷启动预算是估算，只有真实运行积累历史后才会校准；旧 `mode-and-page-count` 记录继续可读。
