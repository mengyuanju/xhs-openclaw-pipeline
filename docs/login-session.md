# 网页登录会话

主应用使用签名的 HttpOnly Cookie。中心验证账号密码后，Web 服务签发会话；续期时再次向中心核对同一账号的身份、角色和凭据版本。

| 规则 | 当前值 |
| --- | --- |
| 每次签发的最长有效期 | 8 小时 |
| 开始续期的剩余时间 | 不超过 1 小时 |
| 活跃窗口 | 前台页面最近 15 分钟有真实点击、键盘输入或滚动交互 |
| 周期检查 | 5 分钟；发生交互或页面恢复可见时也检查 |
| 最长连续登录 | 从首次密码登录起 7 天 |

这些参数统一定义在 `src/admin/session-policy.mjs`。每次续期继承首次登录时间，最终到期时间为“当前时间加 8 小时”和“首次登录时间加 7 天”两者中较早的一个，Cookie 的 Max-Age 与这个实际到期时间一致。

这是分段续签：持续操作可以跨过最初的 8 小时截止时间；停止交互后不会再续期，最后签发的会话自然到期。有效期从最后一次签发计算，不保证最后一次操作后仍完整保留 8 小时。业务轮询、鼠标悬停、隐藏页面和合成事件不算活跃。页面恢复可见只触发检查，不自行刷新活跃时间。

## 请求与失效

- `GET /api/auth/session` 返回会话标识和到期时间等元数据，不写 Cookie、不续期，也不返回令牌或凭据版本。
- `POST /api/auth/renew` 必须是同源请求，携带当前 Cookie 和预期 `expectedSessionId`。旧会话仍有效、身份未变化且进入续期窗口时才签发新令牌。
- 中心的 `GET /v1/profile` 接收原会话的账号 ID、账号名、角色和凭据版本。账号被删除、禁用、改密、重置密码或修改角色/审核权限后，旧会话返回 401，不能借续期恢复权限。
- 原会话在中心校验期间到期，也不会重新签发。到期或真实账号失效需要重新登录，并保留原页面地址。
- 临时网络、数据库或中心连接故障返回 503，保留原会话，稍后重试。会话与预期账号不一致返回 409，不清理另一个账号的 Cookie。

登录、续期、退出与改密的浏览器请求共用跨标签锁。支持 Web Locks 时使用原生锁；局域网 HTTP 等不支持 Web Locks 的环境使用 IndexedDB 原子租约。不同标签同步到期时间、退出与账号切换事件，续期前仍读取实际 Cookie 的元数据，不把浏览器广播当作鉴权依据。

改密成功后的 Cookie 清理也在同一把锁内完成，并携带改密前的会话标识，避免清理另一标签新登录的账号。旧请求迟到的 401 会核对浏览器会话代次，不会结束已经替换的新会话。

退出请求的取消信号同时覆盖共享锁等待。浏览器首次打开 IndexedDB 就因权限策略被永久拒绝、且不支持 Web Locks 时，自动续期关闭，手动登录和退出仍通过本标签队列执行；暂时事务故障或锁争用不会绕过共享锁。

旧账号会话可在有效期内迁移，最长登录时间从原签发时间计算。缺少账号 ID 的历史管理员令牌仍可按原规则校验，但需要重新登录才能续期。会话没有中心存储或逐设备撤销表，旧令牌副本在原到期前仍有效；退出清除当前浏览器 Cookie，改密和账号状态变化继续由中心阻止使用旧凭据。

## 验证

认证与活动测试使用可控时钟和假中心，覆盖 8 小时及 7 天边界、旧格式迁移、挂机、隐藏页面、重试和账号变化。真实 Next 路由测试位于 `tests/integration/session-renewal-next.test.mjs`，运行时使用隔离构建和本地假中心；浏览器测试通过 `RUN_SESSION_RENEWAL_BROWSER=1` 启用，不调用模型或真实业务数据库。
