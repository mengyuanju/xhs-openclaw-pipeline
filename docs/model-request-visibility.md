# 管理员实际模型请求明细

管理员进入作业中心的任务详情，展开“模型调用链路”，再展开某一次调用，即可查看：

- 本次实际使用的业务提示词版本、模板 hash 与渲染后 hash。
- 业务规则原文、程序追加指令、任务数据、实际发送的参考案例与附件信息。
- 输出 JSON schema、字段约束和工具协议，全部只读。
- 完整脱敏请求、完整提示词原文及模型返回内容。

普通用户、审核员没有此入口。Web 代理和中心服务继续限制链路列表、详情为 ADMIN；非管理员任务响应不返回含内部提示词的执行快照。此功能不新增读取权限，也不允许编辑历史请求。业务提示词仍在提示词版本管理中修改。

## 记录的含义

新记录复用现有 `model_call_traces.request` 文本字段，保存 `format=xhs-model-request`、`schemaVersion=1` 的记录对象。`payload` 是实际调用输入；`provenance` 是来源说明，不会作为额外提示词发送给模型。

HTTP 调用保存实际发送的请求体。Codex 保存实际 runner 收到的参数数组、stdin、developer instructions 和输出 schema；OpenClaw 保存参数数组及发送前读取的 message-file 内容。客户端内部未返回的子请求、服务商内部指令、凭据和图片二进制不属于这个文本记录。图片附件显示当次调用的文件位置，临时文件后续可能已清理。

来源信息在模板渲染时关联，并在每次调用时按实际文本筛选。运行中的版本变更不会替换已冻结的版本；被引用为任务数据的旧规则不冒充本次业务规则。缺少或无法唯一确定版本时显示未关联，不拿当前配置补写历史。页面中的分层由实际请求标签解析，未标注的内容仍可在原文查看。

历史记录保持可读。旧格式、缺失记录和截断记录会明确提示完整性未确认。新执行机升级后产生的新记录才能包含补齐的调用参数；历史缺失信息无法追溯补造。

## 验证

- Fake runner / fake HTTP 断言记录与实际发送的 stdin、参数、schema、请求体一致，不消耗模型额度。
- 来源版本冻结、请求间隔离、引用旧规则、脱敏、截断、旧格式和畸形来源字段均有测试。
- 使用隔离 Next.js 与中心服务、测试账号，在真实 Edge 浏览器核对管理员桌面与 390px 窄屏；无横向溢出，管理员明细无控制台错误。
- 普通用户、审核员在浏览器中无链路入口，直接访问 Web 列表/详情返回 403；中心角色权限测试继续通过。
- 类型检查和生产构建通过。中心服务全量 140/140 通过。本功能及调用适配器、快照、权限的专项回归通过。
