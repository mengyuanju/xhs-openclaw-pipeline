# 自然文案结构规格

## 目标

让正文根据选题类型选择叙事结构，减少机械的“第一步、第二步”模板，同时不通过虚构第一人称经历制造所谓真人感。

## 当前边界

- 本规格对应 Phase 15，当时只调整正文生成规则；后续 Phase 16 已按 `docs/web-research-source-spec.md` 新增正文生成前的联网研究。
- 具体事实现在可由任务输入中的 `referenceUrls`/`referenceText` 或本次固定 `webResearch` 快照支撑。
- 保持现有标题、正文长度、JSON、来源、安全和图片计划契约不变。

## 写作规则

- 教程或操作流程：只有执行顺序确实不能打乱时，才使用编号步骤。
- 推荐、盘点、对比测评：优先按使用场景、选择标准、差异、取舍和适用边界组织。
- 科普、知识、答疑：优先按结论、原因、常见误区、判断边界和行动建议组织。
- 经验、攻略：优先呈现具体场景、关键选择、容易卡住的地方和复盘结论；没有输入证据时不得冒充亲历者。
- 开头直接进入具体困境或反常识判断；段落间使用自然转折；结尾可以落在判断标准、例外情况或一个下一步动作，不强制检查清单。

## 验收标准

- 运行提示词明确要求“按内容类型选择结构”。
- 运行提示词明确禁止默认使用“第一步、第二步、第三步”。
- 基础生成契约与管理员固定提示词都包含相同的结构选择原则。
- 现有提示词与正文契约测试全部通过。

## 命令

- 定向测试：`node --test tests/default-prompts.test.mjs tests/post-contract.test.mjs`
- 全量测试：`npm test`
- 类型检查：`npm run typecheck`
- 构建：`npm run build`

## 发布行为

仓库中的提示词修改不会覆盖已经入队任务的固定快照。已有数据库需要在后台“提示词”页面只发布新的文本系统提示词，或运行 `npm run prompts:install-rules` 发布仓库中所有发生变化的规则提示词；新版本只影响发布后创建的任务。
