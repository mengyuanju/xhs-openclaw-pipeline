# 个人统计与我的作业

入口分为 `/workbench/personal-statistics`（个人数据统计）与 `/workbench/personal`（我的作业）。登录和旧任务链接仍进入我的作业。个人数据统计面板分为“个人数据”和“作业数据”两个页签；交付记录在弹窗中按需加载，支持状态筛选及分页。

## 简化后的面板

- 页面标题下方显示“今日概览”，三张卡片依次为“今日可交付”“今日文案质检通过”“今日图片质检通过”。概览始终使用北京时间今天，独立于下方日期筛选、个人／作业数据页签和作业关系筛选。桌面三列并排，手机纵向排列。
- “今日可交付”按本人当前负责的交付池待交付作业去重，包含待打包和已打包待交付，单位为条。历史入池但当前仍待交付的作业也计入，排除已确认交付、退出交付池、失效版本和测试作业，并沿用交付池的质检门禁。管理员同样只统计本人负责的作业；允许访问交付池的账号可点击卡片进入相同的本人 CURRENT/PENDING 筛选。
- 今日文案／图片质检通过按本人提交内容今天获得的有效通过判定计次，包含返修和同一作业多次通过；图片按整套图片的一次判定计数。卡片可打开固定为该日的匿名通过明细。此处与下方“质检操作”中本人执行的通过操作使用不同归属口径。
- “个人数据”默认统计北京时间今天，时间按钮为今天、昨天、近 7 天、自定义日期（1–366 天）。自定义日期复用 `DatePicker` 组件，选择开始和结束日期后点击“应用筛选”；打开日期编辑时保留当前已应用范围。日期区间首尾均包含，详细统计及匿名明细使用同一日期区间，按实际操作账号归属。文案标注主行显示全部提交、首次文案审核，下一行显示独立的首次提交、返修提交和文案废弃数；图片标注／负责人初审显示全部提交、首次提交和返修提交。全部提交包含首次、返修和普通再次提交，不含废弃，按有效事件逐次计数；因此全部提交可能大于首次与返修之和。同一作业多次操作可重复计数，改派不转移已发生的贡献。自动、免检、代操作及无账号的提交不计入。全部提交卡片的匿名明细区分首次、返修和再次提交。
- 首次文案审核 = 首次提交 + 废弃数。主卡小字显示计算公式，两项数量分别展示在下方独立卡片；首次文案审核明细合并本人首次提交和文案审核／返修中的废弃记录，文案废弃数可单独查看明细。废弃数按实际废弃时间读取 `human_quality_assessments` 的文案废弃（含 `task_reassignment_assessment_records` 中保留的改派历史）和 `copy_return_dispositions` 的返修废弃，不计入下方独立质检的废弃数。账号重新注册不会继承旧账号的审核废弃记录。
- 文案和图片分别显示一次通过率、整体通过率。两者均按所选日期内产生的有效质检结论计算，尚未质检的提交不进入分母；一次通过为首次通过判定／全部通过或退回判定，整体通过包含返修后通过。无判定显示“—”，少于 20 个判定项次提示样本较少。
- “质检操作”按文案、图片分别显示“实际逐条操作量”和“处理覆盖量（含批量）”。实际量为本人逐条通过、退回、废弃或升级的质检项并集，排除批量影响、自动放行、直通及无效自审／模拟记录。覆盖量合并本人逐条处理、本人操作触发的批量退回和真实自动放行成员；同一质检项在所选日期区间内只计一次，新版本复检另计。负责人图片初审计入上方图片提交。
- 首轮、复检拆分人工逐条操作；通过、退回、逐条废弃、升级单独展示。批量退回影响和自动放行覆盖可与逐条项重叠，辅助数量不能相加。所有卡片支持匿名分页明细，覆盖项合并显示“逐条／批量退回／自动放行”的来源。
- 系统联动覆盖归触发该操作的人员，纯系统动作不归个人；同一批次多人参与时分别保留实际记录，个人覆盖量不能直接相加作为系统总量。图片按一个作业版本的整套图片计一条，不按单张图片计数。
- 缺少个人放行归属或成员范围的历史记录不推断补造。覆盖卡显示“已确认 N”，明细标记历史覆盖不完整；已确认 0 不代表没有发生处理。准确的逐条操作明细不受覆盖记录缺失影响。
- “作业数据”显示当前状态，默认“我负责的”，可切换“我创建的”和“与我相关”。待我处理、文案初审、图片初审、返修、异常、生产中、我的内容等待质检、可交付及返修细分均按当前作业 ID 去重。状态可能重叠，不应求和；卡片跳转到带同样筛选的我的作业列表。此页不受今日日期限制。
- 页签分别按需读取；个人数据按日期区间缓存，作业数据按作业关系缓存。首次读取显示加载状态；后台同步保留当前卡片及按钮文案，不插入或移除加载提示。相同业务数据不替换报表，仅更新最近同步时间。接口失败时提示错误，并保留同一日期区间内标明可能过时的上次数据；切换到未成功读取的日期区间不展示其他区间的数字。

## 统计口径

- 当前作业状态默认“我负责的”，可切换“我创建的”和“与我相关”。与个人数据的日期筛选独立。
- “我需处理”是本人负责且需要人工操作的作业集合，按作业 ID 去重；纯机器运行、排队和等待质检不纳入。
- 待返修来源为文案质检、图片质检或最终审核退回，分为仅文案、仅图片、两者返修；三类互斥。普通修改、机器失败与生图重试耗尽不会自动计为质检返修。
- 返修进度分为待修改、后台处理中、待确认结果。提交审核后进入复检，再次退回后重新进入待返修。
- 等待时间从当前阶段进入时间计算；状态或负责人变化才重置。心跳、草稿和同阶段版本修改不重置。规划或图片结果待确认时，从结果就绪时间计算。
- 历史完成按 `copy_approval_events`、`image_approval_events` 中实际操作账号归属；改派不转移历史贡献。文案和图片分别去重，完成作业合并去重；返修次数按阶段提交事件计数。
- 图片退回记录在旧抽检项变成 `SUPERSEDED` 后仍保留。旧版历史查询中的首轮随机抽检率仍只使用首轮随机抽中的实际审核结论，排除未抽中、免检、待审核及强制复检。
- “可交付”只计算当前版本 READY 且尚未打包的作业。交付的计数单位为批次，同时展示期内去重作业数。“待确认交付”只计算已成功下载且未确认的本人可见批次。

## 接口与同步

`GET /v1/personal-workspace/statistics` 和 `GET /v1/personal-workspace/tasks` 使用已认证账号，不接受查询参数指定其他统计账号。统计接口传 `section=overview` 获取固定为北京时间今天的概览，返回 `range`、`delivery.ready/href` 和 `passed.COPY/IMAGE`，忽略详细统计日期及关系筛选；概览在单次只读事务内复用交付池账本及本人标注质检事实。传 `section=personal&period=today|7d|30d|custom` 获取所选时间内的提交、废弃、标注通过率及质检次数，`custom` 同时传 `from/to`，昨天按钮也使用固定日期的 `custom` 查询；传 `section=jobs&personalScope=ASSIGNED|CREATED|ALL` 获取当前作业状态。逐次明细使用 `GET /v1/personal-workspace/qa-activities?period=custom&from=YYYY-MM-DD&to=YYYY-MM-DD&stage=COPY|IMAGE&metric=...` 固定为卡片已经使用的日期，避免跨日或切换筛选后读取其他日期，仅返回匿名编号、阶段、结果、时间及分页信息。新增文案指标 `copyFirstReview` 和 `annotationDiscarded`，分别查询首次审核合并记录及废弃记录；原 `submitFirst` 仍只查询首次提交。旧调用不传 `section` 时保留原报表格式。作业分类共用 `src/personal-workspace.mjs` 逻辑，服务端在单次数据库快照内读取。

新增匿名明细指标 `qaActual`、`qaCoverage`、`qaBatchReturned`、`qaBatchReleased`、`qaDiscarded`、`qaEscalated`。主卡和明细共用 `src/personal-qa-statistics.mjs`；覆盖事实读取 `quality_review_coverage_events`，有证据的旧文案连带退回可从质量账本恢复。明细只增加来源类别 `coverageSources` 和历史完整性标记，不返回质检项／作业／批次／账号的真实标识或内容。

作业查询支持 `mode=CURRENT|COMPLETED|RETURNS|REWORK|QUALITY`，以及 `personalScope`、`category`、`query`、`page`、`pageSize`、`sort`、`priorityMode`、`reworkType`、`reworkProgress`、`reworkSource`、`longWaiting`、`repeated`。历史使用 `period/from/to/stage`；所有日期按北京时间、首日含末日含查询，数据库终点为次日零时。统计卡片携带相同筛选条件跳转。

当前列表和作业数据页签不读取历史报表或交付批次，只补齐当前页有详情权限的作业。失去当前详情权限的历史作业只保留历史展示，不提供操作入口或当前返修内容。旧报表中历史与交付查询失败时分别提示不可用，当前待办仍能显示；整体刷新失败保留并标明旧数据。单次事实/事件读取上限为 50,000，超过上限明确报错，避免静默截断计数。

审核和其他写操作、后台任务完成后发送不含业务数据的刷新信号，300 ms 防抖后更新今日概览及当前可见页签；同一查询在途时不取消重发，连续信号最多合并为一次立即补查。概览独立每 30 秒轮询，个人数据可见时每 60 秒轮询，作业数据每 30 秒轮询；隐藏页面不发起请求，期间的变更标记会保留。重新可见或返回已缓存页签时，仅在数据失效、跨北京时间日期或距离上次成功读取至少 15 秒时更新；手动刷新同时更新概览和当前页签。概览读取失败时保留同日旧数据并标记可能过时，跨日则隐藏旧日数量等待新数据。规划详情可从中心恢复最新任务，关闭窗口和重新进入后仍可查看结果。

## 升级与验证

本次日期筛选、首次文案审核及今日概览复用现有事实表，不新增数据库迁移；中心和 Web 需要同步升级以提供 `section=overview`。

先应用 `0071_personal_workspace.sql`，再同步升级中心与 Web。旧作业的等待起点由最后可得队列时间初始化；更早已被覆盖的等待时间无法恢复。缺少账号身份/时间或已被删除的历史事件不补造。

双质检指标依赖 `0095_quality_review_coverage.sql`；先应用迁移，再同步启动新版中心与 Web。该迁移只新增持久覆盖事实表和读取索引，不修改抽检比例、退回阈值、领取方式或任务状态。覆盖写入与质检操作在同一事务内完成，重复请求不会重复计数；批量动作使用统一事务时间，保留后续改派及内容删除前的身份事实。

自动化验证不调用模型：

- `npm test`、`npm --prefix server test`、`npm run typecheck`
- `RUN_PERSONAL_WORKSPACE_POSTGRES=1 node --test server/tests/personal-workspace-postgres.test.mjs server/tests/personal-today-postgres.test.mjs server/tests/personal-discard-postgres.test.mjs server/tests/personal-overview-postgres.test.mjs`：临时 PostgreSQL 18，验证分类、分页、改派、后台结果、日期边界、废弃和交付池概览口径。
- `RUN_PERSONAL_WORKSPACE_BROWSER=1 node --test tests/personal-workspace-browser.test.mjs`：真实组件和假接口，验证跳转、筛选恢复、只读历史、刷新、交付弹窗及移动端。

PowerShell 中可通过 `$env:RUN_PERSONAL_WORKSPACE_BROWSER='1'` 设置测试开关。测试不会修改现有数据库或发布环境。
