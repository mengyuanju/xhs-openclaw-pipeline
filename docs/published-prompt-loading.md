# 已发布提示词的加载与内置规则

## 加载行为

已发布模板的读取不再依赖 `prompt_runtime` 是否存在。

- 有已发布模板：使用本次执行快照中的内容、版本 ID 和 hash。
- 未配置 `prompt_runtime`：尚未发布的阶段使用内置模板，保留原有审核、OCR 和机械校验行为。
- 已配置 `prompt_runtime`：继续执行完整策略；缺少被调用阶段的已发布模板时明确报错。
- 模板已存在但内容为空或 hash 不匹配：明确报错，不退回内置规则。
- 草稿不参与执行。已冻结任务沿用原快照中的版本，不读取后来发布的新版本。
- 历史本地任务明确保存的 `null` 快照继续保持原有行为；新任务会冻结已发布模板，即使尚未配置运行策略。

文案初稿、长度/格式修复、配图重规划、视觉规划、图片生成和图片编辑均在对应执行上下文内读取规则。正文修复会继承本次已发布的文案与配图规则；这不改变“仅替换 body”的字段合并方式，也不新增语义顺序校验。

`promptExecutionSnapshot()` 返回完整的模板执行快照，供产物保存、恢复和调用记录使用。`promptRuntimeSnapshot()` 保留原来的完整策略开关语义；只有已发布模板但没有策略配置时，它仍返回 `null`。运行快照中的 `settings: null` 明确表示该兼容状态，序列化和恢复时必须保留。

实际调用记录按请求中包含的内容标记来源：已发布模板记录真实版本 ID、版本号和 hash；未发布阶段标记 `BUNDLED_DEFAULT`，版本 ID 为空。

## 程序约束

JSON 字段、枚举、正文和图片文字长度、页数、图片尺寸、逐页文字锁定、数字依据检查、OCR 比较方式、评分聚合算法和重试上限由程序控制。其中部分参数可通过各自设置调整；仅修改业务提示词不能覆盖程序校验。

## 验证

`tests/published-prompt-loading.test.mjs` 使用假模型验证无策略配置时的模板加载、初稿和修复继承、配图重规划、图片提示词组合、实际请求版本记录，以及本地任务冻结和快照恢复。测试不消耗模型额度。

任务 #219 的离线回放使用已保存的原模型返回。修复后，初稿和正文长度修复请求都包含完整图文规划 v3（版本 ID 15）；原最终正文不变。该回放验证的是加载路径，不代表对观点顺序或文案事实的重新验收。

此修复不发布候选提示词、不修改中心运行配置、不回写已有任务。运行中的服务或执行机需要加载新代码后生效；此前生成的产物不会自动重做。
