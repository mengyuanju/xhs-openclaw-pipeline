# 共享交付与汇总保存

管理员和作业人员共用每个文案/图片版本的交付状态。交付池默认展示全部状态；个人工作台的“我的交付记录”使用同一组件和查询，能看到管理员处理的本人条目。

## 操作

1. 进入交付池，在“当前交付内容”中选择待打包内容，点击“打包并下载”。系统冻结版本，状态变为“已打包，待交付”。
2. 已打包内容使用“下载所选冻结内容”，可跨批次选择。确认“生成并下载”后，页面显示排队/生成进度，完成后自动发起各卷下载；浏览器拦截时可使用进度提示中的下载链接。请保持本页面打开；离开后仍可在“文件记录”下载，不会再次自动下载历史记录。生成失败会显示原因，按原范围重试后会继续自动下载。系统读取冻结快照中的文案、文件名和本地图片引用，临时生成 ZIP；作业人员只能获取授权的条目。
3. 实际发送给接收方后，选择内容并“确认所选已交付”。确认前需要该操作人对所选内容的下载记录。支持部分确认；批次进度按当前账号可见成员显示。
4. 管理员筛选“已交付”并设置日期、人员、词包或甲方批次，点击“汇总保存已交付内容”。可勾选跨页内容，或选择符合筛选的全部结果。
5. 预检显示准确条数、原批次数和体积，确认后后台生成文件。从“文件记录”查看进度、失败原因、下载或按原范围重试。再次下载或汇总不改变原交付记录。

每条交付显示打包人和时间、确认人和时间。下载记录表示服务器已传输文件，不自动表示实际交付。确认记录不可覆盖，重复提交不重复计数。

日期可按可交付时间、打包时间、交付确认时间或最近状态变更查询，支持今天、昨天、近 7/30 天和自定义范围。全部日期采用北京时间，结束日期包含当天。没有确认时间的内容不会匹配“交付确认时间”的日期条件；查询某日未交付内容应使用“可交付时间”。

页面可见时每 15 秒刷新，重新聚焦立即刷新，同一浏览器其他页面操作也会触发刷新；失败后退避至 60 秒并保留错误提示。筛选写入 URL，分页和完整结果查询由服务端执行。

原有预览发布和原始批次 Excel/ZIP 功能保留在交付池下方的“图文预览、预览发布与原始批次工具”中。这个工具区的批次入口仍按原始创建者授权，不用作新的共享交付统计入口。

## 数据与权限

- 迁移 `0073_shared_delivery.sql` 新增条目确认、负责人快照、条目下载、汇总任务、冻结成员和汇总下载事件。
- 保留原始批次的版本唯一约束、冻结文件快照及本地原图引用。ZIP 不再长期保存；汇总任务是独立记录，不会被当作新的交付批次。
- 旧的已确认批次按成员回填确认；仅生成或下载的批次不迁为已交付。旧整批确认和下载通过数据库触发器映射到条目记录，逐条确认完成整批后同步旧批次状态。
- 历史负责人使用账号 ID 和可信分配时间恢复；不能确认的旧身份保持未知，不能归给同名新账号。
- 当前池按当前负责人授权，历史按负责人快照、当前负责人和本人操作记录授权；确认权限仍按当前负责人检查。管理员可以处理全体正式内容。
- 对外接口不提供数据库原始快照。作业人员汇总下载只能是 `DOWNLOAD`，管理员才可创建 `ARCHIVE`；管理员创建的文件任务不会因账号降为普通用户而继续开放下载。
- 个人统计按条目确认计算本人内容交付进度，并单列本人执行确认的作业数量；人员统计仍归属实际确认账号。

## 文件与任务

新建批次 ZIP 按“甲方批次/任务-N-资源包/文案与图片”组织，一次解压即可使用，不再包含每个任务的独立 ZIP。

冻结内容下载和汇总保存按 `.delivery-snapshots` 中的快照读取所选文件，沿用“甲方批次/任务-N-资源包/文案与图片”的原目录和文件名，不附加 manifest.json、清单.xlsx，也不添加文案版本和图片版本目录。快照保存文本原字节、文件顺序、原图路径及校验值，图片继续使用已有本地文件，不再额外保存一份图片压缩包。文案 TXT 首行“原始 Query”优先使用汇总条目中冻结的下发 Query；未记录或为空时使用该冻结条目的 Query。旧汇总记录缺少该字段时沿用源词条回退规则。首行之外的文案、图片及原有链接文件保持原字节。旧批次内嵌的任务 ZIP 在迁移时展开；同一任务多个历史版本的文件夹重名时追加 -2、-3 避免覆盖，不增加目录层级。快照或原图缺失、哈希错误、成员重复或缺少时明确失败，不用当前文案或图片版本替代。

历史下载按冻结成员重新生成 ZIP，解压后的文件保持冻结内容；每次生成的 ZIP 容器字节和哈希不作为与旧 ZIP 完全相同的保证。已有“文件记录”及交付状态继续保留，下载时不要求旧 ZIP 仍然存在，但旧批次必须先完成快照迁移。

手动勾选最多 200 条，筛选全量最多 2,000 条；每卷最多 200 条或 1 GiB，单次成员文件总量不超过 10 GiB。单任务大于 1 GiB 时预检拒绝。每个账号最多 2 个排队/运行任务，全局最多 20 个等待/运行任务，单个服务进程最多同时生成 2 个。

长期保留的是 `CONTROL_PLANE_STORAGE_ROOT/.delivery-snapshots/<批次UUID>.json`、被快照引用的本地图片，以及 PostgreSQL 中的任务、成员和图片保护引用。批次及汇总 ZIP 生成到 `.delivery-exports` 的独立临时目录，完成使用、断连、取消或超时后清理；再次下载重新生成，不共用其他下载请求的临时文件。汇总准备完成只保留分卷元信息，准备时生成的 ZIP 也会清理。历史引用图片受清理与永久删除保护。服务异常退出留下的临时目录由既有过期清理处理。

任务用租约运行，进程中断后过期任务转为失败，可以按原冻结范围重试；排队任务在服务启动或打开记录时继续处理。单个服务进程最多同时下载 4 个汇总文件，同一账号最多 2 个；每次汇总下载的生成和传输最多 10 分钟。这是用户主动触发的文件生成，没有新增内容发布或生产定时调度。

主要接口：

- `GET /v1/delivery-items`：`CURRENT / HISTORY`、状态、日期、人员、来源及归档筛选。
- `POST /v1/delivery-items/confirm`：确认所选条目，事务检查权限、门禁和当前版本，重复提交幂等。
- `POST /v1/delivery-archives/preview`：校验冻结来源并创建 10 分钟有效的选择快照。
- `POST /v1/delivery-archives`：凭快照和 `requestId` 建立持久任务；网络重试使用原 `requestId`。
- `GET /v1/delivery-archives`、`GET /v1/delivery-archives/:id`：历史和进度。
- `POST /v1/delivery-archives/:id/retry`：失败后按原成员重试。
- `GET /v1/delivery-archives/:id/download/:part`：按快照临时生成并下载指定分卷；HEAD 只返回授权后的元信息，不生成 ZIP，也不写下载事件。

## 升级与验证

首次启用共享交付需要 `0073_shared_delivery.sql`，本次快照存储还需要 `0120_delivery_snapshot_assets.sql`。上线前同时备份 PostgreSQL 与完整图片存储目录。旧批次使用 `scripts/migrate-delivery-snapshots.mjs` 校验原 ZIP、匹配本地原图并建立快照及图片保护引用；默认只检查，`--apply` 才写入，`--apply --remove-archives` 才在校验通过后移除旧包。清理历史汇总 ZIP 前还要求汇总任务为空闲状态。应在维护窗口完成迁移并确认所有批次成功后再切换服务，不应手工先删旧包。

数据库备份不包含快照 JSON 或图片文件；恢复历史交付必须配套恢复 `.delivery-snapshots` 与全部被引用原图。迁移前保留旧 `.delivery-batches`、`.delivery-archives` 备份以便回退；完成快照迁移后，ZIP 可重新生成，无需作为常规交付备份长期保存。中心和 Web 同步升级，健康能力 `sharedDeliveryVersion=1`；不回退到只认识整批确认或旧 ZIP 的服务。

```powershell
node scripts/migrate-delivery-snapshots.mjs --environment=development
node scripts/migrate-delivery-snapshots.mjs --environment=development --apply
```

生产环境需要明确使用 `--environment=production`。执行删除旧包前应确认迁移结果和备份，再额外指定 `--remove-archives`。

本次数据库验证使用独立临时 PostgreSQL 18，未运行生产迁移。测试不调用模型。

```powershell
$env:RUN_SHARED_DELIVERY_POSTGRES='1'
node --test server/tests/shared-delivery.test.mjs
$env:RUN_SHARED_DELIVERY_BROWSER='1'
node --test tests/shared-delivery-browser.test.mjs
npm run typecheck
npm run build
```
