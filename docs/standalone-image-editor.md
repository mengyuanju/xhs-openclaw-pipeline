# 独立图片编辑

入口 `/image-editor`，ADMIN 与 USER 可用。所有账号（包括 ADMIN）仅能查看和操作自己创建的工作区、参考图和结果；列表、详情、资产下载、提交和删除均在接口层校验创建人。与文案审核、质检和业务任务归属无关。

## 使用

上传 1–5 张 1086×1448 的 PNG/JPEG/WebP，每张原始文件最多 5 MiB，规范化后的 PNG 最多 10 MiB。复用现有图片解码、签名检查、去 EXIF 与 PNG 规范化。创建工作区的原图必须严格符合 1086×1448，禁用参考图的自动缩小，也不会自动裁剪或拉伸。默认限制集中在 `src/standalone-image-editor-config.mjs`，每个工作区冻结限制版本；未来调整尺寸必须同步坐标和处理器，当前不开放不受支持的尺寸设置。

产品替换参考图沿用任务编辑的上传规则：原始文件 ≤5 MiB、像素 ≤16M；去 EXIF 并规范化为 PNG 后，仅在超过 20 MiB 时自动等比例缩小至限制内，不裁剪或拉伸，已合限的参考图保持原尺寸。每次编辑最多 4 张参考图，合计 ≤40 MiB/32M 像素；每个工作区最多保留 20 种不同参考图、实际占用 ≤100 MiB。仍保存原始上传字节的 SHA-256 和最终规范化 PNG 的 SHA-256，参考图尺寸记录最终保存的 PNG 尺寸。编辑结果的 20 MiB 上限保持不变。

页面仅展示图片编辑列表，右上角“新增图片”打开上传弹窗。选择图片后自动上传，上传成功后在同一弹窗下方立即展开编辑组件，无需再次打开编辑弹窗。点击“保存并提交生图”直接入队并返回列表；仅上传未提交的记录不出现在生图列表中。

当前页面按文件上传二进制原图，最多同时传输两张，显示已上传张数。全部文件通过签名、尺寸与大小校验后，再一次性创建工作区；失败不会产生部分工作区。相同请求与图片凭据可重试，已成功提交但响应丢失时返回原工作区。旧中心继续使用原 base64 接口。临时原图有一小时有效期、每账号 20 张待提交上限和中心 2 GiB 暂存上限；提交或取消后删除暂存 PNG，过期清理只处理该目录的已知上传文件。

进入列表时不加载编辑器主体；上传成功或打开已有工作区后，才按需加载编辑组件。首次加载显示“正在加载图片编辑器…”。若组件加载失败，可点击“重新加载编辑器”，通过地址中的工作区编号重新打开已上传的图片。关闭弹窗、切换图片、处理中只读与提交锁定沿用原有行为。

上传后可添加人工生成标识（模型或程序）、替换产品、局部修改、取消、重试、对比、采用及恢复历史版本。新建程序标识默认实心徽章、自定义颜色 `#111827` 与白字，可选择描边或自动配色；系统色板、HEX 输入和支持浏览器中的屏幕取色可调整主题色。重新打开时恢复上次的标识文字、徽章样式和颜色，无字段的旧请求仍使用描边和自动配色。成功或失败预览均保留原有验收标记。下载按钮仅在本轮生图结束且存在结果时显示，统一放在保存按钮左侧；原始上传和待生图、生图中不显示下载按钮。重新打开时恢复上次的局部修改说明或产品替换参数，修改后保存会创建新请求，列表回到“待生图”。采用后可继续基于当前图片编辑。上传原图始终保留。

生图中的记录仅支持查看；参数输入、参考图上传、保存、恢复、采用、取消等修改操作均不可用。接口在编辑事务内持有与执行机领取相同的任务锁，再检查运行状态，避免打开旧弹窗绕过限制。多张图片保存使用同一个事务整体入队，任何一张校验失败都不会提交部分请求，执行机只能在整组提交后领取。

编辑器和后台通知共享轻量状态查询，仅传状态、版本和账号归属；初次打开、版本变化及明确操作后才读完整历史。隐藏页面降低轮询频率，不再每轮传提示词、配置、事件和验收结果。打开工作区时强制读取新状态，已开始的旧请求完成后会补读一次，避免排队快照覆盖“处理中”的只读状态。

列表支持单条删除和勾选本页后批量删除。生图中不可删除；批量删除先校验全部记录的归属和运行状态，再原子执行。删除后记录、图片与编辑接口均不可访问，排队请求取消并暂停领取；底层资产和历史以删除审计标记保留，不物理清理文件。删除重试不会重复写入删除记录，不需要新增数据库迁移。

## 隔离与复用

独立编辑组件使用自己的接口命名空间；后端通过独立服务和处理器适配已有编辑引擎，原任务入口不接入独立组件。程序队列和徽章渲染由两类入口共同复用。

为兼容现有任务编号、资产外键和执行租约协议，工作区使用 `task_kind=STANDALONE_IMAGE_EDIT` 的内部任务作为执行载体。`standalone_image_workspaces` 记录不可变的上传账号、上传幂等键、哈希及默认限制。空的页面元数据只供旧执行协议使用，标记 `USER_UPLOAD`；没有生成或审核业务文案，也不对用户展示为已批准文案。

普通任务列表、个人列表及统计、作业模式、任务计数和重复 Query 扫描排除该类型。原业务任务接口拒绝操作这种内部记录，数据库约束禁止它进入普通生图、文案审核、图片审核或交付状态。采用结果仅切换独立工作区中的当前图片。

独立图片编辑仅在自己的列表查看状态，不再出现在原“生图中”页面。列表统一展示“待生图 / 生图中 / 已完成”；已结束的失败、取消和拒绝记录在已完成阶段下保留明确的结果说明及失败原因，可打开记录重试。列表自动刷新，保留分页和结果下载入口，后台通知跳转此入口。

## 执行

独立编辑请求仍保存于 `image_edit_requests`。模型编辑共享 IMAGE 执行机、领取事务、负责人轮转、并发容量、租约续期和取消后的过期回传保护；执行机能力版本 **13** 才能领取独立模型编辑，旧执行机继续领取原任务，不能误领上传图。领取快照标记类型，独立模型编辑分派到对应处理器。

程序标识 `SVG_DISCLOSURE` 由中心独立队列领取，默认在独立 Node.js 子进程内以 **2 并发**执行、每张图使用 `sharp.concurrency(1)`，直接调用程序渲染，不初始化独立编辑适配器的模型客户端。创建、批量提交、草稿提交和重试在事务提交成功后立即唤醒；旧 `QUEUED` 程序请求自动接管，已远端 `RUNNING` 的请求继续原执行。程序通道不等待 IMAGE 模型容量，也不要求独立编辑执行机版本 13。

程序编辑历史显示“准备处理 / 程序处理中 / 预览待确认”。取消、版本检查、像素完整性校验和审计继续生效；租约过期进入 `FAILED`，由用户检查后人工重试。程序重试无需模型费用确认，不显示模型收费提醒。程序生成预览仍需明确采用，原始上传图继续保留。

描边文字和边框同色；实心底色和边框同色，文字按 WCAG 对比度自动选择黑色或白色。新建界面明确发送 `overlay.badgeVariant=solid-pill` 和 `overlay.badgeColor=#111827`，显式主题色优先于页面保存色。用户选择自动配色时不发送 `badgeColor`，依次取页面保存的 `aiDisclosureStyle.color`、视觉方案标识色、调色板末色和 `#68744A`；独立上传图片没有这些样式信息时使用回退色。历史请求及旧客户端省略字段的行为保持兼容。完整颜色规则、`overlay.badgeVariant`、`overlay.badgeColor` 与进程/容器配置见 [程序生成 AI 标识](programmatic-image-disclosure.md)。

模型编辑适配器根据原图与结果比较原有文字和未点名内容，不使用业务文案白名单。模型调用、冻结的管理员图片编辑提示词、模型标识/产品/局部操作和结果完整性校验仍由原引擎完成。假模型只在测试中注入。程序方式不读取图片编辑提示词，也不调用图片或视觉模型。

## 部署与验证

初次部署独立图片编辑时需要应用 `0082_standalone_image_editor` 和 `0083_standalone_image_editor_compatibility_repair`，并更新中心、网页和支持独立模型编辑的图片执行机。中心启动只检查迁移状态，使用现有数据库升级命令应用待执行迁移。

本次程序队列与实心徽章变更复用现有表，无新增数据库迁移。更新并重启中心服务和 Web 即可；默认程序子进程随中心启动，外置模式另更新并重启程序 worker。图片执行机无需为这次程序功能更新或重启。

若数据库已执行早期 `0082`（尚未包含工作区状态约束），迁移器仅接受已知的精确校验值，并通过 `0083` 补齐约束；已执行完整 `0082` 和全新数据库也兼容。保留原迁移校验记录，不修改任务、图片或工作区数据；未知校验值仍阻止启动。没有自动应用生产迁移、发布或增加生产定时任务。

验证：`npm run typecheck`、`npm test`、`npm --prefix server test`；隔离数据库端到端测试设置 `RUN_POSTGRES_E2E=1` 后执行 `node --test server/tests/standalone-image-editor.test.mjs`；浏览器测试设置 `RUN_IMAGE_EDIT_BROWSER=1` 后执行 `node --test tests/standalone-image-editor-browser.test.mjs`。测试不消耗模型额度。

开发页面真实验收可执行 `node scripts/image-editor-live-e2e.mjs`。脚本先核对开发与生产数据库、存储目录分离，再为 `http://127.0.0.1:3002/image-editor` 创建专用随机账号，只对本次工作区执行程序标识、下载、采用与删除；不会启动全局队列或调用模型。结束后软删除测试工作区并禁用测试账号，结果保存到 `reports/image-editor-live-e2e.json`。可选 `--with-production-proof` 需要预先保存优化前后的 `.next-image-editor-before` / `.next-image-editor-e2e` 正式构建，用于核对列表与打开编辑器时的 JavaScript 加载，以及加载失败后的恢复。

删除成功后会同步清理该工作区全部后台任务与提醒，跨标签页保留删除标记，避免旧轮询响应恢复通知。已删除编辑的状态查询只向创建人返回最小删除状态，不再当作生图失败；详情、图片和修改接口仍不可访问。旧版缓存中的不可用通知会在重新打开新版页面时复查并静默清理。
