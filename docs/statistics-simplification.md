# 标注与质检统计精简

状态：本地实现；业务数据库与生产部署未变更。

## 页面

- 管理员入口分为总数据、账号数据。总数据只保留文案标注、图片标注、文案质检、图片质检、新增可交付内容五个数量；一次通过率单独显示文案和图片。
- 账号数据按标注、质检切换，支持日期、姓名/账号、内容类型。总数据切换时清除账号和工作类型限制，避免把单人数据误认为团队数据。
- 首次返修通过率、抽检覆盖、操作记录和处理时长放到明细。累计通过率尚未提供：不能把不同时间或不同轮次的样本混算，也不能把旧版本曾通过视为当前有效通过。
- 个人统计采用相同的历史事实来源与轮次计算，质检记录继续使用匿名回执，保持盲评信息隔离。
- 用户可见角色统一为标注、质检、管理员；内部 USER/REVIEWER 权限标识不变。整条任务改派在界面要求填写原因，沿用既有改派日志。

## 口径

条数在期间内按任务和阶段去重；一组图片计一条。次数按实际提交/质检事件统计。返修提交不增加同期间同任务同阶段的条数。首次提交、返修处理可能重叠，个人接力或跨日处理的条数相加也不保证等于团队期间去重数量。

标注按提交日、质检和通过率按质检结论日，使用北京时间。一次通过率延续首次随机抽检口径；首次返修通过率仅计可追溯到真实首检退回的第一次复检。团队比例按样本加权，零样本显示空值，小于 20 个样本提示样本较少。通过率是内容提交人的质量指标，不是质检人员的准确率。

个人历史不再从返修版本/当前状态推造质检失败；没有有效结论的旧返修版本保留在当前返修流程中，但不增加已质检退回条数。批量牵连、快捷直放、自检、模拟、未知身份继续单列或排除。

## 自动轮次与改派提醒

迁移 `0076_quality_inspection_links.sql` 保存每个抽检项的阶段、任务、提交记录、原提交账号、父抽检项和创建时间。该记录不随任务或版本级联删除。插入触发器先安装，再回填现存来源；源记录已经删除且缺少父链的历史不编造。

统计沿各自阶段的父链计算质检轮次和有效退回次数；缺失父节点、跨任务父链、循环或过深链均标记轮次未知。机器重试和流程状态变化不增加质检失败次数。首次返修指标排除仅因批量牵连产生的复检。

当前建议改派仅针对仍处于人工处理阶段、同一当前标注在同一链上连续至少两次被有效退回的任务。最后一次提交必须在该次分配之后；改派后不把前任失败继承给新标注，任务通过后也不再提醒。该提示不受历史日期范围影响，不执行自动改派。任务依然采用整条任务一个标注负责人的分配方式。

## 升级与验证

中心与 Web 需一起更新；中心按现有数据库升级流程应用 `0075`（如尚未安装）和 `0076`。Web 要求统计口径版本 3，旧服务显示升级提示。应按既有流程先备份业务数据库；本次只在隔离临时 PostgreSQL 中验证迁移。

验证覆盖纯函数、管理员/个人接口、真实 PostgreSQL 中的回填和删除历史保留、接力归属、不同日期范围中的当前改派提醒、盲评回执、桌面/手机浏览器、导出快照、类型检查和构建。所有数据使用测试夹具，不调用模型。
