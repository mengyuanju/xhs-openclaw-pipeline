# 任务详情与审核弹窗

文案审核阶段在桌面端采用左右双栏：左侧为原始 Query、标题、正文、标签及可折叠的资料来源，右侧为图片文案规划。两栏独立滚动；不足 1024px 时切换显示文案或图片规划，编辑内容保存在同一份草稿中。图片审核与已完成详情保留文案、图集、规划的查看顺序。

- 移除任务概览，Query 原文在文案区只读展示，长内容可展开；没有文案时仍显示 Query 和必要的失败提示。
- 图片规划提供页码、类型和标题摘要，默认展示第一页，生成指令默认折叠。
- 交付格式、背景、格式转换和历史配置恢复仅管理员可见。普通用户和审核员的文案提交保留任务已有图片配置。
- 文案、全部图片规划和水印选择沿用现有审核接口一起提交；按钮明确说明审核通过后开始生图。
- 关闭或刷新前提示未提交修改；提交失败保留草稿。提交时校验所有页面，并展开、定位首个不合格字段。
- 生图重试耗尽返回文案审核时，保留失败提示及旧图片；旧图放在左栏，保持双栏布局。

## 隔离验证

```powershell
node node_modules/typescript/bin/tsc --noEmit --incremental false
node --test tests/creation-workbench-ui.test.mjs tests/model-call-trace-ui.test.mjs
node scripts/test-task-review.mjs
```

浏览器脚本复制实际组件及样式到 `.codex_artifacts/task-review/run-*`，使用独立 Next.js 输出目录、临时端口和浏览器上下文。测试工程不复制应用路由、凭据或数据库；所有控制面请求由浏览器中的内存假数据响应，其他来源的请求被拦截。不调用真实审核、生图或模型服务，不重启现有服务，也不运行工作目录中的生产构建。脚本结束时只停止自己创建的测试进程。

覆盖三种角色、跨页修改共同提交、原图片配置保留、关闭与刷新保护、失败保留草稿、折叠字段校验定位、无文案状态、重试耗尽及历史图片，以及 320 / 768 / 1024 / 1440px 布局。截图和测试服务日志保存在对应的隔离目录中。
