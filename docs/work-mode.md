# 作业模式

入口：侧边栏「作业模式」，页面路径 `/work-mode`。

页面按当前账号的权限展示文案作业、图片作业、文案质检、图片质检。左侧是待处理队列，右侧直接处理当前内容。无需选择业务状态；后台根据现有流程和账号身份生成队列。

## 待办范围

| 类型 | 纳入条件 | 完成后 |
| --- | --- | --- |
| 文案作业 | 分配给当前账号，待文案审核，已有文案，未暂停 | 审核提交或废弃成功后移出；仅保存评分或草稿继续保留 |
| 图片作业 | 分配给当前账号，待图片初审或图片返修，已有图集，未暂停 | 图片初审提交成功后移出；重新生图后退出人工待办 |
| 文案质检 | 当前账号有权处理的待检项，未暂停 | 通过或打回成功后移出 |
| 图片质检 | 当前账号有权处理的待检项，未暂停 | 通过或打回成功后移出；有未完成编辑时禁止通过 |

文案与图片作业始终以当前账号为负责人，包括管理员。质检范围沿用原有质检权限，管理员可处理全局质检项。盲评脱敏、自检限制、版本校验和返工规则继续由现有接口执行。返工后再次符合待办条件的数据会自动回到队列。

## 操作行为

- 桌面作业区自动填满顶部导航、标题和提示之外的可用高度，页面本身不再产生第二层滚动，提交按钮保持可见。窗口宽度不超过 760px 或高度不足 600px 时，编辑区随整页滚动，避免在小窗口内嵌套滚动；底部操作栏吸附在窗口下沿。
- 文案作业在宽屏同时展示文案与图片文案规划，两栏等宽并分别滚动；主内容区不足 640px 时切换为标签页。桌面窗口不超过 1280px 时待办栏缩窄至 195px，使包含应用导航的常见桌面宽度仍可展示双栏；收起待办侧栏后，内容区自动利用腾出的宽度。
- 图片作业只展示图片与图片操作，不展示正文文案或逐页规划。当前页、预览底色和修改图片集中在顶部；左侧主要展示大图，底部缩略图缩小为紧凑导航条，右侧保留评分/返工记录、格式设置与历史图片；窄屏改为上下排列。
- 点击大图可放大预览，支持切图、缩放和旋转；关闭预览后保留最后查看的图片页。作业标题及底部提交操作不随内容栏滚动。
- 文案作业和文案质检压缩标题、提示和卡片留白，优先展示正文与逐页规划；文案质检保持等宽双栏。图片质检将当前页、预览底色和问题标记集中在顶部，原始 Query 可展开查看全文；核验时大图占满内容区，开始打回后才显示右侧返工表单。评分与返工范围并排，问题页和原因采用紧凑布局，长表单仍可滚动以保证所有字段可达。
- 质检主内容区不足 640px 时通过“查看文案 / 规划与质检”或“查看图片 / 质检操作”切换；开始打回时直接进入操作栏。翻页、关闭预览、窄屏切换和提交失败均保留当前返工填写，盲评信息和版本校验沿用原有规则。
- 成功提交后立即移出，自动打开下一条；请求失败保留当前内容。
- 切换文案前先保存审核草稿；保存失败时留在当前条目。
- 暂跳过只移动当前加载队列中的位置，不改变任务状态。
- 切换质检内容前，如有未提交的返工说明，会提示确认放弃。
- 页面可见时每 30 秒刷新首批待办，不替换正在编辑的内容。加载了更多页时手动刷新，避免后台刷新缩减已加载列表。
- 搜索只筛选已经加载的待办，按钮明确标注「加载更多待办」。
- 「本次已提交」记录当前页面会话中的成功提交，刷新页面会重置；持久历史仍在原作业中心。
- 当前作业位置按账号保存在当前标签页的 sessionStorage，刷新后恢复作业类型和条目；目标已不在待办时提示并选择下一条。不同标签页分别保留自己的编辑位置。

## 后台任务

- 顶部同时显示后台处理中数量和未读提醒数。左侧对应作业显示规划或具体图片页的「排队中 / 处理中 / 待确认 / 失败」。生成完成仍需人工核对，不计入已提交。
- 作业模式内点击通知或提醒弹窗的「查看任务」，直接在当前编辑区定位对应作业。系统先按当前账号权限查询目标，再保存当前草稿并切换；保存失败或取消放弃修改时保留当前内容。任务不在首批待办时单独显示，不影响加载更多的分页位置。
- 已提交、暂停、转交或无权处理的任务不会强行打开；保留当前编辑内容并提示前往作业进度与历史查看。
- 提醒按处理中、待确认、需要处理分组，已处理记录默认折叠。支持全部标为已读；标为已读不会采用图片结果或载入规划，待确认结果仍保留。
- 同一账号、同一浏览器来源下通过 storage 事件同步任务、已读和已采用状态。支持 Web Locks 的浏览器对轮询加跨标签页锁，避免同一完成事件重复弹窗；不支持时仍同步状态并尽力去重。图片预览就绪后继续查询采用状态。
- 后台任务完成时刷新可见页面的首批待办，保留正在编辑的内容；加载多页时继续使用手动刷新。

## 接口与运行

新增只读接口 `GET /v1/work-mode/items?kind=COPY&limit=50&offset=0`。`kind` 可选 `COPY`、`IMAGE`、`COPY_QA`、`IMAGE_QA`；`limit` 为 1–100。

中心重新校验账号状态、凭据版本与权限，以稳定账号 ID 限定负责人，不接受客户端指定负责人。任务过滤在数据库分页和计数之前执行。质检通过多读取一条判断是否有下一页，不能确定总数时显示已加载数量加 `+`。

可选 `itemId` 用于精确定位及刷新恢复：文案/图片作业使用任务整数 ID，质检使用公开 UUID。查询仍同时应用待办状态、负责人/质检分配、暂停和盲评规则，不扩大可见范围。

本模块无需数据库迁移。运行中的部署需要同时更新网页端和中心服务，并按现有发布流程重新构建、重启；仅更新网页端无法读取新增接口。

## 验证

- 常规检查：`npm test`、`npm --prefix server test`、`npm run typecheck`、`npm run build`。
- 浏览器流程：PowerShell 下运行 `$env:RUN_WORK_MODE_BROWSER='1'; node --test tests/work-mode-browser.test.mjs`。默认使用本机 Edge，可用 `WORK_MODE_BROWSER_CHANNEL` 指定其他已安装的 Chromium 通道。
- 浏览器验证使用本地假接口，覆盖四类作业、草稿切换、提交失败、列表刷新失败、返工、盲评、图片查看、质检门禁和窄屏布局，不调用模型。
