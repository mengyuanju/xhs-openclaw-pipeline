# 作业中心列表

作业中心在侧栏提供七个子菜单，每个地址只显示对应列表。访问 `/workbench` 默认跳转到个人作业中心。

| 子菜单 | 地址 | 范围 |
| --- | --- | --- |
| 个人作业中心 | `/workbench/personal` | 当前账号提交或负责的全部未废弃任务，覆盖文案、生图、人工归档和已审核阶段 |
| 全部文案任务 | `/workbench/all-copy` | 全局待执行、执行中、失败的文案任务 |
| 待文案审核 | `/workbench/copy-review` | 全局待文案审核任务 |
| 生图中 | `/workbench/images` | 全局待生图、正在生图任务 |
| 人工归档 | `/workbench/manual-archive` | 全局生图成功、等待人工归档的任务 |
| 已完成 | `/workbench/completed` | 全局图片已审核通过的任务，可查看详情和下载资源 |
| 全部作业 | `/workbench/all` | 仅管理员：全部账号、全部执行节点、全部任务状态及无创建者历史任务 |

普通用户只显示个人作业中心；审核员保留业务列表；管理员额外拥有全部作业入口。页面和服务端均校验权限，隐藏菜单不是权限判断的唯一依据。

## 审核默认值与列表操作

每次打开待文案审核任务（包括生图失败后回审的任务）时，“AI生成水印”默认关闭，审核人可手动开启，提交审核时保存选择。打开已进入生图或归档阶段的任务时，显示当时保存的设置。该交互不修改历史图片或全局生产配置。

列表通常只保留“查看”或“审核”主按钮，重试和重试生图收进“更多操作”菜单。管理员在“全部作业”处理排队任务时会直接看到“废弃”，废弃后原位置切换为“永久删除”；可恢复的“重新排队”仍放在更多操作中。菜单保留各操作的角色权限、禁用条件和确认提示，支持键盘选择、Escape 关闭，取消确认后焦点回到菜单按钮。桌面和窄屏均保持单行操作区。

任务详情中的“模型调用链路”仅管理员可见。Web 代理和中心服务均拒绝普通用户、审核员读取链路列表及单条详情；普通任务详情响应也不再向非管理员返回含内部提示词的执行快照。管理员的链路查询与执行机记录上传保持可用。

## 人工归档与图片审核

管理员、审核员打开人工归档任务后，在“图片审核”区域选择：

- **审核通过**：状态从 `MANUAL_ARCHIVE` 变为 `REVIEWED`，界面显示“已审核”，移入“已完成”列表。详情记录审核账号和时间，仍可下载当前文案及图片。
- **重试生图**：保留已审核文案，使用最新配置重新生成整套图片，状态回到 `IMAGE_QUEUED`；旧图片和执行记录保留，重新生成会消耗模型额度。
- **废弃**：状态变为 `CANCELLED`，移出业务列表，管理员仍可从全部作业查看历史。

人工归档列表也提供废弃按钮。审核员可处理其他账号创建的人工归档任务；普通用户仍按原有归属权限查看和废弃自己的任务，不能提交最终图片审核。

中心新增 `POST /v1/tasks/:taskId/review-images`，请求包含 `imageRunId` 和 `decision=APPROVE|RETRY|DISCARD`。审核身份取自中心验证的当前账号。服务端在事务中锁定任务，检查人工归档状态及当前图片运行 ID；通过审核还会检查图片运行已完成且对应当前文案。重复或过期操作返回 409，不能覆盖新结果。

排序统一为：待文案审核 → 人工归档 → 文案生成中 → 生图中 → 生成失败 → 待执行 → 已审核 → 已废弃；同优先级按创建时间、任务 ID 倒序。服务端在分页前排序，旧中心数组兼容路径使用相同优先级。

本次需先升级并重启中心服务，自动执行增量迁移 `0011_image_review`，再更新 Web。迁移只扩展状态及增加可空审核字段，现有人工归档任务仍等待人工判断，不自动通过。回滚 Web 不影响数据；回滚中心代码前需先处理新状态，不能直接移除已有审核字段或迁移记录。

2026-09-06 验证：本次改动独立副本的 805 项主项目测试、122 项中心服务测试、生产构建和 Mock smoke 全部通过。隔离 PostgreSQL 验证迁移、分页前排序和并发审核互斥；浏览器验证审核员跨账号通过/重试/废弃、已完成详情与下载，以及 320/768/1024/1440 宽度和键盘操作，未调用模型。

## 管理员全部作业与角色筛选

“作业员（创建者）”可以按姓名或账号搜索，用姓名、账号和当前角色区分人员，候选包括停用账号。选定后同时提交账号名与不可复用的数字账号 ID，中心据此精确查询这一代账号创建的任务；即使删除后重新建立同名账号，也不会混入旧账号历史。筛选可与角色、状态及 Query 关键词组合，改变人员筛选回到第一页。清除人员选择后恢复所有创建者。旧版只保存账号名的链接或常用视图不会自动转向同名新账号，界面会要求重新选择。已删除账号不在候选中，其历史作业仍可通过未知角色及 Query 搜索查看。Query 搜索范围为作业选题，不是生成正文全文。

列表将 ID 与 Query、账号与角色、状态与进度、开始时间与耗时分别组合展示。长 Query 最多显示三行，点击查看完整详情；姓名、执行机和进度说明限制为两行并提供完整悬浮文本。桌面 Query 固定占表格约 25%，避免独占剩余空间；右侧操作列保持可见，表格可横向滚动。1050px 及以下的平板和手机转为卡片。

全部作业默认不限制创建者或执行机，包含 `IMAGE_FAILED`（生图失败）和 `CANCELLED`（已废弃）。角色、状态和 Query 搜索可以组合使用；改变筛选时回到第一页，由中心计算筛选后的总数。“清空筛选”一次重置选题、人员、角色和状态，不重置每页条数。列表显示创建者当前角色、真实任务状态、文案/生图执行机和进度，点击“查看”复用已有详情。

管理员可以在“全部作业”的排队任务行直接点击“废弃”，确认后任务原子退出文案或生图队列并进入 `CANCELLED`，历史数据不删除。已废弃任务直接显示“永久删除”；永久删除仍要求删除二级密码，并清理任务、执行记录、文案、图片及素材，无法撤销。误操作时可在更多操作中重新排队。批量处理使用相同的“批量废弃 → 批量永久删除”边界。

所有工作台列表共用页脚分页，支持首页、上一页、下一页、尾页，以及输入整数页码后点击跳转或按 Enter；越界页码就地提示。默认每页 20 条，可选 50/100 条，修改条数回到第一页。页脚显示当前记录区间与总数，并在长列表滚动期间保持可见；切页成功后滚到新页列表开头。加载时保留上次表格高度，暂时禁止旧行操作，避免空屏闪动。读取失败时明确显示“上次结果”和失败页码，并提供页脚重试按钮。

角色选项包括全部角色、管理员、审核员、普通用户和未知角色。角色来源是中心 `app_users` 中的当前记录，不是任务创建时的历史角色；角色调整后旧任务随当前角色分类。无创建者或创建者已删除的任务属于未知角色，不从执行节点推断身份。

中心 `GET /v1/tasks` 新增可选 `createdByRole=ADMIN|REVIEWER|USER|UNKNOWN`，仅管理员可以使用；非法值返回 400，非管理员携带该参数返回 403。省略参数保持既有角色权限；普通用户始终强制按自己的账号查询。任务响应新增可空 `createdByRole`，通过已有用户关联读取，不需要数据库迁移。角色条件在分页前应用，并同时应用于 total 查询。

全部作业检查 `/health` 的 `capabilities.adminTaskFilters=true`，并要求 `includeTotal=true` 返回 `{ items, total, limit, offset }`。旧中心明确提示升级，不将前 100/200 条显示为全部任务。现有其他工作列表的旧中心兼容逻辑保持原行为。

列表在可见时每 30 秒自动刷新，隐藏页面暂停轮询，返回时立即刷新；已有请求未结束时不叠加自动刷新。管理员能力检查与任务读取并行，仍要求两者通过才显示结果。切页或更改条件会终止浏览器中的旧请求，并用请求编号防止旧响应覆盖当前筛选；不缓存任务结果，不预取全量。失败时显示原因并保留上次成功结果、最近成功时间和重新读取按钮。保留结果可能不符合新筛选或最新状态，界面会明确提示。

部署时先更新并重启中心服务，再更新 Web。执行机、模型调用和生成/重试流程无需调整。全部作业只查询当前 `CONTROL_PLANE_URL` 对应中心，不自动汇总本地和远程数据库。

个人作业中心同时显示当前账号提交的任务和当前由其负责的任务；提交者与负责人仍分别记录，不会因为转派而改写创建信息。普通任务在机器生成文案期间保持未分配，提交者可以跟踪进度并在允许的机器阶段撤销，进入文案待审核后才由自动池或管理员分配负责人。界面服务从已验证会话注入不可变账号 ID、账号名、角色及凭据版本；浏览器伪造的身份筛选不会被采纳。搜索、分页和总数使用相同的服务端稳定账号可见范围。同一账号从不同节点登录时看到相同的任务，管理员代建并分配的作业员也能看见自己的待办。

个人列表覆盖当前账号提交或负责的任务。未分配的文案执行中或执行失败行允许稳定创建账号在“更多操作”中重试，重试会作废当前执行并重新排队；任务分配负责人后则只允许负责人或管理员操作。未领取任务显示“待文案执行”，由有空闲并发容量的执行机领取。个人列表与生图中列表的“更多操作”菜单提供“重试生图”：只有存在已审核文案的生图任务、历史归档任务或生图失败回审任务可以点击，执行后旧运行会被作废并以最新配置回到全局 `IMAGE_QUEUED`；尚未审核文案的任务菜单项禁用，不能绕过审核。

管理员在“运营与系统”下可访问 `/executors` 执行机管理页。该页通过管理员专用的 `/v1/executor-statuses` 接口展示所有执行机的90秒心跳在线状态、最后上报时间、图片能力开关及两类并发占用，并每15秒自动刷新；审核员和普通用户访问会被拒绝或重定向。

中心服务仍遵循可信私网部署边界；身份请求头只允许由 Web 服务注入，中心会对照当前账号 ID、账号名、角色、状态和凭据版本校验，但不应绕过 Web 直接暴露在公网。

更新中心服务并重启时，会自动执行增量迁移 `0003_task_creator`，新增可空创建者字段及分页索引。也可按现有数据库升级流程提前执行迁移。必须先更新中心服务，再使用新的个人列表。

旧任务没有可靠的账号归属，因此迁移不会根据节点推断创建者；它们继续出现在对应全局列表。由旧客户端直接创建、未携带账号信息的任务也遵循此规则。任务废弃后仍保留历史数据，在原有业务列表中隐藏，但管理员可以在全部作业中查看和筛选已废弃记录。
