# 作业中心列表

作业中心在侧栏提供五个子菜单，每个地址只显示对应列表。访问 `/workbench` 默认跳转到个人作业中心。

| 子菜单 | 地址 | 范围 |
| --- | --- | --- |
| 个人作业中心 | `/workbench/personal` | 当前账号创建的全部活跃生命周期任务 |
| 全部文案任务 | `/workbench/all-copy` | 全局待执行、执行中、失败的文案任务 |
| 待文案审核 | `/workbench/copy-review` | 全局待文案审核任务 |
| 生图中 | `/workbench/images` | 全局待生图、正在生图任务 |
| 人工归档 | `/workbench/manual-archive` | 全局图片生成成功、等待人工归档的任务 |

个人任务归属使用登录会话账号 `createdByUserId`，与创建节点、分配的执行机分别记录。界面服务从已验证的会话注入创建者请求头，浏览器提交的创建者字段不会被采纳；`mine=true` 也由界面服务解析成当前账号的筛选条件。搜索、分页和总数使用相同的服务端创建者筛选。同一个管理员账号从不同节点登录时看到相同的个人任务。

个人列表按创建账号展示任务。文案执行失败的行提供“重试”按钮，确认后沿用现有文案重试接口，使用最新配置回到共享文案队列；未领取任务显示“待文案执行”，由有空闲并发容量的执行机领取。个人列表与生图中列表的每一行同时展示“重试生图”：只有存在已审核文案的生图任务、历史归档任务或生图失败回审任务可以点击，执行后旧运行会被作废并以最新配置回到全局 `IMAGE_QUEUED`；尚未审核文案的任务按钮禁用，不能绕过审核。

管理员在“运营与系统”下可访问 `/executors` 执行机管理页。该页通过管理员专用的 `/v1/executor-statuses` 接口展示所有执行机的90秒心跳在线状态、最后上报时间、图片能力开关及两类并发占用，并每15秒自动刷新；审核员和普通用户访问会被拒绝或重定向。

中心服务仍遵循现有可信私网部署边界；身份请求头用于保存创建者信息，不是中心服务新增的认证机制。

更新中心服务并重启时，会自动执行增量迁移 `0003_task_creator`，新增可空创建者字段及分页索引。也可按现有数据库升级流程提前执行迁移。必须先更新中心服务，再使用新的个人列表。

旧任务没有可靠的账号归属，因此迁移不会根据节点推断创建者；它们继续出现在对应全局列表。由旧客户端直接创建、未携带账号信息的任务也遵循此规则。任务废弃后仍保留历史数据，按照原有交互从列表隐藏。

验证使用模拟任务和本地测试服务，不启动执行代理或调用模型。
