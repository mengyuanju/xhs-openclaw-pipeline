# 作业中心列表

作业中心在侧栏提供六个子菜单，每个地址只显示对应列表。访问 `/workbench` 默认跳转到个人作业中心。

| 子菜单 | 地址 | 范围 |
| --- | --- | --- |
| 个人作业中心 | `/workbench/personal` | 当前账号创建的全部未废弃任务，覆盖文案、生图和人工归档阶段 |
| 全部文案任务 | `/workbench/all-copy` | 全局待执行、执行中、失败的文案任务 |
| 待文案审核 | `/workbench/copy-review` | 全局待文案审核任务 |
| 生图中 | `/workbench/images` | 全局待生图、正在生图任务 |
| 人工归档 | `/workbench/manual-archive` | 全局生图成功、等待人工归档的任务 |
| 全部作业 | `/workbench/all` | 仅管理员：全部账号、全部执行节点、全部任务状态及无创建者历史任务 |

普通用户只显示个人作业中心；审核员保留业务列表；管理员额外拥有全部作业入口。页面和服务端均校验权限，隐藏菜单不是权限判断的唯一依据。

## 管理员全部作业与角色筛选

全部作业默认不限制创建者或执行机，包含 `IMAGE_FAILED`（生图失败）和 `CANCELLED`（已废弃）。角色、状态和 Query 搜索可以组合使用；改变筛选时回到第一页，每页 20 条，由中心计算筛选后的总数。列表显示创建者当前角色、真实任务状态、文案/生图执行机和进度，点击“查看”复用已有详情。

角色选项包括全部角色、管理员、审核员、普通用户和未知角色。角色来源是中心 `app_users` 中的当前记录，不是任务创建时的历史角色；角色调整后旧任务随当前角色分类。无创建者或创建者已删除的任务属于未知角色，不从执行节点推断身份。

中心 `GET /v1/tasks` 新增可选 `createdByRole=ADMIN|REVIEWER|USER|UNKNOWN`，仅管理员可以使用；非法值返回 400，非管理员携带该参数返回 403。省略参数保持既有角色权限；普通用户始终强制按自己的账号查询。任务响应新增可空 `createdByRole`，通过已有用户关联读取，不需要数据库迁移。角色条件在分页前应用，并同时应用于 total 查询。

全部作业检查 `/health` 的 `capabilities.adminTaskFilters=true`，并要求 `includeTotal=true` 返回 `{ items, total, limit, offset }`。旧中心明确提示升级，不将前 100/200 条显示为全部任务。现有其他工作列表的旧中心兼容逻辑保持原行为。

列表每 30 秒自动刷新；失败时显示原因并保留上次成功结果、最近成功时间和重新读取按钮。保留结果可能不符合新筛选或最新状态，界面会明确提示；旧请求晚于新请求返回时不会覆盖新筛选结果。

部署时先更新并重启中心服务，再更新 Web。执行机、模型调用和生成/重试流程无需调整。全部作业只查询当前 `CONTROL_PLANE_URL` 对应中心，不自动汇总本地和远程数据库。

个人任务归属使用登录会话账号 `createdByUserId`，与创建节点、分配的执行机分别记录。界面服务从已验证的会话注入创建者请求头，浏览器提交的创建者字段不会被采纳；`mine=true` 也由界面服务解析成当前账号的筛选条件。搜索、分页和总数使用相同的服务端创建者筛选。同一个管理员账号从不同节点登录时看到相同的个人任务。

个人列表按创建账号展示任务。文案执行失败的行提供“重试”按钮，确认后沿用现有文案重试接口，使用最新配置回到共享文案队列；未领取任务显示“待文案执行”，由有空闲并发容量的执行机领取。进入文案审核、生图或人工归档阶段后，仍可在个人列表及对应全局列表查看。

中心服务仍遵循现有可信私网部署边界；身份请求头用于保存创建者信息，不是中心服务新增的认证机制。

更新中心服务并重启时，会自动执行增量迁移 `0003_task_creator`，新增可空创建者字段及分页索引。也可按现有数据库升级流程提前执行迁移。必须先更新中心服务，再使用新的个人列表。

旧任务没有可靠的账号归属，因此迁移不会根据节点推断创建者；它们继续出现在对应全局列表。由旧客户端直接创建、未携带账号信息的任务也遵循此规则。任务废弃后仍保留历史数据，在原有业务列表中隐藏，但管理员可以在全部作业中查看和筛选已废弃记录。

验证使用模拟任务和本地测试服务，不启动执行代理或调用模型。
