# 工作台性能与审核体验改进

## 本轮范围

- 个人作业列表及任务详情为已停止的生图失败任务提供“从失败步骤继续”。复用原配置和检查点；能力不支持、检查点缺失时明确报错，不转为全量重画。普通用户可以读取中心健康接口的能力信息，任务操作仍由中心校验归属和权限。
- 图片审核顶部显示当前运行的自动评分、严重问题和逐项证据，并可直接跳到图片。读取已有 `qc.rubric.dimensions` 和问题标签；本地格式/背景转换版本显示待人工核对，不沿用原版本的通过分数。
- 图片审核的通过、重试和废弃操作固定在弹窗底部。手机上使用两列按钮；提交错误显示在操作区，保持按钮可见。
- 任务图片缩略预览使用长边不超过 480 像素的 WebP，保留比例和透明通道、不放大小图；打开大图和下载继续使用原图。

## 资产接口与缓存

`GET /v1/assets/:id` 返回原图；`GET /v1/assets/:id?variant=thumbnail` 返回缩略图。未知 variant 返回 400。两者均支持 HEAD 和各自独立的 ETag。

图片响应使用 `Cache-Control: private, no-cache`：浏览器可存储，每次重用都必须通过登录、账号状态和任务归属检查，再按 ETag 返回空的 304。Next 代理不缓存到共享 fetch 缓存，只传递资产条件请求和私有响应头，并以 Cookie 区分用户。错误响应和业务 JSON 保持 no-store。

鉴权查询只读取任务 ID 和创建者，避免每张图片都加载执行记录、文案、图片运行及资产历史。原图通过流返回。缩略图首次请求时生成，按资产哈希和转换版本存放在中心 `storageRoot/thumbnails/<taskId>/` 下，后续复用；每个中心进程最多同时转换两张、最多排队 32 个不同资产。同一资产的并发请求合并。缓存目前没有自动淘汰，需要纳入磁盘容量管理。

## 本地验证（2026-09-07）

50 张现有 PNG 样本的原图总量为 141,890,964 字节；对应缩略图为 1,153,076 字节，减少 99.19%。首次转换中位耗时 53.19 ms，已生成缓存查找中位耗时 0.27 ms。这是本地转换/文件访问测量，不是公网加载时间；正式环境表现取决于硬件、带宽及图片内容。原图未被修改。

验证覆盖：主工程与服务端测试、TypeScript、Next 生产构建、mock 流水线，以及隔离假数据页面的桌面和 390×844 手机浏览器操作。HTTP 回归覆盖透明通道、尺寸、原始字节、跨实例磁盘复用、真实 no-store 代理下的 304、越权和失效账号。浏览器验证了质检摘要、跳转图片、缩略图 URL、续跑确认、检查点缺失报错，以及手机错误提示后的按钮可见性；没有调用真实模型。

提交前在独立工作树重新验证：主工程 951 项测试、中心服务 155 项测试全部通过。分支基于 `auto-clow-poker` 的 `b0c4cd4`，仅包含本轮性能与审核体验修改。

## 更新运行环境

中心目录运行 `npm ci` 安装锁定的 Sharp 依赖，然后重启中心服务；Web 更新后重启其服务。开发模式下 Web 页面修改会自动刷新，但已有中心进程需要重启才能加载新的资产路由。无需数据库迁移，也无需预先转换历史图片。旧中心不识别缩略图参数时仍能展示原图，但没有本轮传输收益。

统计页聚合、长列表数据量、草稿自动保存和生成阶段耗时监控不在本轮修改范围。
