# Query 对应小红书链接采集

这条采集链路独立于文案模型：Query 词包明细在人工筛选中变为 `SELECTED` 时，中心 PostgreSQL 会幂等创建搜索任务；链接不会写入 `task.input`、模型执行快照或文案版本，所以不会进入模型 Prompt。

## 首次登录

1. 安装依赖并升级中心数据库：`npm install`，再按数据库升级流程应用至 `0042_xhs_search_rate_limits.sql`。
2. 为中心服务和搜索执行机配置同一个 `XHS_SEARCH_MACHINE_TOKEN`（32–512 字符，只放在运行环境或密钥管理中，不提交到仓库）。
3. 运行 `npm run xhs:login`。
4. 在打开的 Edge 专用窗口中手动扫码或输入验证码，确认登录成功后关闭窗口。

登录 Cookie 只保存在仓库外的专用浏览器目录。首次使用时目录必须为空，执行机会写入专用标记；系统不接收、传输或保存小红书账号密码，也不要把日常浏览器的默认用户目录配置给执行机。

## 搜索执行机

- 持续处理：`npm run xhs:search`
- 只处理一条：`npm run xhs:search -- --once`
- 人工处理登录或验证码后恢复：`npm run xhs:search -- --resume`
- 检查执行环境后按生产任务精确重试普通失败：`npm run xhs:search -- --retry-task-id=123`
- 也可按搜索任务精确重试：`npm run xhs:search -- --retry-job-id=456`

一个账号同一时间只会执行一个 Query。出现登录页或安全验证时，当前任务会进入 `BLOCKED`，后续 Query 也不会再被领取；人工处理并显式恢复后才会继续。网络故障最多自动尝试三次，恢复登录不会重置普通失败任务。排除网络或页面异常后，可使用独立的精确重试参数重置指定失败任务的尝试次数，避免任务永久卡住导出；无指定任务 ID 时不会重置任何失败记录。

## 账号与节点状态

每一个启动 `npm run xhs:search` 的进程都会注册成独立的小红书搜索节点，包括中心服务器本机和普通执行机。建议为每个进程配置唯一的 `XHS_SEARCH_NODE_ID`，并设置：

- `XHS_SEARCH_ACCOUNT_LABEL`：管理员可识别的非敏感账号显示名，不要填写手机号、密码或 Cookie。
- `XHS_SEARCH_HOST_KIND=CENTER`：搜索进程运行在中心服务器时使用。
- `XHS_SEARCH_HOST_KIND=EXECUTOR`：搜索进程运行在普通执行机时使用，也是默认值。

管理员的“执行机管理”页面统一显示节点类型、账号标签、搜索进程在线状态、最新登录状态、最近实际验证时间和最近搜索任务。搜索进程每次轮询都会刷新心跳；超过 90 秒未上报显示为离线。登录状态只记录 `等待首次验证`、`最近验证正常`、`需要重新登录` 或 `需要安全验证`，中心不会读取或保存浏览器 Cookie、账号密码。

任一节点检测到需要登录或安全验证后，所有管理员页面都会弹出提醒，搜索队列保持暂停。管理员在对应主机完成处理并用 `--resume` 恢复后，提醒状态先变为“等待验证”；下一次成功搜索后变为“登录正常”。文案和图片生产队列仍独立运行。

人工登录阶段会一直等待，直到操作人员主动关闭专用浏览器，不再使用 30 秒超时。极速模式的首次导航上限为 10 秒，打开结果页后等待 3 秒并只读取首屏；深度排序模式沿用 45 秒导航上限，每次打开结果页或滚动加载后等待 15 秒，再读取文章卡片。

可用环境变量见 `.env.example`。`XHS_SEARCH_PROFILE_DIR` 必须是仓库外的绝对专用路径；默认使用本机 `LOCALAPPDATA`。执行机使用系统已安装的 Microsoft Edge，也可将 `XHS_SEARCH_BROWSER_CHANNEL` 设为 `chrome`。中心端口仍应只开放在受信网络内；机器密钥仅允许通过本机回环 HTTP 发送，连接其他主机时 `CONTROL_PLANE_URL` 必须使用 HTTPS。

管理员可在“生产配置 → 生成与模型 → 小红书素材搜索”中选择：

- 极速模式（默认）：只读取首屏，在首屏有效候选中按点赞量选择最高的 1 条，不向下滚动。
- 深度排序模式：读取首屏并向下滚动 3 次，在全部候选中按点赞量保留 1–10 条，默认 3 条。

同一面板提供管理员可调的账号保护节奏：两次搜索最短间隔默认 60 秒、滚动 60 分钟最多 30 次、滚动 24 小时最多 150 次。中心服务在发放搜索任务前检查全部限制，并按每一次发放的搜索任务计数；随后搜索失败、出现验证码或登录失效也会消耗额度。管理员调整后对下一次任务领取立即生效，执行机本地的轮询间隔不能绕过中心限制。

三项数值会同时做范围和容量校验。每小时上限不得超过 `floor(3600 / 最短间隔秒数)`；每日上限不得超过 `floor(86400 / 最短间隔秒数)`，也不得超过每小时上限的 24 倍。例如最短间隔为 30 秒时，每小时最多只能设置 120 次，不能保存 200 次。当前允许范围为：间隔 10–3600 秒、每小时 1–360 次、每天 1–8640 次。

`1.2万`、`3千+` 等页面显示值会换算后排序，同赞数保持原搜索顺序。无法确认点赞量的卡片不会混入榜单，有效结果不足时实际保存数量可能少于设置值。

这项管理员配置属于搜索协议 v4；中心服务和搜索执行机需要同步升级。中心会在执行机领取任务时把当时的模式及实际数量冻结到该任务，正在执行和已完成的结果不受后续配置修改影响；失败或阻塞任务重新领取时使用最新设置。极速模式的实际数量固定为 1，深度模式使用管理员保存的 1–10 条设置。`XHS_SEARCH_RESULT_LIMIT` 和 `--result-limit` 不再控制执行数量，可以从旧部署配置中删除。

搜索结果 URL 只保留小红书域名、笔记路径，以及打开结果需要的一对 `xsec_token` / `xsec_source` 参数；其他追踪参数会被删除。令牌使用 URL 安全 Base64，合法的尾部 `=` padding 会被保留并规范编码。裸笔记地址在其他浏览器中并不可靠；访问参数失效时需要重新搜索，因此链接仅作为审核与交付时的辅助材料。

任务详情和交付数据源统一暴露：

```json
{
  "xiaohongshuLinks": [
    {
      "noteId": "66f000000000000000000000",
      "url": "https://www.xiaohongshu.com/explore/66f000000000000000000000?xsec_token=EXAMPLE_TOKEN%3D&xsec_source=pc_search",
      "title": "示例笔记标题",
      "rank": 1
    }
  ]
}
```

被重新筛选为 `REJECTED` 的明细不会对任务或导出暴露链接；尚未完成的搜索同时会被取消。已经完成的数据仅作为中心审计记录保留。

升级前已经成功的搜索不会自动改成管理员当前设置的数量，因为旧 `rank` 可能只是搜索顺序而不是点赞量排名；这类任务需要在新版上重新搜索，不能从裸笔记 ID 合成或补造 `xsec_token`。
