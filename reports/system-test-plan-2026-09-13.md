## 1. 文档目的

本文档用于指导小红书内容工场的完整测试、缺陷修复、回归验证和最终验收。目标包括：

1. 验证核心作业从 Query 输入到最终交付的完整业务闭环。
2. 验证中心服务、执行器、数据库、前端和独立预览服务之间的契约与数据一致性。
3. 重点保护作业状态机、执行幂等、审核门禁、图片断点恢复和权限隔离。
4. 系统化发现并修复前端使用问题、显示问题、请求竞争和错误反馈问题。
5. 建立性能、并发、恢复和长时间运行的稳定性证据。
6. 对无法自动完成的真实账号或外部服务测试进行明确登记，提供配置及复测步骤。
7. 形成可审计的最终发现总结报告，为是否发布提供依据。

软件测试无法从数学意义上保证系统绝对不存在新缺陷。本方案通过冻结核心契约、测试先行、最小修复、分层回归、性能对比、数据恢复演练和发布门禁，将回归风险控制在可接受范围内。

## 4. 测试总体策略

### 4.1 测试分层

| 层级 | 目标 | 默认外部依赖 |
| --- | --- | --- |
| 单元测试 | 函数边界、状态转换、校验、错误处理 | 无，全部 Fake |
| 组件与契约测试 | 前端状态、API 契约、客户端解析 | Fake HTTP/Fake 数据 |
| 集成测试 | PostgreSQL、SQLite、中心 API、执行器协作 | 临时数据库、Fake 模型 |
| 系统 E2E | 浏览器到数据库的完整业务链路 | 隔离中心、Fake 执行器 |
| 外部真实验收 | 小红书、Codex、DeepSeek、预览服务 | 明确授权、最小样本 |
| 性能与长稳 | 吞吐、延迟、资源、并发和恢复 | 合成数据、Fake 模型 |

### 4.2 测试环境原则

1. PostgreSQL 集成测试使用系统临时目录创建独立集群，不读取生产 `DATABASE_URL`。
2. SQLite 测试使用临时数据库，每个用例独立关闭连接和清理句柄。
3. 模型、网络搜索和图片生成默认使用 Fake，禁止消耗真实额度。
4. 外部 Query、模型输出、文件名和 URL 始终视为不可信输入。
5. 测试使用固定随机种子、可控时间和稳定测试数据，禁止依赖执行顺序。
6. 不通过增加任意等待时间掩盖并发和请求竞争缺陷。
7. 任何需要真实账号、验证码、密钥或外部服务的项目均先登记，再配置复测。
8. 不在测试中写入或输出凭据，不把真实 Token、Key、Cookie 或密码写入报告。

## 5. 核心作业状态机

核心业务链路如下：

```text
Query 搜索/词包筛选
        │
        ▼
COPY_QUEUED ──领取──▶ COPY_RUNNING
     ▲                     │
     │                     ├──失败──▶ COPY_FAILED ──重试──┘
     │                     │
     │                     ▼
     │             COPY_REVIEW_PENDING
     │                     │
     │                     ├──无需抽检──────────────┐
     │                     │                        │
     │                     ▼                        │
     │              COPY_QC_PENDING                │
     │                     │                        │
     │                     ├──退回→修改→强制复检───┤
     │                     │                        │
     │                     ▼                        ▼
     └──────────────── IMAGE_QUEUED ──领取──▶ IMAGE_RUNNING
                                                   │
                                                   ├──失败──▶ IMAGE_FAILED
                                                   │             │
                                                   │             └──断点恢复/重试
                                                   ▼
                                             MANUAL_ARCHIVE
                                                   │
                                                   ▼
                                                REVIEWED
                                                   │
                                                   ▼
                                         ZIP/XLSX/独立预览交付
```

`CANCELLED` 是受权限和状态约束的逻辑终态。重新入队、永久删除和批量操作必须按照原状态、审核冻结和执行状态进行校验。

## 6. 核心业务不变量

以下不变量属于发布阻断级别，必须全部自动验证：

1. 同一任务同一时刻最多存在一个有效的同类运行执行。
2. 旧执行、失败执行或超时执行不能覆盖新执行结果。
3. 任务状态、当前阶段、当前执行 ID、当前文案版本和当前图片运行必须一致。
4. 领取时冻结的提示词、生产配置、知识、图片数量和审核设置不受后续全局修改影响。
5. 图片资产只能属于合法整数任务 ID、当前图片运行和对应执行记录。
6. 已验收图片不得重画；上传失败只能补传，不得重复调用模型。
7. 文案抽检或返工强制复检未通过前，不得进入 `IMAGE_QUEUED`。
8. 文案机器评分为 `2` 或 `2.5` 时，必须实际修改标题、正文或标签后才能以最终 `3` 分通过。
9. 机器原稿为 `3` 分时允许不修改通过，但必须保存明确审核来源。
10. 请求响应丢失后使用相同 requestId 重放，不得重复领取或重复运行模型。
11. 一个执行失败不得阻塞其他执行完成、补位或独立失败回报。
12. 非当前负责人、非所有者或权限不足的用户不得读取或修改任务。
13. 同名账号删除后重建，不得继承旧账号的任务、权限或审核记录。
14. 批量操作发生数据库或文件错误时，必须整体回滚或给出逐项明确结果。
15. 交付只能读取最终固定的文案版本、图片运行和资产集合。

## 7. 详细单元测试方案

### 7.1 输入与领域校验

| 用例组 | 主要边界与异常 | 预期结果 |
| --- | --- | --- |
| Query | 空字符串、空白、1 字、500 字、501 字、换行、Emoji | 合法值规范化；超限明确拒绝 |
| 批量任务 | 0、1、100、101 条，重复 Query，部分非法 | 边界内接受；非法请求不产生部分写入 |
| 任务 ID | 0、负数、小数、超安全整数、路径字符 | 只接受正安全整数 |
| 图片数量 | `auto`、3、4、5、其他整数和字符串 | 只接受协议允许值 |
| JSON | 循环引用、不可序列化、字节上限前后 | 明确拒绝，不崩溃、不截断后误用 |
| 阶段和进度 | 非法阶段名、-1、0、100、101 | 只接受规范阶段和 0–100 整数 |
| 文案审核 | 标题、正文、标签数量和长度边界 | 错误字段精确、原数据不被破坏 |
| 图片策划 | 3–5 页、首图位置、重复 hero、非法布局 | 只接受完整结构化方案 |
| URL | 非 HTTP(S)、私网、非小红书域名、追踪参数 | 按业务协议拒绝或清理 |
| 文件路径 | `..`、绝对路径、符号链接、伪造扩展名 | 不能逃出任务目录或冒充图片 |

### 7.2 SQLite 队列

- 新任务按创建顺序领取。
- 同一任务不能被两个 Worker 同时领取。
- Lease 未过期不能被回收，过期后可由新 Worker 恢复。
- 续租只允许当前 Worker，且不增加业务尝试次数。
- 完成和失败只允许持有当前 Lease 的 Worker。
- 延迟重试在到期前不可领取，到期后只领取一次。
- 连续恢复次数和总恢复次数分别计数。
- 认证或额度熔断可持久化，并在明确恢复后清除。
- prepared statement 参数与外部输入完全分离。
- 数据库关闭后无残留句柄，异常时不留下锁文件。

### 7.3 文案生成与质量

- 搜索成功、结果不足、搜索失败和超时路径。
- Codex 与 DeepSeek 搜索提供方契约一致性。
- Dots 与 Codex 文案提供方切换不影响搜索提供方。
- 知识匹配分数 `69.99`、`70` 和同分稳定选择。
- 空知识、无匹配、部分畸形响应和未知 ID。
- 完整案例进入提示词，未选案例不得泄漏。
- 外部 Query、网页文本和知识内容不能改变系统指令。
- 文案 Schema 缺字段、重复字段、错误类型和额外内容。
- 文案长度修复、质量修复和修复次数上限。
- 模型容量、认证、额度和上下文不足错误准确分类。
- 错误和请求证据脱敏，不能记录 Key、Token 或 Cookie。

### 7.4 文案审核与抽检

- `3` 分原稿不修改通过。
- `2`、`2.5` 分原稿未修改时拒绝通过。
- 修改标题、正文或标签后形成新版本并记录最终 `3` 分。
- 只修改图片策划不能冒充文案修改。
- 重复提交同一审核 session 幂等返回。
- 两个审核员同时提交时只有合法当前提交成功。
- 自动派单、人工派单和免审负责人边界。
- 文案抽检样本冻结后不因后续任务变化而漂移。
- 单条退回、整批退回、释放其余任务和强制复检。
- 返工提交本身不能立即触发生图。
- 抽检冻结中的任务不能由通用取消入口绕过审核门禁。

### 7.5 图片生成、接收和恢复

- 图片原生完成事件重复到达时去重。
- 模型文本中的伪造路径不能作为图片完成证据。
- 输出文件必须来自本次执行允许目录。
- 文件签名、媒体类型、尺寸、数量和页面位置一致。
- 首图完成后后续页面并发不超过任务内上限。
- 全局图片许可不超过同机共享上限。
- 图片对齐失败时只执行有界修复。
- 新图和编辑指令严格分离。
- 已成功页面复用检查点，失败页面继续执行。
- 检查点缺失时明确失败，不静默全量重画。
- 资产上传失败保留本地证据，重试仅补传。
- 新执行代次创建后，旧执行完成不能覆盖当前结果。
- 达到图片重试次数上限后进入人工处理路径。

### 7.6 权限和会话

- ADMIN、REVIEWER、USER 的接口权限矩阵。
- 普通用户只能读取自己的或明确授权的任务。
- 审核员只能操作已分配且处于正确阶段的任务。
- 管理员批量、永久删除、用户和配置操作单独校验。
- 用户在请求执行过程中被禁用、删除或改角色时，请求失败关闭。
- 同名账号重建不能继承旧身份。
- HEAD、GET、批量下载和资产读取使用相同权限规则。
- 登录失败、过期 Session、错误 Cookie 和重放请求。

## 9. 核心系统 E2E 场景

### 9.1 E2E-CORE-001：标准完整交付

前置条件：隔离中心、临时 PostgreSQL、Fake 文案和图片执行器、三个测试角色。

步骤：

1. 管理员创建 Query 词包。
2. 完成 Query 筛选和任务分配。
3. 创建生产批次。
4. 文案执行器领取并完成文案。
5. 审核员打开任务，核对文案、评分和图片策划。
6. 文案审核通过并进入抽检或生图门禁。
7. 抽检通过后进入图片队列。
8. 图片执行器领取、生成并上传多张图片。
9. 审核员完成图片审核。
10. 任务进入 `REVIEWED`。
11. 管理员在交付池下载 ZIP 和 XLSX。
12. 创建独立预览并访问公开页面。

预期结果：每个状态只按允许顺序迁移；版本和资产引用一致；交付内容与最终审核内容逐项相同；不存在重复执行或多余资产。

### 9.2 E2E-CORE-002：低分文案修改

1. Fake 模型生成 `2.5` 分文案。
2. 审核员不修改直接提交，系统拒绝。
3. 审核员实际修改文案并再次提交。
4. 系统保存原稿评分、人工修改版本和最终 `3` 分。

### 9.3 E2E-CORE-003：抽检退回和强制复检

1. 任务进入 `COPY_QC_PENDING`。
2. 抽检员退回。
3. 作业员提交返工稿。
4. 验证任务仍未进入生图队列。
5. 强制复检通过后才进入 `IMAGE_QUEUED`。

### 9.4 E2E-CORE-004：图片断点恢复

1. 多图任务前两张成功、第三张失败。
2. 系统进入图片失败状态并保留检查点。
3. 人工从失败步骤继续。
4. 验证前两张未重画，只生成失败及后续页面。
5. 新图片运行成为当前运行，旧执行回报被拒绝。

### 9.5 E2E-CORE-005：上传补偿

1. 图片已经由模型生成成功。
2. 模拟中心上传连接中断。
3. 重试后只重新上传原文件。
4. 验证模型调用次数不增加、文件哈希不改变。

### 9.6 E2E-CORE-006：权限隔离

1. 分别以管理员、审核员和普通用户登录。
2. 验证菜单、列表、详情、资产、批量操作和配置页面。
3. 修改用户状态或重建同名用户。
4. 验证旧 Session 和在途请求立即失效。

### 9.7 E2E-CORE-007：取消、重新入队和永久删除

- 排队任务取消后保存原状态。
- 只允许符合条件的任务重新入队一次。
- 运行任务取消时放弃当前执行，旧回报无效。
- 永久删除只允许规定终态。
- 删除失败时恢复数据库和文件。

## 10. 小红书真实账号测试方案

### 10.1 安全原则

- `XHS_SEARCH_MACHINE_TOKEN` 仅用于中心与搜索执行机的内部认证，不是小红书账号 Token。

### 10.2 自动化 Fake 测试

- 前端账号状态、最近验证时间和错误提示。

### 10.3 真实最小验收


验收：

1. 搜索节点注册并显示在线。

## 12. 性能、并发和稳定性测试

在缺少正式业务 SLO 前，以下为暂定门槛；获得真实业务规模后可调整，但不能在测试失败后为通过而临时放宽。

| 档位 | 任务数 | 用户数 | 执行节点 | 用途 |

重点测量：

- 任务列表、总数、状态、人员、Query 和词包筛选。

- 任务详情、模型调用追踪和图片资产读取。

- 执行节点列表、心跳和任务统计。
- Query 搜索状态列表。

同时检查 SQL 执行计划、索引命中、连接池等待、事务时间和内存峰值。

### 12.3 执行器并发矩阵

- 文案 1 / 图片 1。
- 文案 3 / 图片 2。
- 文案 8 / 图片 4。
- 容量下调。
- 图片能力关闭。
- 一条慢任务和多条快任务交错。
- 领取响应丢失。
- 失败回报持续失败后恢复。
- SIGINT/SIGTERM 停机收尾。
- 节点崩溃和人工恢复。

验收：

- 实际运行峰值不超过节点容量和模型许可。
- 文案与图片池互不阻塞。
- 快任务完成后立即补位，无需等待整批。
- 不确定领取持续占用预留槽，明确终态后才释放。
- 停机后不再领取新任务，但完成在途执行和回报。
- 冷却期间不会高频轮询或占满 CPU。

### 12.4 前端性能

| 指标 | 暂定门槛 |
| --- | --- |
| LCP | ≤ 2.5s |
| INP | ≤ 200ms |
| CLS | ≤ 0.1 |
| 100 行列表滚动 | 无明显掉帧或操作阻塞 |
| 筛选反馈 | 防抖后 300ms 内发出请求，结果按最新请求展示 |
| 图片预览 | 列表使用缩略图，不意外下载全部原图 |

### 12.5 长时间稳定性

- 每个合并候选：30 分钟并发循环。
- 发布候选：2 小时稳定性测试。
- 调度、恢复或数据库重大修改：8 小时长稳测试。

监测：

- 卡死任务和永久 `RUNNING`。
- 重复领取、重复模型调用和重复资产。
- 数据库连接、文件句柄、子进程和浏览器进程泄漏。
- 内存和磁盘持续增长。
- 临时目录、检查点和下载文件残留。
- 心跳、冷却和重试风暴。

预热后 RSS 持续增长超过 15% 时必须调查，不能只以进程仍在运行作为稳定性通过依据。

## 13. 安全与可靠性测试

- SQL 注入、命令注入、路径遍历和恶意文件名。
- Codex 必须使用参数数组和 `shell: false`。
- 模型输出不能控制文件路径、命令、URL 白名单或权限判断。
- CSRF、会话固定、Cookie 属性和登录限流。
- API 请求体大小、文件大小、图片数量和批量上限。
- 资产 ETag、缩略图和原图权限一致性。
- 错误响应不泄漏堆栈、数据库结构、文件路径和凭据。
- 机器 Token 只通过受信环境提供，远程中心必须使用 HTTPS。
- 提示词发布、回滚和任务冻结快照保持可追溯。
- 永久删除前置校验、文件隔离和失败恢复。

## 14. 缺陷等级与处理优先级

| 等级 | 定义 | 发布策略 |
| --- | --- | --- |
| P0 | 数据丢失、跨用户泄漏、凭据泄漏、核心状态不可恢复 | 立即停止，必须修复 |
| P1 | 核心链路中断、重复扣费、重复执行、错误交付 | 必须修复后发布 |
| P2 | 关键 UI 操作困难、错误提示缺失、主要兼容性问题 | 核心页面必须修复 |
| P3 | 轻微排版、文案或低频体验问题 | 风险低时修复，否则记录 |

每个缺陷记录：编号、环境、前置条件、复现步骤、预期、实际、截图或日志、根因、影响范围、修改文件、回归用例、修复结果和剩余风险。

## 15. 修复和回归流程

所有缺陷按照以下顺序处理：

```text
稳定复现
  → 保存证据
  → 添加失败回归测试
  → 明确根因和影响范围
  → 实施最小修复
  → 定向测试
  → 所属模块测试
  → 根目录、中心、预览服务全量测试
  → 类型检查和生产构建
  → 浏览器与视觉回归
  → 性能对比
  → 最终差异审查
```

稳定性保护要求：

1. 核心状态机修复与纯 UI 优化尽量分开提交。
2. 数据库只使用前向增量迁移，不修改已发布迁移校验和。
3. 修复前先写 characterization test，锁定仍需兼容的旧行为。
4. 不删除测试、不放宽断言、不盲目更新截图来让测试通过。
5. 不使用测试自动重试掩盖 flaky case。
6. 性能较基线下降超过 10% 时停止交付并调查。
7. 高风险修复必须包含失败注入和恢复演练。
8. 修改后连续三次全新环境 E2E 通过，才视为无明显不稳定性。

## 21. 功能增删改查（CRUD）完整测试

### 21.1 CRUD 测试原则

本系统包含普通配置对象、版本化对象、状态机对象和审计对象。不同对象不能机械套用相同的增删改查方式：

| 对象类型 | 合理操作方式 | 不应允许的方式 |
| --- | --- | --- |
| 普通配置对象 | 创建、读取、部分更新、受控删除或恢复默认 | 未校验的任意字段覆盖 |
| 版本化对象 | 新建版本、读取历史、发布、回滚、停用 | 原地覆盖已发布版本、删除审计历史 |
| 状态机对象 | 创建、读取、通过业务命令迁移、逻辑取消、受限永久删除 | 绕过状态机直接修改状态或任意硬删除 |
| 审计对象 | 系统创建、授权读取、通常不可修改和删除 | 用户篡改执行证据、评分或调用历史 |
| 外部预览对象 | 创建、读取、撤销公开访问 | 修改已发布内容覆盖原审计记录 |

CRUD 测试不仅检查接口是否存在，还必须检查：

1. 页面是否有清晰入口。
2. 当前角色是否应该看到入口。
3. 前端禁用状态与后端权限是否一致。
4. 必填项、格式、长度、数量和重复值校验。
5. 提交过程中按钮是否防重复。
6. 成功后列表、详情、数量和筛选是否同步。
7. 失败后表单数据是否保留，是否给出可执行提示。
8. 两人同时修改时是否重新检查当前状态。
9. 数据库失败时是否回滚。
10. 涉及文件时数据库与文件系统是否保持一致。
11. 删除是否可恢复、是否需要二次确认、是否影响关联数据。
12. 操作是否产生完整审计记录且不泄漏敏感信息。

### 21.2 通用新增测试

每一种“新增”操作至少覆盖：

- 正常新增。
- 所有必填项缺失。
- 单字段最小值、最大值及越界值。
- 前后空格、换行、中文、英文、Emoji 和超长连续字符。
- 重复名称、重复业务键和重复幂等键。
- 双击提交和网络超时后重试。
- 无权限用户直接调用接口。
- 用户在提交过程中被禁用或删除。
- 数据库写入中途失败。
- 新增成功但页面刷新失败。
- 新增完成后列表、详情、统计和筛选的一致性。

新增操作验收标准：只生成一条合法记录；重复请求不会产生意外副本；失败不留下半条记录；创建者、时间和来源审计准确。

### 21.3 通用查询测试

每一种“查询”操作至少覆盖：

- 列表、详情、总数和关联对象。
- 空数据、单条、分页边界和大数据量。
- 首页、尾页、指定页、超范围页和切换每页条数。
- 状态、角色、创建者、负责人、执行机、Query、词包和日期组合筛选。
- 中文大小写不适用场景、英文大小写、前后空格和部分匹配。
- 正序、倒序、同值稳定排序。
- 不存在 ID、非法 ID、已删除 ID 和无权限 ID。
- 会话过期和请求执行过程中权限变化。
- 快速切换筛选、翻页和详情时拒绝旧响应。
- HEAD、缩略图、原图和下载接口的权限一致性。
- 列表总数、分页条数和统计口径一致。

查询操作验收标准：不能跨用户泄漏；不能因 JOIN 重复导致计数或分页错误；旧请求不能覆盖新页面；大数据量下仍满足性能门槛。

### 21.4 通用修改测试

每一种“修改”操作至少覆盖：

- 修改单个字段和多个字段。
- 未提交字段保持原值。
- 传入未知字段时拒绝或明确忽略，不能写入数据库。
- 将字段清空、设为 `null`、恢复默认和继承配置。
- 修改为当前值时的幂等行为。
- 两个操作者同时修改。
- 修改对象已被删除、停用或迁移状态。
- 修改过程中操作者权限变化。
- 保存成功但响应丢失后的重试。
- 数据库失败后的完整回滚。
- 修改后的历史记录、快照和在途任务保持正确。

修改操作验收标准：只修改允许字段；不可变字段不变；并发冲突不会静默覆盖；已领取任务继续使用旧快照；后续新任务使用新配置。

### 21.5 通用删除测试

每一种“删除”操作必须先判定其语义：硬删除、逻辑删除、停用、撤销、退休或回滚。至少覆盖：

- 正常删除或停用。
- 不存在对象重复删除。
- 无权限删除。
- 依赖对象存在时删除。
- 活跃任务、运行执行或审核冻结存在时删除。
- 二次确认取消和确认。
- 批量删除中部分对象不符合条件。
- 数据库提交前文件处理失败。
- 文件隔离后数据库提交失败。
- 删除成功后列表、详情、统计、下载和历史访问。
- 可恢复对象的恢复路径。
- 同名对象重新创建后的身份隔离。

删除操作验收标准：不产生孤儿记录或孤儿文件；不能绕过状态机；失败可恢复；删除后的历史审计符合业务规定。

### 21.6 各模块 CRUD 能力与测试矩阵

#### 21.6.1 用户与个人资料

| 操作 | 业务入口 | 角色 | 必测内容 |
| --- | --- | --- | --- |
| 新增 | 管理员创建用户 | ADMIN | 用户名唯一、角色、初始状态、临时密码处理、重复提交 |
| 查询 | 用户列表、个人资料 | ADMIN / 当前用户 | 列表筛选、本人资料、跨用户禁止、同名重建隔离 |
| 修改 | 角色、状态、姓名、个人资料、密码 | ADMIN / 当前用户 | 在途任务约束、旧 Session 失效、密码规则、不可修改身份 ID |
| 删除 | 删除用户 | ADMIN | 存在未完成任务时拒绝；删除后旧身份不可被同名账号继承 |

重点用例：

- 将有未完成任务的普通用户停用、改角色或删除时必须失败并给出关联任务提示。
- 管理员不能因同名账号重建而访问旧账号任务。
- 用户修改密码后旧 Session 按规定失效。
- 删除用户后审计记录保留稳定账号身份，不变成新同名用户。

#### 21.6.2 自动派单池

| 操作 | 业务语义 | 必测内容 |
| --- | --- | --- |
| 新增 | 将普通作业员加入派单池 | 角色必须为 USER、账号 ACTIVE、重复加入幂等或明确冲突 |
| 查询 | 查看派单设置和人员容量 | 当前任务数、状态、排序和离线账号 |
| 修改 | 启停自动派单、调整人员状态或容量 | 新任务生效、在途任务不漂移、并发分配公平性 |
| 删除 | 从派单池移除 | 不取消已分配任务；后续不再自动分配 |

#### 21.6.3 Query 词包

| 操作 | 业务入口 | 必测内容 |
| --- | --- | --- |
| 新增 | 创建或导入 Query 词包 | 文件格式、重复 Query、数量上限、创建者、部分失败原子性 |
| 查询 | 列表、详情、项目分配摘要 | 分页、状态、负责人、筛选、总数、旧数据兼容 |
| 修改 | 词包负责人、单项负责人、筛选结果 | 并发修改、非法状态、已创建生产批次后的约束 |
| 删除 | 放弃、永久删除预览、永久删除 | 先预览影响范围；有关联批次、任务和冻结时正确关闭或拒绝 |

永久删除必须验证嵌套关联闭包：词包、项目、生产批次、任务、执行、版本、抽检冻结、资产和交付记录不能留下不一致残留。

#### 21.6.4 生产批次

生产批次属于审计和流程对象，不建议提供任意原地修改或直接硬删除。

| 操作 | 合理实现 | 必测内容 |
| --- | --- | --- |
| 新增 | 从已筛选 Query 创建批次 | 选中项、数量、负责人、任务快照、重复提交 |
| 查询 | 批次状态、任务、抽检准备度 | 汇总与明细一致、历史批次可追溯 |
| 修改 | 仅通过抽检冻结、释放、退回等命令改变流程 | 禁止任意修改批次归属和历史快照 |
| 删除 | 跟随词包/任务受控闭包，不提供普通删除 | 有审核冻结或交付时必须拒绝或完整闭包处理 |

#### 21.6.5 作业任务

任务是状态机对象，“修改”必须通过明确业务动作完成，不能提供通用 PATCH 任意改状态。

| 操作 | 业务入口 | 必测内容 |
| --- | --- | --- |
| 新增 | 单条或批量创建任务 | 1–100 条、负责人、免审条件、快照、重复 Query |
| 查询 | 列表、详情、计数、归档、模型追踪 | 权限、分页、筛选、当前版本和资产一致性 |
| 修改 | 分配、审核、抽检、重试、图片修改、取消、重新入队 | 每个动作只允许指定状态；并发时重新锁定检查 |
| 删除 | 逻辑取消、受限永久删除、批量永久删除 | 终态白名单、运行执行处理、文件隔离和回滚 |

任务 CRUD 必须覆盖的关键场景：

- 创建免文案审核任务时必须指定普通作业员或当前管理员。
- 普通 Query 初始进入全局机器队列，不被错误绑定执行机。
- 分配负责人不能改变生成快照、文案版本或图片运行。
- 运行任务不能被通用编辑接口修改状态。
- `CANCELLED` 任务只能按保存的原状态合法重新入队一次。
- 永久删除只允许 `COPY_FAILED`、`IMAGE_FAILED`、`REVIEWED`、`CANCELLED` 等规定状态。
- 批量操作必须返回每条成功、跳过或冲突原因，不能只返回整体成功。

| 修改 | claim、complete、block、fail、resume、精确 retry | Token、节点身份、状态门禁、重试目标精确 |
| 删除 | 不提供普通删除；跟随词包/任务闭包 | 不能通过删除隐藏失败或验证码记录 |

#### 21.6.16 模型调用追踪、统计和审计

| 操作 | 合理实现 | 必测内容 |
| --- | --- | --- |
| 新增 | 执行器上传调用追踪，系统生成统计 | 调用 ID 幂等、执行归属、脱敏 |
| 查询 | 管理员读取追踪和统计 | 权限、分页、时间范围、统计口径 |
| 修改 | 不允许普通用户修改历史追踪 | 重复上传只能按协议更新当前追踪状态 |
| 删除 | 不提供普通删除 | 防止掩盖失败、成本和审计证据 |

### 21.7 CRUD 前后端一致性审计

对每个功能生成一张追踪表：

| 功能 | UI 入口 | API | 仓储方法 | 权限 | 数据库约束 | 自动测试 | 结论 |
| --- | --- | --- | --- | --- | --- | --- | --- |

审计重点：

- UI 有按钮但 API 不支持。
- API 存在但页面没有入口。
- 前端隐藏按钮但后端未鉴权。
- 页面成功提示出现，但数据库没有变更。
- 数据库已变更，但列表、计数或详情没有刷新。
- 批量接口与单条接口规则不同。
- 中心模式和本地模式行为不一致。
- 删除入口名称与实际语义不一致，例如“删除”实际是取消或退休。

## 22. 操作流程合理性评审

### 22.1 总体结论

从当前代码和业务说明看，核心流程总体设计合理，尤其是：

- 机器执行与人工审核分离。
- 任务领取时冻结配置，避免在途任务被全局设置污染。
- 文案低分必须人工实际修改。
- 抽检退回后必须强制复检，不能直接生图。
- 图片失败使用检查点恢复，避免重复生成和重复消耗额度。
- 旧执行不能覆盖新执行。
- 交付内容固定到最终文案版本和当前图片运行。
- 提示词和知识采用版本化或退休，而不是覆盖历史。
- 预览采用撤销而不是直接删除母版，便于审计。

但“设计原则合理”不等于实际页面和接口已经完全合理。正式测试必须重点检查流程是否让用户知道：当前在哪一步、为什么不能操作、下一步由谁处理、失败后如何恢复。

### 22.2 主要流程逐项评审

| 流程 | 当前设计判断 | 合理原因 | 重点风险与验证 |
| --- | --- | --- | --- |
| Query 词包→筛选→生产批次 | 合理 | 先筛选再生产，避免无效任务消耗 | 重复 Query、部分选择、永久删除闭包、操作入口是否清晰 |
| 普通任务进入全局机器队列 | 合理 | 不预绑执行机，提高可用容量和故障切换 | UI 不应把创建者、执行机和审核负责人混为一谈 |
| 文案完成后再分配审核负责人 | 合理 | 避免执行前占用人工容量 | 自动派单失败、无人可分配和管理员手动接管必须可见 |
| 免文案审核需明确负责人 | 合理且必要 | 防止机器结果无人负责直接流入图片 | 创建页面必须强提示，后端必须拒绝无负责人请求 |
| 3 分原稿可直接通过 | 合理 | 避免无意义修改 | 必须保存人工确认和原评估证据 |
| 2/2.5 分必须修改后通过 | 合理 | 保证人工确认具有实际内容改进 | UI 必须指出需要修改的字段，避免用户反复试错 |
| 文案抽检和强制复检 | 质量上合理，交互复杂 | 防止被退回文案直接进入生图 | 状态、负责人、下一步入口容易混淆，应做流程引导 |
| 图片生成成功→人工归档 | 合理 | 保留最终图文审核 | `MANUAL_ARCHIVE` 技术名称可能误导，应验证 UI 使用业务语言 |
| 图片失败→检查点恢复 | 合理且必须 | 避免已通过图片重画和额外成本 | 恢复能力、缺失检查点和重试次数耗尽提示必须明确 |
| 上传失败只补传 | 合理且必须 | 模型结果已生成，不应再次付费 | 必须用模型调用次数和文件哈希验证 |
| 取消→重新入队 | 合理但必须严格受控 | 允许恢复误取消的排队任务 | 原状态保存、只恢复一次、审核冻结不能绕过 |
| 永久删除前预览影响范围 | 合理且必要 | 防止误删关联任务和文件 | 预览与实际删除必须在同一事务规则下重新校验 |
| 提示词/知识版本化 | 合理 | 保持在途任务和历史结果可解释 | UI 不能让用户误以为编辑会改变已领取任务 |
| 中心不可用时不回退本地 | 合理的失败关闭 | 防止两套真源产生分叉 | 页面必须明确中心不可用，不能显示本地旧数据冒充最新 |
| 独立预览撤销 | 合理 | 立即停止公开访问并保留审计 | 撤销后图片路由也必须立即失效 |
| 小红书人工登录+低频搜索 | 合理 | 不保存账号凭据，降低平台风险 | 验证码、Session 失效后必须停止继续领取 |

### 22.3 需要重点验证或可能优化的流程点

以下项目不是已经确认的缺陷，而是正式测试中的高风险评审点：

1. `IMAGE_RETRY_EXHAUSTED` 可能通过 `COPY_REVIEW_PENDING` 状态承载人工处理，技术状态与用户理解不完全一致。不得直接改状态机，先验证列表分类、状态文案、负责人入口和恢复按钮是否准确。
2. `MANUAL_ARCHIVE` 容易被理解为“已经归档”，而业务实际可能是“图片生成完成，等待人工图文审核/归档”。UI 应使用清晰业务名称。
3. 文案审核、普通抽检和强制复检存在多个相近入口，需要验证用户能否从任务详情直接进入正确动作。
4. 创建者、文案执行机、图片执行机和审核负责人是四个不同概念，列表和筛选不能使用含糊的“人员”字段。
5. 批量操作存在部分成功时，必须展示逐条结果，不能只提示“操作完成”。
6. 永久删除、放弃、取消、退休、撤销和归档的语义不同，按钮文字和确认文案必须对应真实行为。
7. 配置设为 `null` 表示继承默认值，UI 必须区分“空值”“关闭”和“继承”。
8. 提示词或知识发布后，在途任务不变化；页面需要解释生效范围，避免误判为保存失败。
9. 中心模式不读取本地 SQLite 分支，中心故障时页面必须失败关闭并保留明确错误。
10. 图片重试、图片修改和从失败步骤继续是不同操作，必须限制各自可用状态和预期成本。
11. 交付池不得提供绕过审核的直接编辑；需要返工时必须回到受控任务流程。
12. 小红书搜索 `--once` 会领取一条排队任务，真实测试前必须创建隔离任务，不能盲目对生产队列执行。

### 22.4 流程合理性测试方法

每条业务流程从六个角度评审：

| 角度 | 检查问题 |
| --- | --- |
| 必要性 | 该步骤是否确实保护质量、成本、权限或审计 |
| 可理解性 | 用户是否知道当前状态、阻塞原因和下一步 |
| 可达性 | 正确角色能否从当前页面直接找到操作入口 |
| 一致性 | UI、API、数据库状态和统计是否表达同一事实 |
| 可恢复性 | 网络、执行器、数据库或外部账号失败后能否安全继续 |
| 防误操作 | 是否有状态门禁、确认、幂等、权限和回滚 |

每个流程输出一个结论：

- **合理并验证通过**：规则与实现一致，用户可完成任务。
- **规则合理、交互需优化**：不改核心状态机，只优化入口、文案或布局。
- **实现与规则不一致**：必须先增加失败测试，再修复实现。
- **产品规则不明确**：记录为待确认，不由测试人员擅自补功能。
- **不合理且有风险**：提出替代流程、兼容与迁移方案，经确认后实施。

### 22.5 CRUD 与流程联合 E2E

除第 9 节核心 E2E 外，增加以下联合场景：

#### CRUD-FLOW-001：用户生命周期

管理员创建普通用户→用户登录修改资料→加入自动派单池→获得审核任务→存在未完成任务时删除被拒绝→任务转交→删除成功→同名重建账号不能继承旧任务。

#### CRUD-FLOW-002：词包生命周期

创建词包→读取详情→修改负责人和筛选结果→创建生产批次→验证有关联数据时不能随意删除→查看永久删除预览→在允许状态下完整删除或明确拒绝。

#### CRUD-FLOW-003：任务生命周期

创建任务→列表和详情读取→负责人修改→执行和审核状态命令→逻辑取消→合法重新入队→完成→永久删除→验证数据库、文件和统计无残留。

#### CRUD-FLOW-004：提示词和配置生效范围

发布版本 A→任务 1 领取并冻结 A→发布版本 B→任务 1 继续使用 A→任务 2 使用 B→回滚到 A→任务 3 使用重新发布的 A；历史版本和三条任务均可追溯。

#### CRUD-FLOW-005：知识生命周期

创建知识版本→发布→任务领取快照→发布新版本→退休知识→验证新任务不再匹配、旧任务仍能显示原版本证据。

#### CRUD-FLOW-006：图片资产生命周期

生成原图→读取缩略图和原图→创建修改版本→验证原图未覆盖→审核通过→交付固定→任务永久删除失败时恢复全部资产→成功删除后无孤儿文件。

#### CRUD-FLOW-007：预览生命周期

创建预览→重复相同 sourceRef 和内容时复用→相同 sourceRef 不同内容时冲突→读取公开页面和图片→撤销→页面及图片立即不可访问→管理审计仍存在。

### 22.6 CRUD 和流程放行标准

- 所有对用户可见的新增、查询、修改和删除入口均有测试映射。
- 所有写接口均有权限、校验、幂等、并发和回滚测试。
- 所有删除语义均明确区分硬删除、逻辑删除、停用、退休、撤销和归档。
- 状态机对象不存在通用接口绕过业务门禁。
- UI 操作成功后，数据库、列表、详情、计数和统计结果一致。
- 所有批量操作提供逐项结果并处理部分冲突。
- 审计、历史版本和旧任务快照不能被后续 CRUD 操作破坏。
- 关键流程均从正确角色的真实浏览器入口走通。
- 任何产品规则不明确项在最终报告中单独列出，未经确认不擅自实现。

## 23. 容易遗漏的测试盲区补充

前述测试已经覆盖主要功能、CRUD、状态机、UI、性能和外部账号，但完整发布验收还需要显式覆盖以下容易被忽略的领域。

### 23.1 部署、升级和回滚

必须验证的不只是“当前代码能运行”，还包括从旧版本安全升级和升级失败后的恢复：

- 在一份旧版本数据库副本上预览迁移、正式迁移和重复迁移。
- 中心先升级、执行器后升级的标准顺序。
- 新执行器连接旧中心时是否明确拒绝，而不是静默降级。
- 旧执行器短时间连接新中心时的兼容边界。
- 应用代码回滚但数据库保留新迁移时能否安全运行或明确阻止。
- 升级时存在 `COPY_RUNNING`、`IMAGE_RUNNING` 和上传中任务的行为。
- Windows 重启、服务重启后执行器、中心、前端和搜索进程的恢复顺序。
- 全新目录执行 `npm ci`、类型检查和生产构建，验证结果不依赖开发机残留文件。
- lockfile、Node 版本、Sharp 原生依赖和 PostgreSQL 版本一致性。

发布前要求：至少完成一次“旧数据副本→升级→核心 E2E→应用回滚验证”的演练，并记录升级与回滚时间。

### 23.2 完整备份与灾难恢复

普通事务回滚不能替代灾难恢复测试。需要验证：

- PostgreSQL 全量备份可以在空实例恢复。
- 数据库恢复后，中心文件目录和对象存储资产仍与记录一致。
- 数据库时间点晚于或早于文件备份时，系统能发现缺失资产和孤儿资产。
- SQLite 队列和 Codex 运行状态库的备份范围不会混淆。
- 恢复后的用户、任务、提示词、知识、审核、图片和交付可正常读取。
- 恢复后执行器不会把历史运行任务当作全新任务重复执行。
- 备份文件本身的完整性、加密、访问权限和保留策略。
- 恢复到新主机时路径、权限、时区和服务账号差异。

正式验收需要给出：

- 实测恢复点目标（RPO）。
- 实测恢复时间目标（RTO）。
- 最后一次成功恢复演练时间。
- 数据库与资产不一致时的人工处置步骤。

### 23.3 进程、主机和基础设施故障注入

需要在每个关键提交点注入故障，而不是只测试普通接口报错：

| 故障 | 注入时机 | 必须验证 |
| --- | --- | --- |
| 执行器进程退出 | 领取后、生成中、上传中、回报中 | 任务可识别、可恢复、不重复扣费 |
| 中心服务退出 | 领取事务前后、审核提交中 | 客户端结果明确，恢复后幂等 |
| PostgreSQL 重启 | 查询、事务、批量删除中 | 无半事务、连接池恢复、错误不泄漏 |
| Windows 重启 | 有排队和运行任务时 | 服务恢复顺序、历史执行处理 |
| 磁盘空间不足 | 图片落盘、ZIP/XLSX、数据库日志 | 明确失败、无损坏文件、可清理恢复 |
| 目录只读/权限变化 | 创建任务目录、上传资产时 | 失败关闭、不绕到其他目录 |
| 文件被杀毒软件占用 | 重命名、删除、归档时 | 有界重试、错误可理解、不丢记录 |
| 网络断开 | 请求前、请求后、响应传输中 | requestId 重放、无重复动作 |
| DNS/代理失败 | Codex、DeepSeek、预览服务 | 提供方错误准确分类，不误判认证 |
| TLS 证书异常 | 远程中心或预览服务 | 拒绝不安全连接，不自动降级 HTTP |

### 23.4 时间、时区和时钟偏差

系统包含 Lease、心跳、超时、冷却、UUIDv7、24 小时回执保留、日期筛选和统计，因此必须测试：

- 中心使用 UTC、浏览器使用 Asia/Shanghai 时的显示和筛选。
- 日期边界 00:00、月底、年底和闰日。
- 夏令时地区浏览器访问时不重复或漏掉统计区间。
- 执行机时钟比中心快或慢 1 分钟、5 分钟和 30 分钟。
- 心跳离线 90 秒阈值的边界。
- Lease、重试冷却和模型冷却到期前后 1 毫秒。
- 24 小时 requestId 回执清理边界。
- 浏览器休眠、系统睡眠和唤醒后的倒计时与自动刷新。
- 同一时间戳多条任务的稳定排序。

时钟偏差不能导致任务提前回收、重复执行、无限冷却或错误统计。

### 23.5 配置优先级和配置漂移

当前系统存在中心生产配置、本机环境变量、默认值和任务快照四层来源，必须建立完整优先级矩阵：

```text
任务已领取快照
    > 领取时中心非空生产配置
    > 执行机环境变量
    > 程序默认值
```

重点验证：

- 中心值存在、为 `null`、为空字符串和字段缺失的区别。
- 搜索面板只更新搜索字段，不覆盖其他生产设置。
- 执行机启动后环境变量变化是否需要重启，页面是否明确。
- 多台执行机配置不一致时中心如何展示和阻止危险组合。
- 同一 Codex 状态库的进程使用不同许可配置时是否拒绝。
- 配置发布与任务领取同时发生时，每个任务只能得到一个完整版本快照。
- 配置回滚后新旧任务的来源证据可追溯。
- 中心不可用时不偷偷使用本地旧配置。

### 23.6 外部依赖协议变化

真实系统可能因外部平台升级而失效，即使内部测试全部通过：

- 小红书页面 DOM、登录页、验证码和 URL 参数变化。
- 点赞量显示格式新增或本地化变化。
- Codex CLI JSONL 事件、app-server 图片事件和错误文本变化。
- DeepSeek `web_search_call` Schema 或响应分块变化。
- Dots API 字段、模型名、超时和限流变化。
- 预览服务 API 版本、对象存储返回头和重定向变化。
- 浏览器自动更新后持久化 Profile 或 Playwright 通道行为变化。

应使用版本化契约夹具保存已知合法和畸形响应；外部调用解析失败时必须停止并保存脱敏证据，不能凭 HTTP 200 判定成功。

### 23.7 导出文件和内容安全

ZIP、XLSX、文件名和用户文本是容易遗漏的攻击面：

- Query、标题或标签以 `=`, `+`, `-`, `@` 开头时防止 Excel 公式注入。
- 换行、制表符、控制字符和超长单元格。
- ZIP 中文文件名、重名文件、非法 Windows 字符和路径穿越。
- ZIP 条目不能写出目标目录。
- 压缩前后文件哈希、条目数和清单一致。
- 大量高压缩比内容不能造成内存或磁盘失控。
- 下载中断、客户端取消和重复下载。
- 图片扩展名、媒体类型和真实文件签名一致。
- SVG 或富文本内容不能在预览中执行脚本。
- Markdown 和外部 URL 渲染不能注入危险协议。

### 23.8 缓存、对象存储和一致性

- 原图和缩略图使用独立 ETag。
- 已撤销预览在浏览器缓存、服务端缓存和对象存储层均立即失效。
- 图片版本更新后旧缩略图不能显示为新版本。
- HEAD 与 GET 的权限、ETag 和状态码一致。
- 对象上传成功但数据库失败时清理本次对象。
- 数据库成功但对象暂时不可读时显示可恢复错误。
- 相同内容哈希的复用不能跨越任务或权限边界。
- CDN 或反向代理不能缓存带用户权限的私有响应给其他用户。

### 23.9 可观测性和告警有效性

系统能完成任务并不代表出现问题时能定位。必须测试：

- requestId、taskId、executionId、model call ID 在中心、执行器和前端日志中可关联。
- 日志包含必要阶段和耗时，但不包含 Key、Token、Cookie、密码或完整敏感提示词。
- 执行机离线、任务长时间无心跳、失败率升高和存储不足能够被发现。
- 告警恢复后不会持续重复通知。
- 统计值与原始任务、执行记录和调用追踪抽样核对一致。
- 客户端错误提示包含可提供给管理员的请求 ID。
- 生产日志级别不会因调试输出造成磁盘快速增长。
- 日志轮转、保留和清理不会删除仍需审计的证据。

### 23.10 并发公平性和饥饿

除了“不超容量”，还需要验证任务不会长期得不到执行：

- 多执行节点竞争时旧任务不会被持续跳过。
- 图片恢复任务和普通图片任务的优先级符合规则。
- 某个节点持续失败时不会反复抢占同一任务。
- 快任务不会永久压制慢任务。
- COPY 和 IMAGE 两个池都能持续补位。
- 自动派单在多个作业员间满足定义的公平或容量规则。
- 降低容量后新增任务仍有确定执行顺序。
- 大批量客户任务不会使小批量任务永久饥饿；如业务允许优先级，必须明确规则。

### 23.11 高风险竞态组合

需要针对以下并发动作编写确定性测试：

- 自动派单与管理员手动派单同时发生。
- 审核通过与任务取消同时发生。
- 图片重试与旧执行完成同时发生。
- 永久删除与资产下载同时发生。
- 永久删除与批量归档同时发生。
- 提示词发布与任务领取同时发生。
- 用户停用与审核提交同时发生。
- 抽检冻结与普通审核提交同时发生。
- 预览撤销与图片读取同时发生。
- 执行机心跳与管理员退休节点同时发生。

每个竞态必须定义唯一合法结果或有限的合法结果集合，不能接受随机数据状态。

### 23.12 隐私、数据保留和最小暴露

- 用户删除与任务审计保留之间的规则。
- 小红书账号标签不得包含手机号、密码或 Cookie。
- 模型请求和搜索结果中可能出现的个人信息如何展示和导出。
- 普通用户不能通过错误详情读取其他用户 Query、提示词或图片路径。
- 备份、日志、测试报告和截图中的敏感信息脱敏。
- 测试数据有明确标识和清理周期。
- 永久删除后数据库、文件、预览和备份中的处理范围有明确说明。
- 生产问题复现时优先使用脱敏数据，不直接复制完整生产库。

### 23.13 无障碍之外的人因与误操作测试

除 WCAG 和键盘操作外，还要验证真实操作人员是否容易做错：

- 新用户能否识别创建者、执行机、负责人和审核员的区别。
- 状态文案是否直接说明“为什么不能操作”和“下一步找谁”。
- 高风险按钮的位置、颜色和命名是否会误导。
- 批量操作是否明确影响数量和不可恢复后果。
- 离开未保存表单时是否提示。
- 重复刷新、浏览器后退和关闭弹窗不会丢失已提交结果。
- 错误提示不只显示技术代码，还提供解决动作。
- 长时间任务能显示阶段、最近活动和是否仍正常运行。
- 手机端关键按钮不因软键盘、浏览器底栏或横屏被遮挡。

建议由非开发人员按任务卡完成一次可用性走查，记录完成时间、错误次数和需要帮助的步骤。

### 23.14 测试体系自身质量

测试代码也可能产生假阳性或不稳定：

- 在全新临时目录执行，确认不依赖之前生成的数据。
- 随机化测试顺序，发现共享状态污染。
- 对时间、网络和并发使用可控时钟及确定性同步点。
- 禁止真实模型测试混入 `npm test`。
- 测试失败时保存种子、环境、请求 ID 和最小复现数据。
- 重复执行全量测试，失败率必须为 0，不能依靠重试变绿。
- 对关键 Fake 做契约测试，防止 Fake 与真实服务行为偏离。
- 覆盖率只作为缺口信号，不为了数字测试无意义实现细节。
- 测试数据清理必须限定在明确临时目录，不能使用宽泛删除路径。
- CI 或本机测试超时时必须终止子进程并输出未关闭句柄。

### 23.15 补充项优先级

#### 发布前必须完成

- 升级与回滚演练。
- PostgreSQL 与资产联合恢复演练。
- 核心故障注入。
- 时间与时钟偏差边界。
- 配置优先级矩阵。
- XLSX 公式注入和 ZIP 路径安全。
- 高风险竞态组合。
- 日志脱敏和请求链路关联。
- 全新目录可重复构建和测试。

#### 满足对应功能时必须完成

- 真实小红书最小搜索验收。
- 真实 Codex/DeepSeek/Dots 调用。
- 独立预览对象存储与撤销缓存验证。
- 大批量 ZIP/XLSX 压力测试。
- 多执行节点公平性测试。

#### 长期治理

- 8 小时以上长稳趋势。
- 非开发人员可用性走查。
- 外部协议定期探测和契约夹具更新。
- 备份恢复定期演练。
- 依赖漏洞、许可证和供应链持续检查。
