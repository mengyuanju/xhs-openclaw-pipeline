## 1. 执行摘要

本轮完成了根项目自动化测试、中心服务自动化测试、隔离 PostgreSQL 18 测试、149 项 CRUD 定向回归、类型检查、生产构建、预览服务启动与冒烟测试、浏览器检查，以及真实 Codex、DeepSeek 和小红书最小样本调用。随后增加了管理员控制的小红书极速/深度搜索策略，并对默认极速模式进行了隔离页面与真实账号复测。Dots 因没有配置 API 密钥而无法发出真实请求。

**当前结论：暂不放行。** 自动化测试门禁、预览服务、CRUD 核心逻辑和真实小红书极速搜索已经通过；但 DeepSeek 真实调用返回 HTTP 402，Dots 缺少 API 密钥，而且完整的认证后浏览器 CRUD、故障注入、备份恢复及长稳测试尚未执行。

### 4.6 真实外部最小验收

#### Codex

- 实际模型：`openai/gpt-5.6-sol`
- 结果：通过，返回约定的 `LIVE_CODEX_OK` 标记。
- 耗时：12,174 ms。
- 用量：输入 7,688 tokens，输出 19 tokens，推理输出 0 tokens。
- 证据记录仅保留用量、长度和 SHA-256，不保存完整业务内容。

#### DeepSeek

- 实际端点：项目内置 DeepSeek Responses 接口。
- 结果：失败，请求发出后服务返回 HTTP 402。
- 解释：证明网络与服务端已收到请求，但当前账号计费或额度状态不允许完成调用；未取得模型输出，不能计为通过。
- 附带现象：错误返回后 Node 进程出现一次 `UV_HANDLE_CLOSING` 断言信息，需要在额度恢复后确认是否只发生在失败退出路径。

#### Dots

- 结果：阻塞，未发出请求。
- 原因：根 `.env`、`server/.env` 和当前进程均没有配置 `XHS_DOTS_API_KEY`。
- 所需动作：配置有效密钥后执行一次最小文本请求，并记录实际模型、耗时、状态码和返回契约。

#### 小红书

- 使用仓库外专用 Edge Profile 和既有人工登录 Session。
- 管理员现在可选择 `FASTEST` 极速模式或 `THOROUGH` 深度排序模式；默认是极速模式。
- 极速模式在任务领取时冻结为首屏最高 1 条、0 次滚动、3 秒首屏等待和 10 秒首次导航上限。
- 临时 PostgreSQL 与临时中心中只创建 1 条 `TEST-` 标记任务，没有连接或领取现有中心队列。
- 早期隔离验收以 3 条上限验证了跨滚动点赞排序；最新复测使用默认极速模式，一次领取成功，尝试次数为 1，实际保存 1 条结果。

## 6. 缺陷总结

### 6.1 ST-001：预览服务重复绑定导致无法启动

| 属性 | 内容 |
| --- | --- |
| 等级 | P1，发布阻断 |
| 状态 | 已修复并复测通过 |
| 影响 | 预览服务可以构建，但 Wrangler 无法启动，所有预览 API 不可用 |
| 根因 | `vite.config.ts` 和 `wrangler.jsonc` 同时声明 `DB`、`FILES`，构建合并后产生同名绑定 |
| 修复 | 保留 `wrangler.jsonc` 作为本地绑定唯一来源，移除 Vite 插件配置中的重复 D1/R2 声明 |
| 复测 | lint、类型检查、构建、生产启动、单条冒烟、批量冒烟全部通过 |

修改文件：`preview-service/vite.config.ts`。

### 6.2 ST-002：3 项 PostgreSQL 历史迁移测试期望过期

| 属性 | 内容 |
| --- | --- |
| 等级 | P2，测试门禁阻断 |
| 状态 | 已修复并复测通过 |
| 影响 | 修复前 3 项历史升级兼容测试在迁移清单比较处提前失败，未执行后续数据完整性断言 |
| 根因 | 固定数组仍只列到 `0033`，没有包含后续合法迁移 |
| 修复 | 更新期望清单至当前最新的 `0042_xhs_search_rate_limits`，保留迁移顺序和后置数据断言 |

失败用例：

1. `legacy delivery migrations retain their checksums and upgrade through the compatibility repair`
2. `delivery runtime integrity migration withdraws JavaScript-unsafe asset ids without resetting anomaly time`
3. `Query-package preassignment repair clears only the proven legacy signature`

隔离 PostgreSQL 18 全量 526 项已经通过，这三项均继续执行并通过了后置数据完整性断言，测试门禁已关闭。

## 10. 小红书账号保护控制器增量复测

在极速/深度搜索策略之后，管理员配置新增三项中心强制控制：两次搜索最短间隔、滚动 60 分钟上限、滚动 24 小时上限，默认值分别为 60 秒、30 次和 150 次。允许范围为 10–3600 秒、每小时 1–360 次、每天 1–8640 次。

保存前会同时检查数学容量：每小时不得超过 `floor(3600 / 间隔秒数)`，每日不得超过 `floor(86400 / 间隔秒数)` 和 `每小时上限 × 24` 中较小者。因此 30 秒间隔最多允许每小时 120 次，200 次会同时被页面和中心拒绝。中心以任务发放为尝试计数点，后续失败、验证码或登录失效也不会返还额度；达到任一限制时任务保持待处理，不会被执行机领取。
