# Web 作业统计方案与实现说明

## 范围

用户已确认按本方案实施。改动限定为 Web 页面、Web 自身的只读统计聚合、缓存和测试。执行机、中心服务器代码、数据库结构、任务队列、模型调用、审核及重试流程均不改动。

现有 `tasks/plan.md`、`tasks/todo.md` 是其他任务的迁移计划，因此本方案独立保存。

## 页面设计

### 作业人员：个人作业概览

放在个人作业中心的列表上方，默认只显示紧凑统计卡和状态数字，图表可展开，保持任务操作为页面主体。

核心卡片：今日新增、累计创建、今日审核完成、累计已完成。第二行显示当前排队、生成中、待文案审核、待图片审核、需要处理的异常数量，失败回审按异常标签标注，不与状态总数重复相加。

展开后显示近 7 / 30 天每日新增趋势、当前任务状态分布。审核完成趋势采用“当前有效审核时间”口径，不能声称是不可变的历史审核事件统计。状态数字可筛选个人任务，统计卡不受列表页码和 Query 搜索影响。

普通账号仅查看自己的数据，不展示其他人员数量、模型名称、执行快照或提示词。审核员的个人统计同样只统计自己创建的作业；本期不新增审核员绩效体系。

### 管理员：作业统计页

侧栏增加“作业统计”，避免在全部作业列表顶部塞入完整仪表盘。默认查看今日，提供近 7 天、近 30 天、自定义日期和作业员筛选；累计指标独立标注，不随日期筛选变化。

1. 业务概览：期间新增、期间审核完成、当前待处理、异常待处理，补充累计创建与累计已完成。
2. 生成效率：文案平均耗时、图片整套平均耗时、总交付平均耗时；展开可看中位数、90% 的任务在多长时间内完成及有效样本数。
3. 图表：每日新增/有效审核完成趋势、文案/图片平均耗时趋势、当前各阶段积压、作业员任务量横向柱状图。
4. 作业员明细表：姓名、账号、期间新增、期间审核完成、累计创建、累计已完成、当前待处理、当前异常、已废弃。支持排序、搜索与角色筛选；完整人员表为主，图表只画前若干名。历史无归属任务单列，不推断归属。
5. 补充指标：有效产出图片数、文案/图片失败执行占比、多次执行任务占比、长期停留任务清单。按数据覆盖率展示，缺失字段不填零。

不将模型执行速度作为作业员绩效排名：该速度还受排队、配置、图片张数和任务复杂度影响。人员表重点用于了解提交量、有效产出和当前积压。

## 统一统计口径

| 指标 | 口径 |
| --- | --- |
| 今日 | Asia/Shanghai 当日 00:00 至次日 00:00，使用半开区间 |
| 作业数 | 按任务 ID 去重，一条 Query 是一项作业；重试不增加作业数 |
| 今日 / 期间新增 | `createdAt` 落入时间范围的任务数量 |
| 累计创建 | 全部历史创建任务，包含已废弃；已废弃另列，避免历史工作量随废弃减少 |
| 当前已完成 | 当前状态 `REVIEWED` 的任务，不将文案生成或图片生成完成等同于全部完成 |
| 今日 / 期间审核完成 | 当前仍为 `REVIEWED` 且 `imageReviewedAt` 在范围内的任务；重新生图可能使该数字变化 |
| 当前待处理 | 尚未审核完成且未废弃的任务，细分排队、生成、待审核、失败，不受日期筛选影响 |
| 文案平均耗时 | `COPY`、`SUCCEEDED` 执行的 `finishedAt - startedAt`；按执行结束日期分组，含检索、自动质检等阶段内部耗时，不含排队和人工审核 |
| 图片平均耗时 | `IMAGE`、`SUCCEEDED` 执行的 `finishedAt - startedAt`；单位是整套图片执行，不是单张模型推理耗时。条件允许时按实际张数分组比较 |
| 有效样本 | 起止时间有效且结束不早于开始；失败、运行中、已放弃记录不混入成功耗时均值；零样本显示“暂无样本” |
| 重复执行 | 每条成功执行独立计入执行均值；另列同一任务同一阶段有多条执行记录的占比，不称为模型内部重试率 |
| 交付耗时 | 当前有效审核完成任务的 `imageReviewedAt - createdAt`，包含排队、执行、人工审核等待及重做，和生成耗时分开 |
| 有效产出图片数 | 当前已审核任务的当前图片运行中的实际图片资产数，不使用计划张数，不累加旧运行和失败资产 |
| 失败执行占比 | 期间结束的失败执行数 /（成功执行数 + 失败执行数），文案与图片分别统计；已放弃执行另列 |
| 长期停留 | 基于现有最后活动时间给出“距上次更新多久”，阈值只影响 Web 提示；不冒充精确排队或审核等待时长 |

已明确标注的模拟/测试运行与真实运行分开统计。无法可靠识别的历史数据标为“来源未标明”，不可仅凭任务标题自动排除。人员角色仅有当前值，不能还原创建时的历史角色。

## 已核对的数据能力

- 中心 `GET /v1/tasks` 已有账号、角色、状态筛选和分页总数，列表带创建时间、有效图片审核时间等字段。
- 中心 `GET /v1/tasks/:taskId` 对管理员返回分开的文案 / 图片执行历史及起止时间，也有图片运行、资产等信息；可支持阶段耗时与有效图片数。
- 非管理员详情已不返回执行快照，个人数量统计不需要恢复这部分权限。
- 旧 `/api/statistics` 汇总的是本地 SQLite 导入批次，不作为当前中心作业数量来源，避免混用两个系统的数据。
- 中心现有列表没有日期过滤、统计分组或一致性快照接口，而且按可变化的任务状态排序。不能只请求当前页或前 200 条就声称是完整历史统计。

## Web 端实现方式与限制

在 Next.js Web 服务中增加只读聚合层，沿用已验证会话访问现有中心接口，不直接连接中心数据库。个人账号的筛选身份来自会话，管理员权限在 Web 端检查；缓存按中心地址、权限和账号隔离，响应只含汇总字段。

数量优先使用现有分页总数和列表字段。阶段耗时仅在管理员打开统计页时读取执行详情并提取所需数值，不把原始提示词、模型响应或执行快照发送到统计页面。列表数量与耗时分析独立加载，分析慢或失败不能挡住作业列表。

数量缓存 60 秒。明细按任务状态、当前图片运行、文案版本及更新时间增量复用：状态或版本变化立即失效；仅更新时间变化时最多复用 5 分钟；未变化的明细继续复用。页面访问触发刷新，提供手动刷新与最近更新时间，不新增常驻采集器或生产定时任务。首次历史扫描显示进度，失败或只读取部分数据时显示“统计未完整”，不得补零或把部分结果当总量。

每个 Web 进程的新增统计中心请求共用 **1 次/秒、并发 1** 的预算，最多 8 个待执行读取，排队超过 10 秒返回忙碌状态；单次中心读取 8 秒超时。相同账号和范围的并发请求合并；手动刷新数量至少间隔 15 秒，失败后间隔 30 秒重试。多 Web 实例的上限相加，不声称是跨实例全局限速。现有任务列表请求不占用此统计预算，也不修改其读取逻辑。

每次页面请求只推进一页列表或一项明细。冷加载阶段串行轮询，静置完成后通常每 60 秒读取，隐藏标签页暂停；关闭页面后不继续采集。日期及管理员人员筛选在缓存事实中计算，不重复拉取完整历史。明细只读取最后更新时间可能覆盖所选日期的任务。

缓存保留最多 12 个账号/权限/范围组合，按最近使用淘汰空闲组合；每个范围最多读取 20,000 项作业，每项详情各数组最多 10,000 条记录。超过上限明确提示统计未完整，不截取后伪称总数。管理员人员筛选发生在全量账号范围汇总之后，不能用日期或人员选择绕开这一读取上限；超大规模报表需另行规划。

完整时间统计在首次加载时仍需分页读取大量历史列表，中心现有接口无法直接把范围缩到某一天。分页期间状态变化可能导致跨页移动，Web 端应去重、检查总数与缺页并做有界重读；该统计只能提供最近刷新时的近实时视图，不能承诺交易级一致的实时全量报表。数据量较大时显示最后一次完整结果和更新时间，不将大量请求转移给每个浏览器。

本期不承诺永久不变的历史完成曲线、首次人工审核通过率、精确审核等待/排队时长、模型费用、单张图片真实推理耗时；现有数据不足时不推断或伪造。这些指标如将来确有需求，应另行讨论数据能力，本方案不预埋中心服务改造。

## 图表选择

使用 Apache ECharts 的折线图、柱状图，按需加载图表组件；数字卡和明细表优先展示，图表延迟加载。保留文字数值与表格，支持窄屏布局，不依赖颜色传达状态。

官方参考：[按需引入](https://echarts.apache.org/handbook/en/basics/import/)、[无障碍说明](https://echarts.apache.org/handbook/en/best-practices/aria/)。

## 交付入口

个人入口：`/workbench/personal` 顶部概览，趋势默认收起，状态数字筛选任务列表（包含单独查看已废弃）。管理员入口：`/workbench-statistics`，侧栏“作业统计”。只读 Web API：`GET /api/workbench-statistics`。非管理员仅可请求 personal，不可请求 admin 或 details；个人账号身份来自会话，忽略外部传入的账号。

人员表支持排序、账号搜索及跳转全部作业的创建者筛选；长期停留任务可跳转已有详情。图表仅在 Web 浏览器运行，缓存只存白名单统计事实，原始模型快照、提示词和生成内容不进入统计响应。
